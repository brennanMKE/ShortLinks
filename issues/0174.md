# 0174 — A signed-out visitor sees only a sign-in screen or a redirect, with nothing that says what the site is

## Description

When nobody is signed in, `/` shows the sign-in screen, or after #0125 a redirect page when registration is closed and `home_redirect_url` is set. Many instances don't accept new users, so most visitors land on a page that tells them nothing. Brennan wants a public home page whose content each instance's admin chooses in Admin → Settings. The options are a text blurb about the site, a 7-day activity summary (#0175) and a hero image (#0176). The page must still be useful when sign-ups are closed.

## Long Description

**Requested (Brennan, 2026-11-18):** *"For the home page of a ShortLinks website when the user is not signed in we need some kind of content. Some websites won't allow new users so it should be generally useful still. In the settings the admin could choose what to show. It could still offer a summary chart of activity over the past 7 days minus the campaigns and UTM parameters. It could show the most popular 3 links for the past 7 days as well. If the admin does not want to show that it could instead just include a text blurb about what the website is about… We can also include a hero image which would also be added in settings and stored on the server."*

This issue adds the settings and the public data contract. #0175 adds the activity data, #0176 the hero image, and #0177 the page and the admin UI.

**New settings** in the existing `settings` table. Each is validated in `validateSettingValue` and audited like the existing keys.

| Key | Values | Default |
|---|---|---|
| `home_mode` | `default`, `about`, `activity` | `default` |
| `home_title` | plain text, at most 80 characters | empty (the page falls back to the instance host) |
| `home_about` | text, at most 2,000 characters | empty |

- **`default`:** today's behaviour, exactly as #0125 left it. The page shows the sign-in screen, or the redirect page when registration is closed and `home_redirect_url` is set. `home_redirect_url` only applies in this mode.
- **`about`:** a public page with the hero image if one is set, the title, the about text, and **Sign in** (plus **Register** when `registrations_enabled`).
- **`activity`:** everything in `about`, plus the 7-day summary from #0175.

**About text format.** Use plain text. Blank lines separate paragraphs, and bare `https://` URLs become links, rendered by escaping first and linking second. Don't use HTML or Markdown: the page is public and the text is admin-written, so a small, safe format is better than a sanitiser. If Brennan wants bold or headings later, that's a follow-up.

**Public endpoint.** Extend `GET /api/public/home` so it still returns `redirect_url` and `registrations_enabled`, and adds `mode`, `title`, `about` and `hero` (`{"url", "alt", "width", "height"}`, or null, from #0176). `activity` is filled by #0175. Keep `Cache-Control: no-store` for the settings part. The response must carry nothing from `/admin/settings` beyond these keys.

**Docs.** [docs/configuration.md](../docs/configuration.md), or wherever the settings are documented, describes the modes and their precedence.

## Root cause

The signed-out home page had no content settings: `GET /api/public/home` returned only `redirect_url` and `registrations_enabled`, and the `settings` table (PATCH only updates existing rows) had no keys for a mode, title or about text.

## Fix

- Migration `000021_seed_home_page_settings` seeds `home_mode=default`, `home_title=''`, `home_about=''` (down deletes them). The devstore seeds the same rows.
- `validateSettingValue` (internal/handlers/settings.go) validates `home_mode` (enum `default|about|activity`), `home_title` (at most 80 characters, no control characters) and `home_about` (at most 2,000 characters, control characters rejected except `\n`/`\r`). The existing PATCH path already trims values and writes the `settings.updated` audit entry.
- `HomeHandler` returns `redirect_url`, `registrations_enabled`, `mode`, `title`, `about`, `hero` (always `null` for now; #0176 fills it). `activity` is deliberately absent; #0175 adds it only in `activity` mode. Missing rows read as unset and an unknown stored mode is served as `default`. `Cache-Control: no-store` is kept.
- OpenAPI `PublicHome` schema and docs (auth.md, database.md, configuration.md) updated. `default` mode behaviour is untouched; the SPA ignores the new fields.
- One #0125 assertion had to change: `TestHomeHandler_TwoKeysNoStoreNoAuth` pinned exactly two keys, now `TestHomeHandler_ExactKeysNoStoreNoAuth` pins the new six-key set.
