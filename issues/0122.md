# 0122 — The campaign page has no clicks-by-placement rollup, so per-shop poster scans need a CSV pivot

| | |

## Description

Brennan wants to see which shops' posters get the most scans on go.dustalmanac.com. Each poster download mints its own link in the `posters` campaign, and the shop name exists only as that link's `placement`. CampaignDetail can't group clicks by placement: `by_link` buckets (`internal/clicks/stats.go`, `LinkBucket`) don't carry it, and one shop with several downloads shows as several rows. Today the only way is the campaign CSV export plus a spreadsheet pivot.

## Long Description

Requested by Brennan, relayed from the WoodDust session on 2026-11-08. Dust Almanac's poster plaques call `POST /api/links` once per download, with `campaign_slug=posters` and, when the shop opts in, `placement=<shop name>`.

**Wanted:** on CampaignDetail, a "Clicks by placement" table for the selected date range, with these columns: **placement**, **link count**, **click count**. Sort it by clicks, descending.

- **Grouping:** case-insensitive, with whitespace trimmed, so `Testing` and `testing ` are one row. Show the most common original spelling for each group.
- **Blank placement:** links with an empty or NULL placement go in one `(none)` row, so the rows add up to the campaign's total for the range.
- **Optional:** the same rollup in the campaign stats API response (e.g. `by_placement`) and/or as a CSV export, so WoodDust or Home Assistant can read it later.

**Constraints:**
- **Placement stays out of URLs.** It's the only shop identifier, so it must never appear in a short URL, a destination URL or UTM parameters.
- **Privacy:** keep #0121's stance. Return aggregate counts only, with no per-click detail (IP hash, user agent, timestamps per click) in the new output.
- **Bot clicks:** decide whether `is_bot` clicks are excluded the same way the existing campaign stats exclude them, and say so in the plan.

## Plan

### Where it fits

`internal/clicks/stats.go` already has the shape to copy: `campaignClicksByLinkQuery` (clicks grouped on `clicks.campaign_id` with a LEFT JOIN to `links` for enrichment only) and `CampaignRollup`, which reads every part of `GET /api/campaigns/{slug}/stats` inside one `REPEATABLE READ` transaction. The placement rollup is one more read inside that transaction, one more field on `CampaignRollup`/`campaignStatsResponse`, and one more table on `CampaignDetail.svelte`. No migration: `links.placement TEXT` (000011) is already there, and `idx_links_campaign_id` / `idx_clicks_campaign_time` serve the two scans.

The "selected date range" is the window `CampaignRollup` resolves (`campaignWindow`): CampaignDetail has no from/to picker, it calls `getCampaignStats(slug)` and shows `window_from`/`window_to`. Nothing new to plumb; `?from=/?to=` already reach the store for API callers.

### Decisions

1. **Bot exclusion and range: identical to every other campaign number.** `k.is_bot = FALSE`, `k.clicked_at >= $2 AND k.clicked_at < $3`, grouped on `clicks.campaign_id`. This is what makes the rows sum to `stats.click_count` exactly (asserted in a test, see below). Bot clicks are reported once, in the existing `excluded_bot_count`, not per placement.
2. **Click attribution follows the click, link count follows current membership.** Clicks are matched by `k.campaign_id` (a since-unassigned link's clicks still count, #0100); `link_count` is `COUNT(*) FROM links WHERE campaign_id = $1` per group, the same scale as the "Links" summary stat (`CampaignWithCounts.link_count`, no `active` filter). So Σ `click_count` = `stats.click_count` and Σ `link_count` = `detail.link_count`, both checkable on screen.
3. **A link with zero clicks in the range still counts, and its placement still gets a row.** The question is "which shops' posters get scanned", and the answer for a shop that downloaded three posters and got no scans is "3 posters, 0 clicks", not "nothing". Dropping zero-click groups would make the table unable to show the shops whose posters are not working, which is the second half of the question. Rows with 0 clicks sort to the bottom.
4. **Normalization in SQL: `lower(btrim(COALESCE(placement, '')))`.** NULL, `''`, and whitespace-only all normalize to `''` and become the single `(none)` row, labelled with the existing `NoneBucket` constant. Display spelling = the most common `btrim(placement)` among the group's currently-assigned links, one vote per link; ties break on `spelling COLLATE "C" ASC` (byte order, so `Testing` beats `testing`, and the result does not depend on the database collation). A group that has clicks but no current link (every link since unassigned) has no spelling votes; Go falls back to the normalized key.
5. **`by_placement` goes on `CampaignRollup`, not `CampaignStats`.** `CampaignStats` is embedded in `GET /api/campaigns/{slug}` too (via `CampaignSummary`); this rollup needs the `links` join, belongs beside `by_link`, and the SPA already fetches the rollup. Adding it to the API rather than computing it in the SPA from `detail.links` + `by_link`: (a) `by_link` rows for since-unassigned links carry no placement, so a client-side pivot cannot reconcile to the total; (b) the issue asks for it so WoodDust / Home Assistant can read it; (c) the sums-to-total property is testable in Go against a real database.
6. **CSV export is a follow-up, filed as its own issue.** `by_placement` in the JSON already gives WoodDust/HA a machine-readable rollup. Whether it should be a second endpoint (`/export-placements.csv`) or a second block in the existing per-link file is a product call for Brennan; the existing `campaigns_export.go` is deliberately a mirror of the per-link table and should not grow a second table silently.
7. **Privacy:** aggregates only. The new struct is `{placement, link_count, click_count}`; no click rows, timestamps, `ip_hash`, or user agents are read or returned (#0121 stance). Placement is read from `links.placement` and written to the JSON body only; nothing in this issue touches short URLs, destination URLs, UTM fields, or the QR filename path (`qr.Filename` already slugs placement into a download filename, which is unchanged and is not a URL that leaves the admin's browser).

### Steps

**1. `internal/clicks/stats.go`**

- Add, next to `LinkBucket`:
  ```go
  // PlacementBucket is one row of the campaign's clicks-by-placement rollup (#0122).
  // Placement is the display spelling (decision 4) or NoneBucket. LinkCount is
  // current membership; Count is windowed, bot-excluded clicks attributed to the
  // campaign — so the two columns are on different time scales, like link_count
  // vs stats.click_count on the detail page.
  type PlacementBucket struct {
      Placement string `json:"placement"`
      LinkCount int64  `json:"link_count"`
      Count     int64  `json:"count"`
  }
  ```
- Add `ByPlacement []PlacementBucket \`json:"by_placement"\`` to `CampaignRollup`; read it in `CampaignRollup()` after `seriesByLink`, inside the same `tx`.
- Add `campaignClicksByPlacementQuery(ctx, q rowQuerier, campaignID int64, from, to time.Time) ([]PlacementBucket, error)` with one statement:
  ```sql
  WITH members AS (
    SELECT btrim(COALESCE(placement, ''))        AS spelling,
           lower(btrim(COALESCE(placement, ''))) AS grp
      FROM links WHERE campaign_id = $1
  ),
  link_groups AS (
    SELECT grp, COUNT(*) AS link_count FROM members GROUP BY grp
  ),
  click_groups AS (
    SELECT lower(btrim(COALESCE(l.placement, ''))) AS grp, COUNT(*) AS click_count
      FROM clicks k LEFT JOIN links l ON l.id = k.link_id
     WHERE k.campaign_id = $1 AND k.clicked_at >= $2 AND k.clicked_at < $3 AND k.is_bot = FALSE
     GROUP BY 1
  ),
  spellings AS (
    SELECT DISTINCT ON (grp) grp, spelling
      FROM (SELECT grp, spelling, COUNT(*) AS votes FROM members GROUP BY grp, spelling) v
     ORDER BY grp, votes DESC, spelling COLLATE "C" ASC
  )
  SELECT g.grp, COALESCE(sp.spelling, ''), COALESCE(lg.link_count, 0), COALESCE(cg.click_count, 0)
    FROM (SELECT grp FROM link_groups UNION SELECT grp FROM click_groups) g
    LEFT JOIN link_groups  lg ON lg.grp = g.grp
    LEFT JOIN click_groups cg ON cg.grp = g.grp
    LEFT JOIN spellings    sp ON sp.grp = g.grp
   ORDER BY 4 DESC, 3 DESC, g.grp COLLATE "C" ASC
  ```
  Scan into `grp, spelling, linkCount, count`. In Go: `if grp == "" { Placement = NoneBucket } else if spelling == "" { Placement = grp } else { Placement = spelling }`. Return a non-nil empty slice for an empty campaign (file convention). Do **not** add a standalone `CampaignClicksByPlacement` method: the standalone methods are documented as production-dead and the handler must use `CampaignRollup`.
- Doc comment on the query function: why the links CTE uses `links.campaign_id` (membership) while the clicks CTE uses `clicks.campaign_id` (attribution), and the sum properties from decision 2.

### Edge cases

- **`lower()` is not full Unicode case folding.** It applies per-character simple case mapping under the database's `LC_CTYPE`; under a `C` locale it folds ASCII only. `ß`/`SS`, Turkish dotted/dotless `i`, and Greek final sigma are not unified, and a `C`-locale database will keep `Café` and `café` apart. Shop names are overwhelmingly ASCII; document the limit in the query's doc comment and move on. (Normalizing in Go with `strings.ToLower` would be collation-independent, but splits the grouping across two layers and loses the single-statement property; rejected.)
- **Mixed spellings:** `Testing`, `testing `, ` TESTING` → one group; display = the spelling with most links, tie → byte order. Leading/trailing whitespace is trimmed; internal whitespace is not (`"Main  St"` and `"Main St"` stay apart; acceptable, and consistent with how the links handler stores placement with `strings.TrimSpace` only).
- **Every link has no placement:** the query returns exactly one `(none)` row whose `link_count`/`count` equal the campaign totals. The SPA shows the "set a placement" note instead of a one-row table.
- **Click whose `link_id` is NULL** (defensive, unreachable today per `LinkBucket`'s comment): LEFT JOIN yields NULL placement → `(none)`, so it is still counted.
- **Since-unassigned link:** its clicks count under its current placement spelling (read live from `links`), `link_count` for that group may be 0. Sum property still holds because clicks follow `clicks.campaign_id`.
- **Empty window `[X, X)`:** clicks all 0, rows still listed per current link group with `count = 0` (same stance as the CSV export's empty-window decision).
- **Placement literally spelled `(none)`:** collides with the label, same as `dimensionBreakdown` today; ignore.
