## Description

One guide is shared as two or more links, one per platform, and titles carry a channel suffix ("Measuring current without blowing the fuse — Mastodon guide post 84"). Add canonical content grouping in Go, and two reports: `top-content` (ranked content groups) and `top-links` (ranked individual links).

## Long Description

**Content key.** The destination URL with every `utm_*` parameter, the fragment and any trailing slash removed, and the host lower-cased. Two links share a group if and only if their keys match. Put this in `internal/reports/content.go` as a pure function with table tests.

**Display title.** For each member link, cut the title at the last ` — `, ` – `, ` | ` or ` - ` when the tail looks like a channel label: it starts with that link's own `utm_source`, or with a known platform name (mastodon, bluesky, instagram, facebook, threads, x, twitter, linkedin, newsletter, email, poster, flyer, qr), or matches `/\b(post|flyer|poster|qr|newsletter)\b.*\d*$/i`. Use the most common remaining head. If no title is left, fall back to the last path segment with dashes turned into spaces. The cut-off tail becomes that link's `label`.

**`top-content` data** (extra params: `sort=clicks|change|newest`, default `clicks`; `limit` default 10):

```json
{"groups": [{
  "content_key": "www.opencircuitsf.com/guides/measuring-current",
  "title": "Measuring current without blowing the fuse",
  "path": "/guides/measuring-current",
  "clicks": 164, "previous_clicks": 150, "change_pct": 9.3,
  "by_source": [{"value": "mastodon", "clicks": 90}, {"value": "bluesky", "clicks": 52}, {"value": "email", "clicks": 22}],
  "links": [{"key": "HaQRwV", "label": "Mastodon guide post 84", "utm_source": "mastodon", "utm_medium": "social", "campaign_slug": "guides-2026-11", "clicks": 90}]
}], "total_groups": 23}
```

**`top-links` data** (extra params: `sort=clicks|change|newest`, `limit` default 20): each link's key, short URL, title, `label`, `content_key`, destination, campaign, UTM fields, placement, active flag, clicks, previous clicks, change.

Both reports honour the shared filters. A group appears when at least one member had a counted click in the window, or with `sort=newest`.

## Root cause

Nothing related a link to the content it points at. Each platform's link was a separate row with its own title, and the title carried a channel suffix, so ranking content meant adding rows up by hand.

## Fix

Added `internal/reports/content.go`:

- **`ContentKey`** builds the grouping key from the destination URL. It strips `utm_*` parameters (any case), the fragment, the trailing slash and the default ports `:443`/`:80`, keeps other query parameters in a stable order, and lower-cases the host. Opaque URLs such as `mailto:` are returned unchanged.
- **`ContentPath`** returns the path shown for a group.
- **`LinkLabel(title, utmSource)`** cuts the title at its last ` — `, ` – `, ` | ` or ` - `, but only when every token after the cut is a channel token. Channel tokens are platform words, the link's own `utm_source`, words like guide, post and newsletter, numbers, `#`/`No.`, and months or years. At least one of them must be a platform, source or channel word. This is **stricter than the issue's original regex**: under that rule, titles like "Concurrency - Threads in Go" or "Tips - Email marketing…" would have been cut.
- **`ContentTitle`** picks the most common head, breaking ties deterministically, and falls back to the last path segment and then the host.

Added `top_content.go` with two reports. SQL aggregates counted clicks per (link, source) for the current and previous windows using `ScopedQuery`, and Go then groups them by content key.

- **`top-content`** returns per group: `title`, `path`, `clicks`, `previous_clicks`, `change_pct`, `by_source`, member `links` and `total_groups`.
- **`top-links`** returns ranked individual links with `short_url`.

Both support `sort=clicks|change|newest` and `limit`. Both set `data.truncated` plus a highlight when a query hits the `maxLinkRows` cap. Labels and titles depend only on link fields, never on the window or filters. The review fixes (stricter tail rule, `LinkLabel`, the truncation flag, ports, opaque URLs, share wording) were made in `7bdb1b2` on `issue/0140`.

## Gotchas

- **Reuse `LinkLabel`.** #0144 must use it for list items so labels match the reports.
- **`loadLinks` stays unexported.** #0141 and #0143 are in the same package and can call it directly.
- **The row cap counts (link, source) pairs, not links.** A truncated result can therefore undercount part of a single link.
- **"sticker" is not a channel token.** "Guide - QR sticker" is not cut, which is why the test case became "Guide - QR 7". Add words to the channel set if real titles need them.
