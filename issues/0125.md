# 0125 — A signed-out visitor to the home page always lands on the sign-in screen, even when enrollment is closed

| | |
|---|---|
| **Status** | open |
| **Module** | web / handlers / settings |
| **Platform** | All |
| **Phase** | 3 — SPA routing |
| **First seen** | 2026-11-09 |

## Description

A signed-out visitor to the home page (`/`) of any instance is always bounced to `/#/login`. Examples are someone who scans a poster and then trims the URL, or who just types go.dustalmanac.com. When `registrations_enabled` is false, nobody new can sign up, so for almost every visitor that screen is a dead end. Brennan wants a better home page: if enrollment is disabled and the visitor isn't signed in, show a simple page that redirects to a **primary URL** set in admin settings after a short delay. Existing account holders still need a way to sign in.

## Long Description

**Today:** `web/src/App.svelte`'s guard sends any signed-out route that isn't `/login` to `loginPathWithRedirect(route.path)`. `/` gets the same treatment as a deep link. Runtime settings live in the `settings` table (migration 000006), are edited under **Admin → Settings** (`internal/handlers/settings.go`, `web/src/views/Admin.svelte`), and `validSettingValue` enforces per-key rules. `registrations_enabled` is the only key so far.

**Wanted (Brennan, 2026-11-09):**
- **A new admin setting for the primary URL,** e.g. `home_redirect_url`. It must be an absolute `https://` (or `http://`) URL, validated in `validSettingValue`. Empty or unset means today's behavior.
- **A simple signed-out home page.** When the visitor isn't signed in, `registrations_enabled` is false, and a primary URL is set, `/` shows a minimal page instead of the sign-in screen: the instance name and "Taking you to <host>…". It redirects after a short delay, about 3 seconds; the plan should pick the value and say whether it's configurable. It needs a visible "Go now" link to the primary URL, and a small, unobtrusive **Sign in** link to `/#/login` for account holders.
- **Sign-in stays reachable.** `/#/login`, emailed magic-link and recovery landings (`/auth/*`), and signed-out deep links such as `/#/campaigns/x` keep working and still go to sign-in with their redirect target. Only the bare home page redirects.
- **Signed-in users** see the dashboard as today.
- **Registration open,** or no primary URL set: no change.

**Points for the plan:**
- **SPA or server?** Decide whether the page is an SPA view (the `/` route when signed out) or served by Go before the SPA loads. The server can't see the hash, but it can see the session cookie and settings. It could even send a `Refresh` header or a `<meta http-equiv="refresh">`, so the redirect works without JavaScript.
- **Public data:** the page needs the primary URL and the registration state without signing in. Either add a small unauthenticated endpoint (e.g. `GET /api/public/home`) exposing only those two values, or render them server-side. Admin-only `/admin/settings` must stay admin-only.
- **Safety:** only an admin can set the URL, so this isn't an open redirect for visitors, but validate the scheme strictly: no `javascript:`, no relative URLs. Record changes in the audit log the way `registrations_enabled` changes are.
- **Redirect loop:** the primary URL must not point back at the instance's own `BASE_URL` home page. Reject that.
- **Short links:** `/u/{key}`, `/health`, `/api/*`, the QR endpoints and `/auth/*` are untouched.
- **Per instance, no default (Brennan, 2026-11-09):** anyone can run this repo, so the code can't know a sensible primary URL. There is **no default and no fallback** in code, the seed or the docs. The setting starts empty, and empty means no redirect. Each operator sets their own in Admin → Settings. Docs and tests use placeholder hosts (`example.com`, `go.example.com`), never a real deployment's domain.

## Plan

### Where it fits

Everything the page needs already exists in pieces. `App.svelte`'s `redirectIfNeeded()` is the one place that decides what a signed-out visitor sees; the `settings` table (000006) with `auth.Store.GetSetting` / `UpdateSetting` / `RegistrationsEnabled` holds runtime values; `SettingsHandler.Patch` validates per key and writes the `settings.updated` audit row; `Admin.svelte` has a settings panel with one row. The work is: one seed migration, one validation rule, one tiny public handler, one new SPA view, one new branch in the guard, one new row in the admin panel. No change to `SPAHandler`, `/u/{key}`, `/auth/*`, `/api/me`, or the route table.

### Decisions

1. **SPA view, not a server-rendered page.** The server sees `GET /` for `go.x.com/`, `go.x.com/#/login`, and `go.x.com/#/campaigns/x` alike: the hash never leaves the browser. A server-rendered redirect at `/` would therefore send signed-out deep links and `/#/login` to the primary site, which breaks two acceptance criteria. A hybrid (serve HTML with a script that checks the hash before falling back to the SPA) adds a second code path to maintain and still needs JS for the deep-link case, so the no-JS benefit is theoretical: the SPA (passkeys, fetch) already requires JS, and `<meta http-equiv="refresh">` would fire before the hash check could stop it. So: `App.svelte` fetches the public home info only when `/api/me` is 401 **and** the hash is root, and renders a new `Home.svelte` instead of bouncing to `/login`. Trade-off accepted: a crawler or a no-JS client sees the SPA shell, as it does today.
2. **Setting key `home_redirect_url`**, seeded by migration `000016` as `''`. Empty means "unset, behave as today". There is deliberately no default URL and no code fallback; the value only ever comes from this setting. No new table or column; the value is text in the existing `settings` table, read fresh on each request like `registrations_enabled` (no cache, so an admin edit takes effect on the next cold load).
3. **Validation lives in the handler and knows `BASE_URL`.** `validSettingValue(key, value) bool` becomes `validateSettingValue(key, value, baseURL string) error` so the 400 body can say *why* (the admin UI shows it) and so the self-redirect check has the instance host. `SettingsHandler` gains a `baseURL` field via `NewSettingsHandler(store, auditor, baseURL)`. Rules for `home_redirect_url`, after `strings.TrimSpace` (Patch trims every value; `"true "` for `registrations_enabled` then also passes, which is harmless):
   - `""` → valid (clears the setting).
   - Length ≤ 2048; no whitespace or control characters (`strings.ContainsAny(v, " \t\r\n")` or any rune < 0x20).
   - `url.Parse` succeeds; `strings.ToLower(u.Scheme)` is `http` or `https`; `u.Host != ""`; `u.User == nil` (no credentials); `u.Opaque == ""`. This rejects `javascript:`, `data:`, `//host`, `/path`, `example.com`, `ftp://`.
   - **Not self:** `strings.EqualFold(u.Hostname(), base.Hostname())` where `base, _ := url.Parse(baseURL)` → reject with "must not point at this instance". Hostname only, port ignored: anything on the instance's own hostname is pointless as a primary site and the strict rule can never loop. If `baseURL` fails to parse (not possible in a real wiring since `config.Load` requires it) skip the self check rather than reject everything.
   - Messages: `home_redirect_url must be an absolute http(s) URL`, `home_redirect_url must not point at this instance`. `registrations_enabled` keeps `invalid value`.
4. **Audit: no new code.** `Patch` already records `settings.updated` with `{key, old_value, new_value}` and `actor_id`; a clear writes `new_value: ""`. The plan only adds a test asserting the row for this key. `admin.ts`'s metadata formatter prints `key=…, old_value=…, new_value=…` generically, so the audit tab shows it with no change.
5. **Public endpoint `GET /api/public/home`**, handler `HomeHandler` in `internal/handlers/home.go`, mounted with **no** middleware (not `requireAPI`). Body: `{"redirect_url":"https://www.example.com/","registrations_enabled":false}`; exactly those two keys, never `updated_at` or other settings. Headers: `Cache-Control: no-store`. `ErrSettingNotFound` for the key (database not yet migrated) is treated as `""`, not 500. Depends on a narrow interface `homeSettingsReader { RegistrationsEnabled(ctx) (bool, error); GetSetting(ctx, key string) (string, error) }`; `*auth.Store` already satisfies it, `devstore.Store` needs `GetSetting` added. Why not fold it into `/api/me`'s 401 body: `/api/me` is behind `RequireSessionOrAPIToken`, whose 401 is written by middleware; a public endpoint is simpler and keeps `/api/me` auth-only. Why `/api/public/`: the prefix is proxied already (Apache `ProxyPass /`, Vite proxy `/api`), and the path says "unauthenticated by design" to anyone reading `main.go`.
6. **The SPA decides, from raw values.** The endpoint returns the two facts; `shouldShowHome()` (pure, in `web/src/lib/home.ts`, vitest-covered) combines them with "signed out" and "path is `/`". Keeping the rule client-side means the server never has to know about the hash.
7. **Delay: 3000 ms, a constant, not configurable.** Brennan asked for about 3 s; a configurable delay is another validated setting and another admin field for marginal value. `HOME_REDIRECT_DELAY_MS = 3000` in `home.ts` so a later issue can make it a setting without touching the view. The redirect uses `window.location.replace(url)` so Back from the primary site does not land on `/` and redirect again.
8. **Sign-out still lands on `/login`.** `homeInfo` is only fetched on a signed-out cold load, and `App.svelte` clears it the moment `$currentUser` becomes non-null, so after a later sign-out the guard falls through to today's `/login?redirect=…` bounce. A sign-out should not eject an account holder to another site. A reload after sign-out shows the redirect page, which is right: that visitor is now just signed out at `/`.
9. **Dev mode (`STORAGE=json`) cannot show the page**: `DevAutoLogin` signs every request in and the dev store seeds `registrations_enabled: true`. Add the `home_redirect_url: ""` seed and `GetSetting` so `/api/public/home` and the admin row work in dev; the page itself is verified by Go tests, vitest, and a Postgres run.

**5. `web/src/views/Home.svelte` (new)**

### Edge cases

- `/#/` and `/#` and `/` all normalize to path `/` (existing `enterApp` + `parseHash`); `/#/?x=1` is also path `/` and shows the page.
- `registrations_enabled` later flips to `true` while a URL is set: `shouldShowHome` is false, visitors see `/login` as today; the admin row explains this.
- `/api/public/home` fails (network, 500) on a signed-out root load: `homeInfo = null`, bounce to `/login`. Never a blank screen.
- Setting stored but somehow invalid (edited in SQL): the SPA passes it through to `location.replace`; validation is the admin endpoint's job. `redirectHost` falls back to the raw string so the copy never throws.
- A URL with a path or query (`https://www.example.com/posters?src=go`) is valid and preserved exactly; only the host appears in the copy.
- Magic-link landings `/register/verify` and `/recover/verify` return from `onMount` before `getMe()`, so they never fetch home info; `enterApp('/')` after a successful ceremony has `$currentUser` set, so `showHome` is false.
- Expired session mid-visit: `currentUser` is set to null by whichever view hits a 401 (existing behavior); `homeInfo` is null (cleared when the user signed in) → `/login?redirect=…` as today.

### Per-instance setup notes (for `DEPLOYMENT.md` after "Enabling registration for other users")

> **Primary URL (signed-out home page).** Each instance decides where a signed-out visitor to its bare home page goes. Sign in as admin, open **Admin → Settings → Primary URL**, and enter the absolute `https://` URL of the site the short links promote, e.g. on `go.example.com` enter `https://www.example.com/`. The URL must not be on the instance's own host (`BASE_URL`). Leave it empty to keep showing the sign-in screen. The redirect only happens while **Registrations enabled** is off; `/#/login`, emailed `/auth/*` links, `/u/{key}` short links, QR codes, `/api/*`, and `/health` are not affected. Changes take effect on the next page load and are recorded in the audit log as `settings.updated`.

There is no default value for any deployment; each operator sets their own.

### Unaffected routes (explicit)

`GET /u/{key}` (redirect handler), every `/api/*` route (all still behind `requireAPI`; only the new `/api/public/home` is public), `/auth/*` (register, login, recover, logout, and the `/register/verify` and `/recover/verify` SPA landings, which `App.svelte` handles before any session check), `/health`, the QR endpoints (`/api/links/{key}/qr.svg|png`, `/api/campaigns/{slug}/qr.zip`), `/admin/*`, `/account/*`, and `SPAHandler` itself (`GET /` still returns `index.html`).
