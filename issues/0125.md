# 0125 — A signed-out visitor to the home page always lands on the sign-in screen, even when enrollment is closed

| | |
|---|---|
| **Status** | open |
| **Module** | web / handlers / settings |
| **Platform** | All |
| **Phase** | 3 — SPA routing |
| **First seen** | 2026-11-09 |

## Description

A signed-out visitor to the home page (`/`) of any instance is always bounced to `/#/login`. Examples are someone who scans a poster and then trims the URL, or who just types go.dustalmanac.com. When `registrations_enabled` is false, nobody new can sign up, so for almost every visitor that screen is a dead end. Brennan wants a better home page: if enrollment is disabled and the visitor isn't signed in, show a simple page that redirects to a **primary URL** set in admin settings after a short delay. Existing account holders still need a way to sign in.

## Long Description

**Today:** `web/src/App.svelte`'s guard sends any signed-out route that isn't `/login` to `loginPathWithRedirect(route.path)`. `/` gets the same treatment as a deep link. Runtime settings live in the `settings` table (migration 000006), are edited under **Admin → Settings** (`internal/handlers/settings.go`, `web/src/views/Admin.svelte`), and `validSettingValue` enforces per-key rules. `registrations_enabled` is the only key so far.

**Wanted (Brennan, 2026-11-09):**
- **A new admin setting for the primary URL,** e.g. `home_redirect_url`. It must be an absolute `https://` (or `http://`) URL, validated in `validSettingValue`. Empty or unset means today's behavior.
- **A simple signed-out home page.** When the visitor isn't signed in, `registrations_enabled` is false, and a primary URL is set, `/` shows a minimal page instead of the sign-in screen: the instance name and "Taking you to <host>…". It redirects after a short delay, about 3 seconds; the plan should pick the value and say whether it's configurable. It needs a visible "Go now" link to the primary URL, and a small, unobtrusive **Sign in** link to `/#/login` for account holders.
- **Sign-in stays reachable.** `/#/login`, emailed magic-link and recovery landings (`/auth/*`), and signed-out deep links such as `/#/campaigns/x` keep working and still go to sign-in with their redirect target. Only the bare home page redirects.
- **Signed-in users** see the dashboard as today.
- **Registration open,** or no primary URL set: no change.

**Points for the plan:**
- **SPA or server?** Decide whether the page is an SPA view (the `/` route when signed out) or served by Go before the SPA loads. The server can't see the hash, but it can see the session cookie and settings. It could even send a `Refresh` header or a `<meta http-equiv="refresh">`, so the redirect works without JavaScript.
- **Public data:** the page needs the primary URL and the registration state without signing in. Either add a small unauthenticated endpoint (e.g. `GET /api/public/home`) exposing only those two values, or render them server-side. Admin-only `/admin/settings` must stay admin-only.
- **Safety:** only an admin can set the URL, so this isn't an open redirect for visitors, but validate the scheme strictly: no `javascript:`, no relative URLs. Record changes in the audit log the way `registrations_enabled` changes are.
- **Redirect loop:** the primary URL must not point back at the instance's own `BASE_URL` home page. Reject that.
- **Short links:** `/u/{key}`, `/health`, `/api/*`, the QR endpoints and `/auth/*` are untouched.
- **Per instance:** each instance sets its own primary URL. For example, go.dustalmanac.com → https://www.dustalmanac.com/.
