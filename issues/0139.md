## Description

Click stats exist only per link (`ClicksOverTime`, `UTMStatsForLink`) and per campaign (`CampaignStats`, `CampaignRollup`) in `internal/clicks/stats.go`. Nothing adds up clicks across all of a user's links. Add an `internal/reports` package with the shared parameter model, a report registry, `GET /api/reports` (catalogue) and the first report, `GET /api/reports/overview`.

## Long Description

**Shared report parameters** (defined once in `internal/reports`, reused by every report, the REST handlers and the MCP tools):

| Param | Values | Default |
|---|---|---|
| `range` | `7d`, `30d`, `90d`, `365d`, `all` | `30d` |
| `from`, `to` | `YYYY-MM-DD`, inclusive days in `tz` (overrides `range`) | — |
| `tz` | IANA zone, e.g. `America/Los_Angeles` | `DEFAULT_TIMEZONE` config, else `UTC` |
| `compare` | `previous` (same-length window immediately before), `none` | `previous` |
| `campaign` | campaign slug, or `none` for clicks with no campaign | all |
| `source`, `medium`, `utm_campaign`, `content`, `term`, `placement` | comma-separated values; `~none` = empty/NULL | all |
| `include_bots` | `true` / `false` | `false` |
| `limit` | 1–500 | report-specific |

Rules: OR within a dimension, AND across dimensions. Days are bucketed with `date_trunc('day', clicked_at AT TIME ZONE $tz)`. The window **includes today** as a partial day and the response says so (`window.partial_last_day: true`). Every query is scoped to the caller's links (`JOIN links l ON l.id = k.link_id WHERE l.user_id = $1`). Campaign attribution uses `clicks.campaign_id`, as the existing rollups do.

**Response envelope** (every report):

```json
{
  "report": "overview",
  "window": {"from": "2026-10-20", "to": "2026-11-18", "tz": "America/Los_Angeles", "partial_last_day": true},
  "previous_window": {"from": "2026-09-20", "to": "2026-10-19"},
  "filters": {"campaign": "guides-2026-11", "source": ["mastodon", "bluesky"]},
  "generated_at": "2026-11-18T20:41:07Z",
  "highlights": ["1,284 clicks, up 18% on the previous 30 days.", "Top content: Measuring current without blowing the fuse (164)."],
  "data": { }
}
```

`highlights` are 1–5 short plain-English sentences computed in Go from `data`. An agent can answer simple questions from them without reading `data`.

**`overview` data:**

```json
{
  "totals":   {"clicks": 1284, "visitor_days": 911, "excluded_bots": 64, "links_clicked": 37, "links_total": 58},
  "previous": {"clicks": 1088, "visitor_days": 813},
  "timeseries": [{"date": "2026-10-20", "clicks": 31}],
  "previous_timeseries": [{"date": "2026-09-20", "clicks": 22}],
  "best_day": {"date": "2026-11-10", "clicks": 96},
  "campaigns": [{"slug": "guides-2026-11", "name": "Guides 2026-11", "clicks": 902}, {"slug": null, "name": "No campaign", "clicks": 71}],
  "facets": {"source": [{"value": "mastodon", "clicks": 498}], "medium": [], "utm_campaign": [], "content": [], "term": [], "placement": []}
}
```

- `campaigns` lists every campaign with ≥1 counted click in the window, sorted by clicks. It applies the UTM filters but **not** the campaign filter, so the SPA's focus chips don't all collapse to the selected campaign.
- Each facet is computed with every *other* dimension's filter applied, so a dropdown never offers a value that produces zero results.
- `visitor_days` = `COUNT(DISTINCT (ip_hash, day))` where `ip_hash IS NOT NULL`. `ip_hash` rotates daily and is nulled after 90 days (`internal/clicks/iphash.go`, `retention.go`), so when the current plus previous window reaches past 90 days, return `previous.visitor_days: null` and say so in `highlights`.
- Run all queries in one `REPEATABLE READ` read-only transaction, as `beginCampaignReadTx` does.
- Add a `DEFAULT_TIMEZONE` setting to `internal/config` (optional, IANA name, validated at load, default `UTC`), and document it in [docs/configuration.md](../docs/configuration.md).

**Registry and catalogue.** Every report registers a name, a one-line description, its extra parameters and a handler. `GET /api/reports` returns that list, so agents and the MCP `list_reports` tool can discover them. Unknown report → 404 `report_not_found`. Bad parameters → 400 with a code naming the field (`invalid_range`, `invalid_tz`, `invalid_date`, …).

## Root cause

Click aggregation existed only per link (`ClicksOverTime`, `UTMStatsForLink`) and per campaign (`CampaignStats`, `CampaignRollup`). There was no query, package or endpoint that summed clicks across all of a user's links, no shared filter model, and no time-zone-aware windows. So neither the planned Overview nor an agent could ask about overall activity.

## Fix

Added `internal/reports` with these parts:

- **Parameter model.** `ParseParams` handles `range`/`from`/`to`, `tz`, `compare`, `campaign`, the UTM filters (`~none` matches empty values), `include_bots` and `limit`. `Params.RangeExplicit` and `Params.Validate` sit on top of it.
- **Windows.** `ResolveWindows` works in calendar days, so daylight-saving changes don't shift the boundaries. Each window is half-open (start inclusive, end exclusive). Today is included and flagged as a partial day, and the previous window has the same length.
- **Query building.** A filter predicate builder (OR within a dimension, AND across dimensions, values always bound as parameters) and an exported `ScopedQuery` builder that every query starts from.
- **Registry.** Reports can declare required and enum params and a `DefaultLimit`, and can override their windows with a `Windows` hook (#0143 needs this for campaign dates).
- **`Service.Run`.** Runs a report in one `REPEATABLE READ` read-only transaction and returns the shared envelope with `highlights`.
- **`overview` report.** Returns totals, visitor-days (null when the window reaches past the 90-day `ip_hash` retention), current and previous daily series, best day, per-campaign counts (ignoring the campaign filter) and facets (each ignoring its own dimension).

The routes `GET /api/reports` and `GET /api/reports/{name}` sit behind `requireAPI`, so they accept a cookie session, a full token or a read-only token. Added an optional `DEFAULT_TIMEZONE` setting; `Local` is rejected. Review asked for reuse fixes before merge: the window hook, required/enum params, an exported query builder, a single `limit`, rejecting a `from` in the future, and route placement. All were made in `1bb6452` on `issue/0139`.

## Gotchas

- **A placeholder no SQL references.** Postgres rejects a bound parameter that no placeholder references. The tz is always passed as `$4`, so `ScopedQuery` keeps `$4::text IS NOT NULL` in the WHERE clause. Number your own arguments from `Scope.Next`.
- **`Local` time zone.** `time.LoadLocation("Local")` succeeds, but `Local` isn't a portable IANA name, so the config loader rejects it.
- **Dev mode.** With `STORAGE=json` the routes aren't mounted, so `/api/reports` falls through to the SPA handler and returns HTML. Unmounted campaign routes already behave this way.
- **Unknown campaign slug.** It currently returns zero results rather than 404. Add a `campaign_not_found` check when a report needs one.
