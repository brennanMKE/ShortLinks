# 0124 — CampaignDetail has no date-range picker: every campaign stat shows only the server's default window

| | |
|---|---|
| **Status** | open |

| **Platform** | All |
| **Phase** | 11 — Campaign analytics |
| **First seen** | 2026-11-09 |

## Description

CampaignDetail calls `getCampaignStats(slug)` with no `from`/`to`, so every number on the page uses the server's default window (`campaignWindow` in `internal/clicks/stats.go`), shown as `window_from`/`window_to`. That includes the totals, channel breakdown, per-link table and #0122's clicks-by-placement table. The API already accepts `?from=`/`?to=`, but the SPA gives no way to choose them. So "which shops got the most scans last month" can't be answered on screen.

## Long Description

The #0122 plan found this while defining that issue's "selected date range": the page has no range selector, so #0122 uses the default window.

**Wanted:**
- **Picker:** a range control on CampaignDetail, with presets such as 7 / 30 / 90 days and all-time, plus a custom from/to. It passes `from`/`to` to the campaign stats request, so every panel on the page moves together.
- **URL:** the range is reflected in the hash route (#0120), so a reload or shared link keeps it.
- **Time zones:** the UTC-midnight boundary semantics from #0119 apply. Decide whether ranges are UTC days or the viewer's local days, and label the choice.

**Considerations:**
- **Retention:** #0121's 90-day retention strips per-click detail, but the click rows stay. All-time counts stay correct, so "all-time" is valid.
- **Link detail:** decide whether LinkDetail gets the same control in the same pass, or as a follow-up.
