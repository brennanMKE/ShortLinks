## Description

`GET /api/links` is fixed to `ORDER BY created_at DESC` with all-time click counts (`internal/links/store.go:676-688`, `internal/handlers/links.go:570-598`). Add search, filters, sorting and a windowed click count, so both an agent's `list_links` tool and the redesigned Links page (#0167) can find links directly.

## Long Description

New query parameters, all optional and backwards-compatible:

| Param | Meaning |
|---|---|
| `q` | case-insensitive match on title, key or destination URL (`ILIKE`, with `%` and `_` escaped) |
| `campaign` | slug, or `none` |
| `source`, `medium` | exact `utm_source` / `utm_medium`, comma-separated |
| `status` | `active` (default when the parameter is present), `inactive`, `expired`, `all` |
| `content_key` | links with this #0140 content key |
| `sort` | `created` (default), `-created`, `clicks`, `clicks_window`, `title` |
| `window` | `7d`, `30d`, `90d`; adds `clicks_window` to each item |

Without any new parameter the response stays exactly as it is today. Each item also gains `content_key` and `label` (from #0140) and `campaign_slug`. Raise `per_page` max to 100.

## Root cause

`GET /api/links` had one fixed query: newest first, all-time click counts, 20 per page. The only way to find a link by title, campaign or source was to fetch every page and filter client-side.

## Fix

The new `links.Store.ListLinksFiltered` (`internal/links/list.go`) serves the extended mode.

**Parameters**
- `q`: `ILIKE` over title, key and destination. `%`, `_` and `\` are escaped, with `ESCAPE '\'`.
- `campaign`, `source`, `medium`: use the reports' newly exported `LinkFilterSQL`, which accepts comma lists and `~none`.
- `status`:
  - `active`, `inactive`, `expired` or `all`. Expired takes precedence over inactive or denied, which takes precedence over active.
  - **Orchestrator decision:** if the parameter is absent, it means `all`, so a search doesn't hide inactive links. An empty `status=` means `active`.
- `content_key`
- `sort`: `created` (newest first, the existing default), `-created`, `clicks`, `clicks_window`, `title`. Every sort ends with `l.id`. `sort=clicks_window` without `window` returns 400 `invalid_sort`.
- `window` (`7d`/`30d`/`90d`): computes `clicks_window` with `reports.ParseParams`/`ResolveWindows`. Today is included and bots are excluded. The time zone is `tz`, falling back to `DEFAULT_TIMEZONE` via `LinksHandler.WithDefaultTimezone`.

**Response**
- Any of the parameters above, even one with an empty value, switches to an extended response.
- Items add `content_key`, `label` (from `LinkLabel`), `campaign_slug` and `clicks_window`. The response gains a top-level `window` object.
- With none of them, the old code path runs unchanged.

**`content_key` lookup**
- SQL selects only id and destination for candidates narrowed by host.
- Go keeps exact `ContentKey` matches and then fetches only the requested page by `l.id = ANY`.
- `total` and paging are exact.

**Edge cases**
- A page past the end gets its `total` from a separate `count(*)`.
- `active` is read as `COALESCE(l.active, TRUE)`.

**Dev mode.** `devstore` implements the same filters. It records no clicks, so the click sorts fall back to newest first. `per_page` was already capped at 100.

## Gotchas

- **The SPA must send `status=active` explicitly.** An absent `status` means `all` (#0156 / #0167).
- **Percent-encoded hosts are missed** by the `content_key` host narrowing (for example `ex%61mple.com`). They are too rare to matter.
- **The golden test compares timestamps as instants.** The driver returns them in the DB session's time zone.
