## Description

Add three comparative reports that agents and the UI can call directly: `movers` (content and links with the biggest change against the previous period), `idle-links` (active links with no clicks in the window) and `campaign-comparison` (every campaign with activity, side by side).

## Long Description

**`movers`**, extra params `unit=content|link` (default `content`), `limit` (default 5 per list) and `min_clicks` (default 5, applied to the larger of the two periods so tiny numbers don't dominate):

```json
{"unit": "content", "rising": [{"title": "…", "content_key": "…", "clicks": 212, "previous_clicks": 150, "change": 62, "change_pct": 41.3}], "falling": [], "new": [], "gone_quiet": []}
```

`new`: no clicks in the previous period, at least `min_clicks` now. `gone_quiet`: at least `min_clicks` before, zero now. Rank by absolute change, with percentage as the tiebreak.

**`idle-links`**, extra param `min_age_days` (default 7, so links created yesterday aren't flagged): active, non-expired links with zero counted clicks in the window, with `created_at`, `last_clicked_at` (all-time, may be null), campaign and content key. Sorted oldest first.

**`campaign-comparison`**: one row per campaign with at least one counted click in the window, or whose date range overlaps it. Each row has slug, name, status (`live`, `scheduled`, `ended`, `archived`, from the dates), start and end dates, link count, links clicked, clicks, previous clicks, clicks per active day, top content (title + clicks) and top source. Sorted by clicks.

## Root cause

The reports could rank and break down clicks. None of them compared periods to find what changed, found links with no activity, or set campaigns side by side, so "what's rising?", "what's dead?" and "which campaign is doing best?" each took several calls and some arithmetic.

## Fix

Added three reports in `internal/reports`:

- **`movers`** (`unit=content|link`, `min_clicks`, `limit`) returns `rising`, `falling`, `new` and `gone_quiet`.
  - `unit=content` reuses `loadLinks` and sorts group members the way `top-content` does, so the counts and titles match exactly.
  - Groups with clicks only in the previous period are kept, so `gone_quiet` works.
  - `min_clicks` applies to the larger of the two periods.
  - Results are ranked by absolute change, then percentage change.
  - With `compare=none` or `range=all`, the report returns `compared:false` and empty lists.
- **`idle-links`** (`min_age_days`, default 7) returns active links with no denial reason that haven't expired, were created on or before today minus N calendar days in `tz`, and had no counted clicks in the window. It sorts oldest first, includes `last_clicked_at` (all time, bots excluded) and a `total_idle` count. The shared filters match the link's own stored fields through the new `Params.linkFilterSQL`.
- **`campaign-comparison`** returns one row per campaign that had counted clicks in the window or whose dates overlap it. Each row has status, dates, links, links clicked, clicks, previous clicks, clicks per active day, top content and top source. Clicks are attributed by `clicks.campaign_id`, and the whole report runs in five queries.
- **`CampaignStatus`** is a pure function for #0146 to reuse. The precedence is archived, then scheduled, then ended, then live. Bounds are inclusive, and today is evaluated in `tz`. Stored dates are UTC-midnight `timestamptz`, read as UTC civil dates. A campaign with no dates is live.

The review fixes went into `8410ad5` on `issue/0142`: the calendar-day idle cutoff, the `movers` member order, and test gaps.

## Gotchas

- **Scheduled campaigns never overlap a window.** Windows end today, and a campaign that starts today already counts as live, so a scheduled campaign appears in `campaign-comparison` only through clicks.
- **Undated campaigns never overlap either**, so they also appear only through clicks.
- **`idle-links` filters by link fields, not click values.** It applies the shared filters to the link's own stored fields because it asks about the link, not its clicks.
- **The last-click lookup may need an index later.** `idle-links` runs `max(k.clicked_at)` for every idle candidate, using `idx_clicks_link_id`. If #0150's performance budget isn't met, add an index on `clicks (link_id, clicked_at)`.
