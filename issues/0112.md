# 0112 — Uncapped Source and Medium columns overflow the campaign links table

| | |
|---|---|
| **Status** | open |
| **Module** | web |
| **Platform** | All |
| **First seen** | 2026-08-08 |

## Description

The campaign links table ([#0103](0103.md)) caps `.title-cell`, `.dest-cell`, and `.placement-cell` with `max-width`, but leaves the **Source** and **Medium** columns uncapped. Ordinary UTM values — not pathological ones — blow past the width the table has to give.

Measured: a campaign using `utm_source=partner_newsletter_q3` widens the Source column from **76.8px to 161.4px**. A 44-link campaign with that shape measures `.table-scroll` at **1039 / 926** — a 113px overflow with the Remove button pushed well outside the container.

**This is pre-existing and is not a [#0106](0106.md) regression.** It reproduces at pre-#0106 geometry with the QR column hidden entirely. #0106's verification found it while building an adversarial dataset and correctly scoped it out.

## Why this matters

[#0103](0103.md) established `scrollWidth == clientWidth == 926` with no horizontal overflow as a hard invariant, and it was treated as blocking in that issue and again in [#0106](0106.md). The invariant is currently enforced only against the *capped* columns — two columns can silently violate it with realistic content.

`partner_newsletter_q3` is not an unreasonable UTM source. `docs/utm.md`'s own canonical-casing guidance encourages descriptive, consistent values, and the print convention this system documents (`utm_source=flyer`, `utm_medium=print`) is short only by luck.

## Scope / deliverables

- Cap the Source and Medium columns so they cannot push the table past its container, consistent with how the other text columns are handled.
- **Cap the header cells, not just the body cells.** [#0106](0106.md)'s verification found that `.placement-cell`'s 90px `max-width` is **completely inert** because `<th>Placement</th>` has no cap and the header word alone sets the column to 101.56px. Whatever is done here must not repeat that — a `max-width` on the `<td>` alone does nothing when the `<th>` is wider.
- Decide what a truncated Source/Medium should show. These are short-ish values where the tail often carries the meaning (`partner_newsletter_q3`), so a leading ellipsis or a tooltip may serve better than trailing truncation.

## Acceptance criteria

- [ ] `.table-scroll` satisfies `scrollWidth == clientWidth == 926` at 1024, 1280, 1440, and 1920 with a campaign whose Source and Medium values are long enough to have previously overflowed.
- [ ] **Report `min-content` headroom, not just a passing threshold.** `table { width: 100% }` with `table-layout: auto` means 926 is a threshold, not a fit — the used width is `max(926, min-content)`, so a table can measure 926/926 while sitting a fraction of a pixel from failure. Measure with `.links-table { width: min-content }` and state the margin.
- [ ] Header cells are capped too, verified by measuring the `<th>` rather than assuming the `<td>` cap applies.
- [ ] Truncated values remain distinguishable between rows, or are recoverable some way that works on touch (a hover-only `title` tooltip is not sufficient on its own).
- [ ] 375px stacked layout still renders correctly with `document.scrollWidth == 375`.
- [ ] `cd web && npm run check` 0 errors; `npm test` passes.
- [ ] **Seen running** via `./scripts/dev.sh` against a campaign seeded with long UTM values.

## Out of scope

- The `Destination` column's content problem — [#0113](0113.md).
- QR column sizing — [#0106](0106.md).
- Making the table horizontally scrollable as an escape hatch. [#0103](0103.md) decided against that deliberately; this issue is about fitting, not about relaxing the invariant.

## Notes

- The measurement approach that found this is worth reusing: build the adversarial dataset **first** (content that reaches every cap), then measure. Two consecutive [#0106](0106.md) fix rounds reported a passing number that evaporated under harsher data, and in both cases the variable was the dataset rather than the CSS.
- Row count is not the variable — column width is.
