## Description

First slice of the campaigns feature (`docs/campaigns-plan.md`). Introduces the `campaigns` entity and everything needed to create, read, update, archive, and delete one. No link membership and no stats yet — those are [#0099](0099.md) and [#0102](0102.md).

The plan's central design decision is that **campaign membership is a first-class database relationship, not a string match on `utm_campaign`**. This issue creates the entity that relationship points at. The reasoning is verified: `internal/handlers/redirect.go:169-173` reads UTM values with `q.Get(...)` from the *inbound* query string only, so a link created with `utm_campaign=summer-fair` baked into its destination and then shared as a bare `https://go.sstools.co/u/ab12de` records `utm_campaign = NULL` on every click. Grouping campaign metrics by `clicks.utm_campaign` cannot work for the normal workflow.

## Data model

Migration `000010_create_campaigns` (highest existing is `000009`; follow the `NNNNNN_description.{up,down}.sql` convention with a down that exactly reverses the up).

```
campaigns
  id                   BIGSERIAL PRIMARY KEY
  user_id              BIGINT NOT NULL REFERENCES users(id)
  name                 TEXT NOT NULL
  slug                 TEXT NOT NULL          -- URL-safe, used in API paths
  description          TEXT
  starts_at            TIMESTAMPTZ            -- nullable; drives default chart window
  ends_at              TIMESTAMPTZ            -- nullable
  archived             BOOLEAN NOT NULL DEFAULT FALSE
  default_utm_source   TEXT
  default_utm_medium   TEXT
  default_utm_campaign TEXT                   -- defaults to slug on create
  default_utm_term     TEXT
  default_utm_content  TEXT
  created_at           TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT now()

  UNIQUE (user_id, slug)
INDEX idx_campaigns_user_id ON (user_id)
```

**Campaigns are scoped per user**, matching how `links` is owned — decided, not assumed. Slug uniqueness is per user, not global.

**The five `default_utm_*` columns are a decided addition to the plan's schema.** Selecting a campaign in the create form prefills the UTM builder fields, and every prefilled value stays editable — the campaign never forces a value. `default_utm_campaign` defaults to the slug at create time. If in practice only `utm_campaign` ever gets a campaign-level default, the other four columns are harmless and can be dropped later; the reverse retrofit would be a migration.

## Scope / deliverables

- Migration `000010_create_campaigns` up and down.
- New package `internal/campaigns`, mirroring the structure of `internal/links`:
  - `Store` with `Create`, `Update`, `Archive`, `Delete`, `ListForUser`, `GetBySlug`.
  - Slug generation and validation: lowercase, hyphens, collision-suffixed against the per-user unique constraint.
  - Ownership checks in whichever layer `internal/links` already puts them — follow the existing pattern rather than inventing a new one.
- Endpoints, following existing `/api/` conventions for the auth guard, error shape, and the SSE broker:

  | Method | Path | Purpose |
  |---|---|---|
  | `GET` | `/api/campaigns` | List for the user (link count and total clicks land in [#0102](0102.md); return 0 for now) |
  | `POST` | `/api/campaigns` | Create |
  | `GET` | `/api/campaigns/{slug}` | Metadata |
  | `PATCH` | `/api/campaigns/{slug}` | Update name, description, dates, archived, defaults |
  | `DELETE` | `/api/campaigns/{slug}` | Delete |

- Audit actions mirroring the existing set: `campaign.created`, `campaign.updated`, `campaign.deleted`. (`campaign.link_assigned` / `campaign.link_unassigned` belong to [#0099](0099.md).)

## Acceptance criteria

- [ ] `migrate up` then `migrate down` returns the schema to its prior state exactly — verified, not assumed.
- [ ] Slug generation is deterministic for a given name, and a collision within one user's campaigns gets a suffix rather than an error.
- [ ] Two different users can each hold a campaign with the same slug; one user cannot.
- [ ] `default_utm_campaign` is populated from the slug when not supplied on create.
- [ ] **Ownership is enforced on every endpoint**: user A cannot read, update, archive, or delete user B's campaign — asserted with a second seeded account, not reasoned about.
- [ ] Archive is reversible (it is a boolean, unlike issue archival); delete is not, and delete does not cascade to anything in this issue's scope.
- [ ] Audit rows are written in the same transaction as the mutation they describe.
- [ ] `go build ./...`, `go vet ./...`, `gofmt -l` clean on touched files; `go test ./...` passes with new tests observed **by name** against the live `shortlinks_test` database.

## Out of scope

- Link membership, `links.campaign_id`, assign/unassign — [#0099](0099.md).
- Anything touching `clicks` — [#0100](0100.md).
- Stats, rollups, link counts, click totals — [#0102](0102.md).
- All frontend — [#0103](0103.md).
- Cross-user or shared campaigns. Per-user scoping is decided; revisiting it later means migrating the unique constraint.
