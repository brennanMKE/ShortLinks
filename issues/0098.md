## Description

First slice of the campaigns feature (`docs/campaigns-plan.md`). Introduces the `campaigns` entity and everything needed to create, read, update, archive, and delete one. No link membership and no stats yet — those are [#0099](0099.md) and [#0102](0102.md).

The plan's central design decision is that **campaign membership is a first-class database relationship, not a string match on `utm_campaign`**. This issue creates the entity that relationship points at. The reasoning is verified: `internal/handlers/redirect.go:169-173` reads UTM values with `q.Get(...)` from the *inbound* query string only, so a link created with `utm_campaign=summer-fair` baked into its destination and then shared as a bare `https://go.sstools.co/u/ab12de` records `utm_campaign = NULL` on every click. Grouping campaign metrics by `clicks.utm_campaign` cannot work for the normal workflow.

## Data model

Migration `000010_create_campaigns` (highest existing is `000009`; follow the `NNNNNN_description.{up,down}.sql` convention with a down that exactly reverses the up).

```
campaigns
  id                   BIGSERIAL PRIMARY KEY
  user_id              BIGINT NOT NULL REFERENCES users(id)
  name                 TEXT NOT NULL
  slug                 TEXT NOT NULL          -- URL-safe, used in API paths
  description          TEXT
  starts_at            TIMESTAMPTZ            -- nullable; drives default chart window
  ends_at              TIMESTAMPTZ            -- nullable
  archived             BOOLEAN NOT NULL DEFAULT FALSE
  default_utm_source   TEXT
  default_utm_medium   TEXT
  default_utm_campaign TEXT                   -- defaults to slug on create
  default_utm_term     TEXT
  default_utm_content  TEXT
  created_at           TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at           TIMESTAMPTZ NOT NULL DEFAULT now()

  UNIQUE (user_id, slug)
INDEX idx_campaigns_user_id ON (user_id)
```

**Campaigns are scoped per user**, matching how `links` is owned — decided, not assumed. Slug uniqueness is per user, not global.

**The five `default_utm_*` columns are a decided addition to the plan's schema.** Selecting a campaign in the create form prefills the UTM builder fields, and every prefilled value stays editable — the campaign never forces a value. `default_utm_campaign` defaults to the slug at create time. If in practice only `utm_campaign` ever gets a campaign-level default, the other four columns are harmless and can be dropped later; the reverse retrofit would be a migration.

## Scope / deliverables

- Migration `000010_create_campaigns` up and down.
- New package `internal/campaigns`, mirroring the structure of `internal/links`:
  - `Store` with `Create`, `Update`, `Archive`, `Delete`, `ListForUser`, `GetBySlug`.
  - Slug generation and validation: lowercase, hyphens, collision-suffixed against the per-user unique constraint.
  - Ownership checks in whichever layer `internal/links` already puts them — follow the existing pattern rather than inventing a new one.
- Endpoints, following existing `/api/` conventions for the auth guard, error shape, and the SSE broker:

  | Method | Path | Purpose |
  |---|---|---|
  | `GET` | `/api/campaigns` | List for the user (link count and total clicks land in [#0102](0102.md); return 0 for now) |
  | `POST` | `/api/campaigns` | Create |
  | `GET` | `/api/campaigns/{slug}` | Metadata |
  | `PATCH` | `/api/campaigns/{slug}` | Update name, description, dates, archived, defaults |
  | `DELETE` | `/api/campaigns/{slug}` | Delete |

- Audit actions mirroring the existing set: `campaign.created`, `campaign.updated`, `campaign.deleted`. (`campaign.link_assigned` / `campaign.link_unassigned` belong to [#0099](0099.md).)

## Root cause

Not a defect — the first slice of a new feature. `campaigns` did not exist.

## Fix

Migration `000010_create_campaigns`, a new `internal/campaigns` package mirroring `internal/links`, five CRUD endpoints, three audit actions, and an in-memory devstore twin. Three decisions worth recording:

**Store methods are `Campaign`-prefixed** (`CreateCampaign`, `UpdateCampaign`, `ArchiveCampaign`, `DeleteCampaign`, `ListCampaignsForUser`, `GetCampaignBySlug`). The first implementation used bare `Create`/`Update`/`Delete`/`GetBySlug`, which **structurally blocked dev mode**: `devstore.Store` already carries `Create`/`Update`/`Delete`/`Get` with different signatures for `filters.FilterRule`, and one Go type cannot hold both. Every other handler-facing interface here already prefixes (`CreateLink`, `ListSettings`, `GetUser`). The prefix is now pinned by a compile-time `var _ interface{...} = (*Store)(nil)` assertion in `devstore`.

**Dev mode got a real in-memory backing, not a stub.** Unmounted routes were being swallowed by the `GET /` SPA catch-all, so `GET /api/campaigns` returned **200 `text/html`** — `fetch(...).then(r => r.json())` saw `res.ok === true` and threw on the `<`. Since `scripts/dev.sh` hard-wires `STORAGE=json` and [#0103](0103.md) must be seen running there, a stub would have left #0103 unbuildable. The devstore reuses the real `campaigns.Slugify`/`GenerateUniqueSlug`, so slug behavior is one implementation rather than two.

**`starts_at <= ends_at` is enforced in the schema, not only the handler** — a `CHECK` constraint added to `000010` before merge. [#0102](0102.md) uses that window as the default chart range, so an inverted row would render a permanently empty chart with no obvious cause. Adding it while the migration was unmerged cost nothing; after #0102 it would have cost a migration.

## Verification

`go build ./...`, `go vet ./...` clean; `gofmt -l` clean on touched files (the five repo-wide flags are pre-existing). `go test ./... -race -count=1` green apart from the pre-existing `internal/config` `TestLoad_DefaultsApplied`, confirmed identical on `main`. **56 tests observed by name**: 25 `internal/campaigns`, 15 `internal/handlers`, 16 `internal/devstore`.

The migration round-trip was verified by `pg_dump --schema-only` before and after `up`/`down`, diffed — identical but for pg_dump's random `\restrict` nonce. Re-verified after the `CHECK` was added. The constraint was then confirmed live and independently by the orchestrator: a raw inverted `INSERT` is rejected with SQLSTATE `23514`.

**Two tests were caught passing vacuously in review and rewritten**, both mutation-proven afterwards by implementer and reviewer independently:

- *Audit atomicity.* The original forced `tx.Commit` to fail through an injectable seam. Moving the audit write to **after** the commit as a fire-and-forget `Record` — the exact arrangement the acceptance criterion forbids — left both tests **passing**, because a failed commit returns before the post-commit write is reached. Replaced with a probe that makes the audit `INSERT` itself fail inside the transaction via an FK violation on `audit_log.actor_id`. That version fails under commit-then-`Record` and passes on the real code, and needs no production seam at all.
- *List key presence.* Decoding into the response struct made an **absent** JSON key indistinguishable from a present `0`; adding `,omitempty` left the test green. Rewritten to decode into `map[string]any` and assert presence.

Ownership was mutation-verified as load-bearing: relaxing `WHERE user_id = $1` fails 8 tests. Devstore concurrency was checked with 30 concurrent creates under `-race` — 30 distinct slugs, no races. Adversarial input found no injection or traversal surface (`'; DROP TABLE campaigns; --` → `drop-table-campaigns`; `../../etc/passwd` → `etc-passwd`). Reviewed by Opus → REQUEST CHANGES (4 blocking) → fixed → APPROVE → one hardening pass.

## Gotchas

- **An assertion that can only observe the passing state proves nothing.** Both vacuous tests here had that shape, as did #0096's 401 replay and #0097's forbidden-substring list. The reliable check is mutation: break the behavior and confirm the test notices. Reviewing the test's *logic* is not a substitute — both of these read correctly.
- **Interface method names are a cross-package contract in Go, not a local style choice.** Bare `Create`/`Update`/`Delete` on a handler-facing interface silently forecloses any type that already has those names. The cost surfaced two packages away, as an HTML response to a JSON request.
- **An unmounted route under an SPA catch-all does not 404.** It returns the index page with `200 text/html`, which passes `res.ok` and fails at `JSON.parse`. Any handler mounted conditionally needs its absence tested, not assumed.
- **Schema-level invariants are free before the migration merges and cost a migration after.** The `CHECK` went in for nothing; a week later it would have been `000013`.
- **Returning a struct containing pointers from an in-memory store aliases its state.** A caller mutating `*c.StartsAt` mutated the store. Harmless until #0102's window-clamping arithmetic, which is exactly the kind of delayed trigger that makes it hard to diagnose.
- **`len(s)` is bytes; validation messages say characters.** A 100-character CJK name was rejected as "at most 255 characters". `utf8.RuneCountInString` is the fix, and stays well inside the 2704-byte btree index-row limit.

## Downstream constraints

Recorded here because they bind [#0099](0099.md)–[#0108](0108.md):

1. **The `Campaign` prefix is a load-bearing contract.** #0099's assign/unassign must be `AssignLinkToCampaign` / `UnassignLinkFromCampaign` or the devstore collision returns.
2. **Every new campaign store method now needs an in-memory twin**, or dev mode regresses to the SPA-catch-all failure. Recurring cost, taken on deliberately.
3. **#0099 and #0100 must actually ship `ON DELETE SET NULL`.** `DeleteCampaign` is a hard delete; without those, it starts throwing FK violations as 500s with no test to catch it. Relatedly, #0099's "deleting a campaign unassigns its links" will be satisfied by the FK rather than application code, so the `campaign.deleted` audit row will not record how many links were unassigned — decide that deliberately.
4. **The slug is immutable** (confirmed deliberate — it follows from `UNIQUE (user_id, slug)` and from `default_utm_campaign` being pinned at creation). A renamed campaign keeps its old slug, so its URL and UTM value drift from its name permanently. #0103's edit form should say so; #0108 must document it.
5. **`default_utm_campaign` can be cleared to NULL via PATCH and is never re-derived.** #0099's prefill must decide whether NULL falls back to the slug or stays empty.
6. **No SSE broadcast.** #0103's campaigns list will be static where the links dashboard is live.
7. **`internal/audit/audit.go`'s doc** ("handlers log-and-continue; ceremonies write in-band") no longer describes all callers — campaigns is the first non-ceremony `WriteTx` caller. Update in #0108; #0099 should pick a convention deliberately rather than by copy.
8. **`GET /api/campaigns/{slug}` omits `link_count`/`total_clicks`** by design. #0102 should extend it with a `campaignDetailView` wrapper mirroring `linkDetailView`, which is purely additive.
9. **`idx_campaigns_user_id` is redundant** with the `UNIQUE (user_id, slug)` constraint index for `WHERE user_id = $1`. Harmless, but #0102's `EXPLAIN` criteria will show the constraint index chosen.
10. **Dev mode records no campaign audit rows** (matching the `DeactivateUser` precedent), so `campaign.*` events cannot be exercised in dev.
11. **`maxCampaignNameLength = 255` runes** is an API contract #0103's form should mirror client-side.

## Follow-ups

- **Slugs are ASCII-only.** Cyrillic, CJK, and emoji names all collapse to `campaign`, `campaign-2`, `campaign-3`; `École d'été` becomes `cole-d-t` rather than folding to `ecole-d-ete`. Acceptable for a single-admin English-language instance, and the slug is user-visible in [#0103](0103.md) — worth a decision there or in [#0108](0108.md) rather than leaving it implicit.
- `cmd/shortlinks/seed_test.go:36` does `DELETE FROM users WHERE email = $1` with the error swallowed; once a seeded user owns a campaign, `campaigns.user_id`'s `NO ACTION` FK makes that cleanup silently stop working.
