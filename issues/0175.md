## Description

When `home_mode=activity` (#0174), the signed-out home page shows a site-wide summary of the past 7 days: a daily clicks chart and the 3 most-clicked links. There are no campaign or UTM breakdowns. Every report in `internal/reports` is scoped to one user, so this needs a separate, deliberately small, instance-wide query that is safe to serve to anonymous visitors.

## Long Description

**Data** (add as `activity` to `GET /api/public/home`, present only when `home_mode=activity`):

```json
{"window": {"from": "2026-11-12", "to": "2026-11-18", "tz": "America/Los_Angeles", "partial_last_day": true},
 "total_clicks": 412,
 "timeseries": [{"date": "2026-11-12", "clicks": 51}],
 "top_links": [{"title": "Measuring current without blowing the fuse", "short_url": "https://go.example.com/u/HaQRwV", "clicks": 64}]}
```

- **Scope:** every user's links on the instance, since this is the site's own activity. Bots are excluded. The window is 7 days including today, in `DEFAULT_TIMEZONE`, built with `reports.ResolveWindows` so the days match the rest of the app.
- **No campaigns or UTM values:** no breakdowns, no campaign names, no sources.
- **Top links: exactly what a visitor sees.** Show the title (the `LinkLabel` head, so channel suffixes like "— Mastodon guide post 84" don't show), the short URL and the click count. **Never the destination URL**, which the short link reveals anyway once followed. Only active, unexpired, non-denied links are listed. Links whose title is empty use the short URL as the label.
- **Grouping:** group by content key (#0140) so one guide posted to two platforms appears once, linking to its most-clicked member. This matches "most popular", and it doesn't show the same title twice.
- **Opt-out per link:** none in this issue. The admin opts in for the whole site, and that's a clear enough control for v1. Note it in the admin UI copy (#0177): "Titles of your most-clicked links will be public."
- **Load:** anonymous traffic must not hit Postgres on every request. Cache the computed `activity` in memory for 5 minutes (invalidated when `home_mode` changes) and rate-limit `GET /api/public/home` with the existing limiter.
- Put the query in `internal/reports` as an exported function, for example `PublicSummary(ctx, q, now, tz, limit)`, not as a registered per-user report. It must not be reachable through `/api/reports`.

## Acceptance criteria

- `activity` is present only in `activity` mode. Tests cover modes `default` and `about` returning no activity and running no click query.
- DB-backed tests cover: clicks summed across several users; bots excluded; today included; inactive, expired and denied links excluded from the top 3; channel suffixes stripped; two links to the same content collapsed into one; no destination URL anywhere in the JSON.
- A cache test shows a second request within 5 minutes runs no SQL.
- Docs describe what the public page reveals.
- `go test ./...` passes.

## Root cause

Every report in `internal/reports` is scoped to one user (`l.user_id = $1`), and `GET /api/public/home` had no activity field, so the public page had nothing site-wide to show.

## Fix

- `reports.PublicSummary` (`internal/reports/public.go`): instance-wide, non-bot clicks over 7 days (today included, `DEFAULT_TIMEZONE`, via `ParseParams` and `ResolveWindows`), zero-filled per day. Top 3 links are limited to active, non-denied, unexpired links and grouped by `ContentKey`. Each group links to its most-clicked member and shows that group's `LinkLabel` head, or the short URL when untitled. The output type has no destination, campaign or UTM fields. It is not a registered report.
- `GET /api/public/home` adds `activity` only in `activity` mode. The summary is cached in process for 60 seconds (the coordinator's value, replacing the issue's 5 minutes). A failure omits `activity` and is not cached. The route is rate limited per IP (1/s, burst 30).
- The five settings reads (#0174) are now one `GetSettings` query, on `auth.Store` and `devstore`.
- `validHomeText` rejects Unicode category Cf (bidi overrides, zero-width characters, BOM). `\r\n` and a lone `\r` are stored as `\n` for `home_title` and `home_about`.
- Docs (`docs/auth.md`) and OpenAPI describe what the public page reveals.

Not done: invalidating the cache when `home_mode` changes (a mode switch is picked up within 60s anyway, because activity is only computed in activity mode). No migration was needed.

## Review round 1

- Top links now require `campaign_id IS NOT NULL AND expires_at IS NULL` (plus active and non-denied), so invites and other expiring or uncurated links are never published. Their clicks still count in the totals. A TODO marks the `external_id IS NULL` condition for #0182. Tests cover an expiring link (excluded), a link with no campaign (excluded) and campaign links (included). The rule is in `docs/auth.md`, the OpenAPI description and `issues/0177.md`, so the admin copy can say "Top links are drawn from campaign links only."
- The activity computation now runs single-flight on a detached 5s context. The mutex is held only to check and set state, never across the query. After a failure the page is served without `activity` for 10s. New tests: a slow store shared by 5 concurrent requests with a client disconnect mid-flight (run with `-race`), and failure backoff.
- Nits: the needless `links` join is dropped from the daily query. U+200D (ZWJ) is allowed in `validHomeText`, with a test (U+200C is still rejected).
- Verification: `go build ./... && go vet ./...`, then `go test -p 1 ./...` on a fresh DB (below).
