# 0136 — Remove ShortLinks' own passkey code and tables once every instance runs on Portiko

| | |
|---|---|
| **Status** | open |
| **Module** | auth / db / handlers / web |
| **Platform** | All |
| **Phase** | 15 — Portiko cutover and cleanup |
| **First seen** | 2026-11-12 |

## Description

After all three instances have switched over (#0135) and Brennan has confirmed it, delete the custom passkey code: the registration, login and recovery services and WebAuthn setup in `internal/auth`, the `/auth/register|login|recover` handlers, the credentials API, the matching `devstore` stubs, and the SPA's `RegisterVerify`, `RecoverVerify` and `webauthn.ts`. Remove the `PORTIKO_ENABLED` switch so Portiko is the only sign-in path, and drop the old tables in a migration.

## Long Description

**Delete:**
- `internal/auth`: `registration.go`, `login.go` (except whatever `Logout` logic still applies), `recovery.go` and `webauthn.go`, plus their tests and the parts of `store.go` that only served them.
- **Keep:** `apitokens.go`, `tokens.go`, `users.go` (admin user management) and the settings accessors.
- `internal/handlers/auth.go` (the ceremony handlers) and `internal/handlers/credentials.go`.
- The sign-in rate limiters in `main.go`.
- The `go-webauthn/webauthn` dependency in `go.mod`, if nothing else uses it. `virtualwebauthn` stays if the Portiko integration tests use it.
- `web/src/views/RegisterVerify.svelte`, `RecoverVerify.svelte`, `web/src/lib/webauthn.ts` and its tests.

**Migration:** drop `passkey_credentials`, `webauthn_challenges`, `pending_registrations`, the recovery token table and `sessions`. The down migration recreates them empty. Make `users.subject` `NOT NULL` if every row has one; otherwise explain in the plan why not.

**Docs:** rewrite `docs/auth.md` and `docs/passkeys.md` to describe the embedded provider and point to Portiko's docs. Update `README.md`, `PRD.md` notes, `docs/configuration.md` and `issues/Issues.md`'s module table (`auth`).

## Notes

- `go test ./...`, `cd web && npm test && npm run build`, and a full production build must pass.
- The audit log keeps its historical `account.registered`/`account.recovered` rows. New sign-in events from Portiko are in its `auth_audit` table. Say this in `docs/audit.md`.
