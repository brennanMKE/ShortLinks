# 0115 — A seven-digit click count overflows the campaign links table

| | |
|---|---|
| **Status** | open |
| **Module** | web |
| **Platform** | All |
| **First seen** | 2026-08-08 |

## Description

The `Clicks` column in the campaign links table renders an **unformatted integer with no `max-width`**, so a large enough count pushes the table past its container and breaks [#0103](0103.md)'s zero-horizontal-scroll invariant.

Measured at 1280px against a 12-row campaign, rewriting the `Clicks` cells:

| click count | `.links-table` `min-content` | headroom vs 926 | `.table-scroll` |
|---|---|---|---|
| ordinary (3 digits) | 917.03px | **+8.97** | 926 / 926 |
| `1234567` (7 digits) | 927.45px | **−1.45** | **927 / 926** |
| 8 digits | 935.56px | **−9.56** | overflows further |

`Share of listed links` contributes nothing here — it is an integer percentage capped at `100%` (`web/src/lib/campaigns.ts`, `Math.round`).

## Why this matters

Not because seven-digit counts are common — they are not, for this app — but because the invariant is currently held by an **unstated assumption about data magnitude**. [#0106](0106.md) spent four review rounds restoring this invariant and [#0112](0112.md) another round; both ended with a headroom figure quoted as if it were unconditional. It is conditional on click counts staying under seven digits, and nothing records or enforces that.

This is the same shape as [#0112](0112.md): a column left uncapped because its content *happened* to be short in every dataset anyone measured.

## Scope / deliverables

- Cap the `Clicks` column, or format the number so its width is bounded (e.g. `1.2M` above a threshold), or otherwise make the invariant independent of click magnitude. Decide, implement, state the reasoning.
- **Cap the `<th>` as well as the `<td>` if a `max-width` is used.** A `max-width` on the `<td>` alone is inert under `table-layout: auto` once the uncapped `<th>` is wider — that is why `.placement-cell`'s 90px cap did nothing for the whole life of #0103.
- If the number is abbreviated, the exact value must stay recoverable in a way that **works on touch** — a hover-only `title` is not sufficient on its own.
- Whatever is chosen, the sort must keep ordering by the true count, not by the formatted string.

## Acceptance criteria

- [ ] `.table-scroll` satisfies `scrollWidth == clientWidth == 926` at 1024, 1280, 1440, and 1920 with a campaign containing at least one **eight-digit** click count.
- [ ] **Report `min-content` headroom in px, not just a passing threshold.** With `table { width: 100% }` and `table-layout: auto` the used width is `max(926, min-content)`, so a table can read 926/926 while sitting a fraction of a pixel from failure — #0106 shipped exactly that at 0.36px.
- [ ] The headroom figure recorded in `CampaignDetail.svelte`'s geometry comment is **unconditional** afterwards, or its remaining conditions are stated explicitly.
- [ ] Sorting by clicks still orders by magnitude with mixed-width values present.
- [ ] The exact count is recoverable on touch if it is abbreviated.
- [ ] 375px stacked layout still renders the full count and `document.scrollWidth == 375`.
- [ ] `cd web && npm run check` 0 errors; `npm test` passes.
- [ ] **Seen running** via `./scripts/dev.sh` with a seeded eight-digit count.

## Out of scope

- The `Source`/`Medium` caps — [#0112](0112.md).
- The `Destination` column's content problem — [#0113](0113.md).
- The ~901–944px overflow band — [#0114](0114.md).
- Formatting click counts anywhere else in the app. If a shared helper is introduced, other call sites can adopt it later.

## Notes

- **Not a [#0112](0112.md) regression** — `Clicks` is uncapped on `main` too, and was uncapped before the QR column existed. #0112's review surfaced it while stress-testing that change's margin.
- Build the adversarial dataset **first**, then measure. Two consecutive #0106 rounds reported a passing number that evaporated under harsher data, and both times the variable was the dataset rather than the CSS.
- Any measurement left in a code comment must be one reproduced in that round. This series shipped several authoritative-looking numbers that did not reproduce, including one with an inverted sign that made a failing step read as passing.
