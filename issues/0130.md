# 0130 — Embed the Portiko provider in the ShortLinks binary under `/id` on each instance's own host

## Description

Run Portiko's `provider` package inside `cmd/shortlinks`, served under `/id` on the instance's own host (e.g. `https://go.sstools.co/id`). It should use the instance's existing `WEBAUTHN_RP_ID` and its own Postgres schema. It sits behind a config switch that is **off by default**, so the binary can ship before any instance cuts over. Sign-in doesn't use it yet: that's #0132.

## Long Description

**Wiring (`cmd/shortlinks/main.go`):**
- New config: `PORTIKO_ENABLED` (default false), `PORTIKO_CRYPTO_KEY` (seals the signing key; required when enabled), and a `PORTIKO_DATABASE_URL` that defaults to `DATABASE_URL` with `search_path=portiko`.
  - Derive the rest from existing settings: `ISSUER = BASE_URL + "/id"`, `WEBAUTHN_RP_ID` and `WEBAUTHN_RP_ORIGINS` from the current values, `SERVICE_NAME` "ShortLinks".
  - Document the new settings in `docs/configuration.md` and `DEPLOYMENT.md`.
- At startup:
  1. Create the `portiko` schema if it's missing.
  2. Call `provider.Migrate`, then `provider.New`.
  3. Mount `p.Handler()` under `/id/` (per #0128).
  4. Call `RegisterClient` for ShortLinks itself. It needs `FirstParty: true`, the redirect URI `BASE_URL/auth/portiko/callback`, the post-logout URI `BASE_URL/`, and the back-channel URI `BASE_URL/auth/portiko/backchannel`. The client secret comes from config.
- **Schema isolation:** Portiko has its own `users` and `schema_migrations` tables, so it must not share the `public` schema with ShortLinks. Check that Portiko's migrator (`migrations/apply.go`) creates `schema_migrations` in the `search_path` schema and not in `public`. If it doesn't, fix that upstream or use a separate database.
- **Mail:** adapt `auth.SESMailer` to Portiko's `provider.Mailer` interface (one-time code + new-passkey notice), and pass it in `provider.Options.Mailer`. Without SES, use Portiko's stdout mailer.
- **Registration policy:** pass the #0129 hook, backed by `auth.Store.RegistrationsEnabled`.
- **Apache:** `ProxyPass /` already covers `/id/…`, so no vhost change is needed. Confirm Portiko's `TRUSTED_PROXIES` is set so its rate limits see real client IPs.
- `/health` stays ShortLinks'. Portiko's health check becomes `/id/health`.

## Expected behavior

With the switch on, `GET /id/.well-known/openid-configuration` returns an issuer of `BASE_URL/id`, and a person can enroll a passkey at `/id/signin` under the instance's existing RP ID. With it off, nothing changes.

## Notes

- Pin Portiko to a specific commit in `go.mod`. Its README says the API is still changing and nothing is tagged.
- Portiko currently uses a newer `go-webauthn` (v0.18.x) than ShortLinks (v0.17.4). Updating the module will bump ShortLinks' copy too, so run the existing auth tests.
- Tests: an integration test using `internal/testdb` that boots the provider under `/id` next to the ShortLinks mux, then checks that `/u/{key}` redirects and `/health` still work and that discovery serves under `/id`.
