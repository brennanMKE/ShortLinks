## Description

Run Portiko's `provider` package inside `cmd/shortlinks`, served under `/id` on the instance's own host (e.g. `https://go.sstools.co/id`). It should use the instance's existing `WEBAUTHN_RP_ID` and its own Postgres schema. It sits behind a config switch that is **off by default**, so the binary can ship before any instance cuts over. Sign-in doesn't use it yet: that's #0132.

## Long Description

**Wiring (`cmd/shortlinks/main.go`):**
- New config: `PORTIKO_ENABLED` (default false), `PORTIKO_CRYPTO_KEY` (seals the signing key; required when enabled), and a `PORTIKO_DATABASE_URL` that defaults to `DATABASE_URL` with `search_path=portiko`.
  - Derive the rest from existing settings: `ISSUER = BASE_URL + "/id"`, `WEBAUTHN_RP_ID` and `WEBAUTHN_RP_ORIGINS` from the current values, `SERVICE_NAME` "ShortLinks".
  - Document the new settings in `docs/configuration.md` and `DEPLOYMENT.md`.
- At startup:
  1. Create the `portiko` schema if it's missing.
  2. Call `provider.Migrate`, then `provider.New`.
  3. Mount `p.Handler()` under `/id/` (per #0128).
  4. Call `RegisterClient` for ShortLinks itself. It needs `FirstParty: true`, the redirect URI `BASE_URL/auth/portiko/callback`, the post-logout URI `BASE_URL/`, and the back-channel URI `BASE_URL/auth/portiko/backchannel`. The client secret comes from config.
- **Schema isolation:** Portiko has its own `users` and `schema_migrations` tables, so it must not share the `public` schema with ShortLinks. Check that Portiko's migrator (`migrations/apply.go`) creates `schema_migrations` in the `search_path` schema and not in `public`. If it doesn't, fix that upstream or use a separate database.
- **Mail:** adapt `auth.SESMailer` to Portiko's `provider.Mailer` interface (one-time code + new-passkey notice), and pass it in `provider.Options.Mailer`. Without SES, use Portiko's stdout mailer.
- **Registration policy:** pass the #0129 hook, backed by `auth.Store.RegistrationsEnabled`.
- **Apache:** `ProxyPass /` already covers `/id/…`, so no vhost change is needed. Confirm Portiko's `TRUSTED_PROXIES` is set so its rate limits see real client IPs.
- `/health` stays ShortLinks'. Portiko's health check becomes `/id/health`.

## Expected behavior

With the switch on, `GET /id/.well-known/openid-configuration` returns an issuer of `BASE_URL/id`, and a person can enroll a passkey at `/id/signin` under the instance's existing RP ID. With it off, nothing changes.

## Notes

- Pin Portiko to a specific commit in `go.mod`. Its README says the API is still changing and nothing is tagged.
- Portiko currently uses a newer `go-webauthn` (v0.18.x) than ShortLinks (v0.17.4). Updating the module will bump ShortLinks' copy too, so run the existing auth tests.
- Tests: an integration test using `internal/testdb` that boots the provider under `/id` next to the ShortLinks mux, then checks that `/u/{key}` redirects and `/health` still work and that discovery serves under `/id`.

## Root cause

ShortLinks had no identity provider. Portiko could not be mounted under a path prefix (#0128), had no runtime registration hook (#0129) and no passkey management (#0137), so it could not share a host with ShortLinks. All three are now in Portiko main (31a79fe), so the embedding can be built.

## Fix

Everything is behind `PORTIKO_ENABLED`, which defaults to false. With it off, `idp.Mount` returns the handler it was given and touches neither the database nor the network, so behaviour is unchanged.

- **Dependency:** `github.com/Kolonnade/Portiko` pinned to commit `effd219d2fda` (pseudo-version `v0.0.0-20261119231241-effd219d2fda`), with no `replace`. This bumped `go-webauthn` to v0.18.1 and `pgx` to v5.11.0. The existing auth tests pass.
- **Wiring:** one call in `newPostgresHandler`, `idp.Mount(ctx, cfg, pool, handler)`, plus the matching closer. The mount wraps the finished mux and compares the raw request path (`/id` or `/id/...`), so every other request reaches the existing mux byte for byte. The MCP dispatcher still uses the bare mux. The provider's handler strips the prefix itself, so there is no `StripPrefix`.
- **Config (`internal/config`):** `PORTIKO_ENABLED`, `PORTIKO_CRYPTO_KEY` (64 hex or base64), `PORTIKO_CLIENT_SECRET` (at least 16 characters), `PORTIKO_DATABASE_URL` (default: `DATABASE_URL` with `search_path=portiko`), and `PORTIKO_TRUSTED_PROXIES`. When the switch is off, no other `PORTIKO_*` value is read, so a stray value can't stop an instance from booting. Enabling it is refused with `STORAGE=json`.
- **Provider settings (`internal/idp`):** issuer `BASE_URL/id`, `WEBAUTHN_RP_ID` and `WEBAUTHN_RP_ORIGIN` as given, service name "ShortLinks", and `DevInsecure` only for an `http://` BASE_URL.
- **Startup:** create the `portiko` schema if missing, `provider.Migrate`, `provider.New`, then `RegisterClient` for client `shortlinks`. It is first-party, with redirect `BASE_URL/auth/portiko/callback`, post-logout `BASE_URL/` and back-channel `BASE_URL/auth/portiko/backchannel`. The secret is `PORTIKO_CLIENT_SECRET`. Then `go p.Sweep(ctx)`.
- **Schema isolation:** checked in Portiko's migrator. `migrations.Apply` creates `schema_migrations` unqualified, so it lands in the `search_path` schema. No upstream change is needed. Verified live: `portiko.schema_migrations` exists beside `public.schema_migrations`, and the public version stays at 20.
- **Mail:** `idp.Mailer` adapts `auth.SESMailer` (new `SendText` method) to `provider.Mailer` (code, passkey-added and address-changed notices). Without SES credentials Portiko's stdout mailer is used.
- **Registration policy:** `Options.RegistrationPolicy` is backed by `auth.Store.RegistrationsEnabled`, read fresh on every call.
- **Docs:** `docs/configuration.md` (table rows and an "Embedded Portiko provider" section), `DEPLOYMENT.md` (section 3), and commented entries in `.env.example`.
- **Apache:** no vhost change. `ProxyPass /` already covers `/id/...`; the docs tell operators to set `PORTIKO_TRUSTED_PROXIES=127.0.0.1,::1`.

## Verification

`go build ./... && go vet ./...` print nothing and exit 0. `go test -count=1 ./...` against a fresh DB (`createdb`, `migrate up` to version 20, drop afterwards) passes in every package, including `cmd/shortlinks`, `internal/auth` and the new `internal/idp` and `internal/config` tests. Two runs saw `truncate: timeout: context deadline exceeded` in `internal/clicks` and `internal/handlers`, on a loaded machine. The re-runs of those packages passed.

New tests:
- `TestPortikoEmbeddedUnderID` boots the real mux with the switch off and then on. It checks that the schema is only created when on, that discovery gives issuer `http://localhost:8211/id`, that `/id/health` and `/id/signin` answer, and that `/health` and `/u/{key}` behave identically both ways.
- `internal/idp`: URL derivation and prefix routing.
- `internal/config`: switch off, on, missing key and secret, bad boolean, dev mode.

Binary run on port 8211 against a `migrate`-migrated DB (version 20):

```
PORTIKO_ENABLED=false
/health                                  200 application/json
/id/health                               200 text/html   (the existing SPA catch-all, the same as on main)
/id/.well-known/openid-configuration     200 text/html   (SPA)
portiko schema present: 0

PORTIKO_ENABLED=true
log: INFO portiko provider enabled issuer=http://localhost:8211/id
/health                                  200 application/json
/id/health                               200 application/json   {"status":"ok"}
/id/.well-known/openid-configuration     200 application/json   {"authorization_endpoint":"http://localhost:8211/id/oauth/authorize",...
/id/signin                               200 text/html          (Portiko's page)
/idx                                     200 text/html          (SPA, not the provider)
portiko.oauth_clients: shortlinks | first_party
```

A restart with the same key works. A restart with a different key fails with `cannot decrypt the private key`, which is the intended safeguard.

With the switch off nothing is served by the provider under `/id`. The SPA catch-all still answers `GET /id/...` with `index.html`, as it does for any unknown path today.

Not exercised: the SES mailer path, and an actual passkey ceremony in a browser (sign-in does not use the provider until #0132).

## Gotchas

- The `shortlinks` DB role must be able to `CREATE SCHEMA` (it owns its database, so it can), or the operator creates `portiko` by hand first.
- `PORTIKO_CRYPTO_KEY` must stay stable per instance, and each instance needs its own.
- Portiko's `Config` is hand-built, so its `Load` checks don't run. `DevInsecure` is derived from an `http://` BASE_URL.
- Portiko is not tagged, so the pin is a pseudo-version. `go get` needs `GOPRIVATE=github.com/Kolonnade` unless the repo becomes public.
- Several implementers are editing `main.go`. The change here is two small hunks (an import and the tail of `newPostgresHandler`).

## Review round 1

Opus asked for changes. All addressed in new commits, after merging main (two keep-both conflicts with #0178, in `internal/config/config.go` and `docs/configuration.md`).

- **A provider failure no longer takes the instance down.** `idp.Mount` now logs the error and serves `/id/*` as 503 (`Retry-After: 60`), and everything else goes to the existing mux. Schema creation, migrate, `New` and `RegisterClient` share a 30-second `StartupTimeout`. `TestPortikoEmbeddedUnderID` now ends by starting with a wrong crypto key and checking that `/id/health` gives 503 while `/health` gives 200 and `/u/{key}` still redirects. The binary shows the same: `badkey /health 200`, `/id/health 503`.
- **go-webauthn 0.18 rejected unsolicited extension outputs**, which would have broken passkey registration, login and recovery for clients that send `credProps`. `NewWebAuthn` now sets `ExtensionsUnsolicitedOutputPolicy: protocol.UnsolicitedOutputPolicyIgnore`. `TestFullCeremony_UnsolicitedExtensionOutputAccepted` (`internal/auth/extensions_test.go`) fails without the setting (`Client returned the "credProps" extension output which was not requested`) and passes with it. The same `webauthn.WebAuthn` serves all three ceremonies.
- **Nits:** `DeriveDatabaseURL` appends `search_path` to the raw query instead of re-encoding it; the mailer methods use a 30-second timeout; `DEPLOYMENT.md` notes the failure mode and the stricter pgx 5.11 `DATABASE_URL` encoding (percent-encode `@`, `:`, `/`, `?`, `#` in credentials).
- **Verification:** on a fresh DB (`migrate up` to version 21, dropped afterwards), `go build`, `go vet` and `go test -count=1 -p 1 ./...` all pass. The binary on port 8211 gives: off, `/health` 200 and `/id/*` the SPA's HTML; on, `/id/health` and discovery 200 JSON; wrong key, `/health` 200 and `/id/*` 503.
- **Note for the rollout:** go-webauthn 0.18 changed how session data is encoded, so a ceremony in flight across the deploy fails and must be retried. It is short-lived (about 5 minutes), so deploy outside busy sign-in windows.
