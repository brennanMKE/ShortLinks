# 0099 — Give links discrete UTM columns, a campaign FK, and a placement label

| | |
|---|---|
| **Status** | open |
| **Module** | db / links / campaigns / handlers / web |
| **Platform** | All |
| **First seen** | 2026-08-07 |

## Description

Adds campaign membership to `links` and, alongside it, **discrete UTM columns** — reversing the storage decision made in [#0048](0048.md), which bakes the five UTM params into `destination_url` and stores nothing separately.

That decision has two consequences this issue removes. First, the campaign view cannot label a link by channel without re-parsing the destination URL, which `docs/utm.md` correctly calls lossy. Second, the edit form cannot repopulate the UTM builder — a limitation #0048 documented at the time and accepted.

**Baking into `destination_url` continues.** The destination site's own analytics depends on those params arriving, so the composed URL is still what gets stored and served. The discrete columns are additive: they record what the builder was given, so the app can read its own data back without parsing.

## Data model

Migration `000011_links_campaign_and_utm`:

```
ALTER TABLE links
  ADD COLUMN campaign_id  BIGINT REFERENCES campaigns(id) ON DELETE SET NULL,
  ADD COLUMN utm_source   TEXT,
  ADD COLUMN utm_medium   TEXT,
  ADD COLUMN utm_campaign TEXT,
  ADD COLUMN utm_term     TEXT,
  ADD COLUMN utm_content  TEXT,
  ADD COLUMN placement    TEXT;

CREATE INDEX idx_links_campaign_id ON links(campaign_id) WHERE campaign_id IS NOT NULL;
```

`ON DELETE SET NULL` so deleting a campaign never deletes links.

`placement` is deliberately **not** `utm_content`. A physical poster location ("18th & Texas board") is operational metadata; `utm_content` is what gets sent to the destination site's analytics. They frequently differ, and collapsing them loses one or the other.

**Existing rows keep `NULL` in all seven columns. Do not backfill by parsing `destination_url`** — the parse is ambiguous wherever a link already carried its own `?utm_source=` from an external source, and a wrong guess is worse than a known gap.

## Scope / deliverables

- Migration `000011` up and down.
- **Populate the discrete columns on create** from the UTM builder, at the same point the composed URL is built. The two must agree: whatever gets baked is what gets stored.
- **Repopulate the builder on edit** from the discrete columns. This is the #0048 limitation being closed; state that in `docs/utm.md`.
- Selecting a campaign prefills the five builder fields from the campaign's `default_utm_*` values ([#0098](0098.md)). **Every prefilled value stays editable** — the campaign supplies a starting point, never a lock.
- Endpoints:

  | Method | Path | Purpose |
  |---|---|---|
  | `GET` | `/api/campaigns/{slug}/links` | Links in the campaign |
  | `POST` | `/api/campaigns/{slug}/links` | Assign existing links by key |
  | `DELETE` | `/api/campaigns/{slug}/links/{key}` | Unassign one link |

- Extend `POST /api/links` to accept an optional `campaign_id` or `campaign_slug`, the five discrete UTM fields, and `placement`. Extend the link detail response to include campaign name and slug.
- Audit actions `campaign.link_assigned`, `campaign.link_unassigned`.

## Acceptance criteria

- [ ] A link created through the builder has discrete columns that **exactly match** what was baked into `destination_url` — asserted by parsing the stored URL in the test and comparing field by field.
- [ ] Editing a link repopulates all five builder fields from the columns, and a link created before this migration (all-NULL columns) opens with empty fields rather than erroring.
- [ ] Deleting a campaign sets `campaign_id = NULL` on its links and deletes no link.
- [ ] A link belongs to **at most one campaign** — decided; enforced by the column, not a join table.
- [ ] **Ownership**: user A cannot assign user B's link into A's campaign, and cannot assign any link into B's campaign. Asserted with a second seeded account.
- [ ] Assigning an already-assigned link moves it (or is rejected with a clear error) — pick one, state which, and test it.
- [ ] Pre-existing links are untouched by the migration: `destination_url` byte-identical, all seven new columns NULL.
- [ ] `go build ./...`, `go vet ./...`, `gofmt -l` clean; `go test ./...` and `cd web && npm test` pass with new tests observed **by name**.

## Out of scope

- Backfilling UTM columns for existing links by parsing `destination_url`. Lossy; deliberately not done.
- Any change to how the redirect handler *records* UTM values on clicks — that fallback is [#0100](0100.md).
- Campaign stats and the campaign detail UI — [#0102](0102.md), [#0103](0103.md).
- Batch creation of many links at once — [#0105](0105.md).
