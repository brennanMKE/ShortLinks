## Description

Adds campaign membership to `links` and, alongside it, **discrete UTM columns** — reversing the storage decision made in [#0048](0048.md), which bakes the five UTM params into `destination_url` and stores nothing separately.

That decision has two consequences this issue removes. First, the campaign view cannot label a link by channel without re-parsing the destination URL, which `docs/utm.md` correctly calls lossy. Second, the edit form cannot repopulate the UTM builder — a limitation #0048 documented at the time and accepted.

**Baking into `destination_url` continues.** The destination site's own analytics depends on those params arriving, so the composed URL is still what gets stored and served. The discrete columns are additive: they record what the builder was given, so the app can read its own data back without parsing.

## Data model

Migration `000011_links_campaign_and_utm`:

```
ALTER TABLE links
  ADD COLUMN campaign_id  BIGINT REFERENCES campaigns(id) ON DELETE SET NULL,
  ADD COLUMN utm_source   TEXT,
  ADD COLUMN utm_medium   TEXT,
  ADD COLUMN utm_campaign TEXT,
  ADD COLUMN utm_term     TEXT,
  ADD COLUMN utm_content  TEXT,
  ADD COLUMN placement    TEXT;

CREATE INDEX idx_links_campaign_id ON links(campaign_id) WHERE campaign_id IS NOT NULL;
```

`ON DELETE SET NULL` so deleting a campaign never deletes links.

`placement` is deliberately **not** `utm_content`. A physical poster location ("18th & Texas board") is operational metadata; `utm_content` is what gets sent to the destination site's analytics. They frequently differ, and collapsing them loses one or the other.

**Existing rows keep `NULL` in all seven columns. Do not backfill by parsing `destination_url`** — the parse is ambiguous wherever a link already carried its own `?utm_source=` from an external source, and a wrong guess is worse than a known gap.

## Scope / deliverables

- Migration `000011` up and down.
- **Populate the discrete columns on create** from the UTM builder, at the same point the composed URL is built. The two must agree: whatever gets baked is what gets stored.
- **Repopulate the builder on edit** from the discrete columns. This is the #0048 limitation being closed; state that in `docs/utm.md`.
- Selecting a campaign prefills the five builder fields from the campaign's `default_utm_*` values ([#0098](0098.md)). **Every prefilled value stays editable** — the campaign supplies a starting point, never a lock.
- Endpoints:

  | Method | Path | Purpose |
  |---|---|---|
  | `GET` | `/api/campaigns/{slug}/links` | Links in the campaign |
  | `POST` | `/api/campaigns/{slug}/links` | Assign existing links by key |
  | `DELETE` | `/api/campaigns/{slug}/links/{key}` | Unassign one link |

- Extend `POST /api/links` to accept an optional `campaign_id` or `campaign_slug`, the five discrete UTM fields, and `placement`. Extend the link detail response to include campaign name and slug.
- Audit actions `campaign.link_assigned`, `campaign.link_unassigned`.

## Acceptance criteria

- [ ] A link created through the builder has discrete columns that **exactly match** what was baked into `destination_url` — asserted by parsing the stored URL in the test and comparing field by field.
- [ ] Editing a link repopulates all five builder fields from the columns, and a link created before this migration (all-NULL columns) opens with empty fields rather than erroring.
- [ ] Deleting a campaign sets `campaign_id = NULL` on its links and deletes no link.
- [ ] A link belongs to **at most one campaign** — decided; enforced by the column, not a join table.
- [ ] **Ownership**: user A cannot assign user B's link into A's campaign, and cannot assign any link into B's campaign. Asserted with a second seeded account.
- [ ] Assigning an already-assigned link moves it (or is rejected with a clear error) — pick one, state which, and test it.
- [ ] Pre-existing links are untouched by the migration: `destination_url` byte-identical, all seven new columns NULL.
- [ ] `go build ./...`, `go vet ./...`, `gofmt -l` clean; `go test ./...` and `cd web && npm test` pass with new tests observed **by name**.

## Root cause

Not a defect — a feature slice, plus the deliberate reversal of [#0048](0048.md)'s bake-only storage decision.

## Fix

Migration `000011` adds `campaign_id` (`ON DELETE SET NULL`), the five discrete `utm_*` columns, `placement`, and a partial index. Links now write the discrete columns alongside the composed `destination_url`; the edit form repopulates the builder from them; selecting a campaign prefills the five fields from its `default_utm_*` values, all editable. Three assign/unassign endpoints, `POST /api/links` extended, `campaign.link_assigned` / `campaign.link_unassigned` audit actions, and devstore twins throughout.

Three decisions #0098 left open:

- **`campaign.deleted` records the unassignment count.** Rather than accept the gap the FK creates, the delete transaction counts affected links first and stamps `unassigned_links_count` into the audit metadata. Transactionally consistent with what the FK is about to do, at the cost of one indexed read on an already-open transaction.
- **A NULL `default_utm_campaign` prefills as empty, with no slug fallback.** `default_utm_campaign` is pinned to the slug at creation, so NULL only occurs when a user deliberately cleared it; re-deriving would undo that. Documented in `docs/utm.md` and pinned by a named test.
- **Assign/unassign audit in-band via `WriteTx`**, consistent with #0098's campaigns store. The resulting invariant — *every mutation `campaigns.Store` performs is audited the same way* — is a cleaner line than `audit.go`'s current "ceremonies vs. handlers"; [#0108](0108.md) should rewrite that doc to it.

`CreateOrReactivateLink`'s duplicate/reactivate branches now **forward-merge** requested `campaign_id`/UTM/`placement` onto the matched row instead of silently discarding them — never clearing, only setting fields the request supplied.

Reviewed by Opus across three rounds → REQUEST CHANGES → REQUEST CHANGES (regression in the fix) → REQUEST CHANGES (comment only) → merged after the orchestrator corrected the comment directly.

**The central invariant was broken twice before it held.** The reviewer proved both by transpiling the real `utm.ts` with esbuild and driving the actual `startEdit`/`saveEdit` sequence, not by reading it:

1. *Round 1.* `composeUtmUrl` only ever **set** keys — it never deleted one. Clearing a UTM field on edit nulled the column while the baked URL kept shipping the param, so [#0100](0100.md) would have recorded `(none)` for a link demonstrably still sending `utm_source=email`.
2. *Round 2, introduced by the fix.* Deleting blank keys **unconditionally** stripped params the builder never owned. On create, a hand-typed `?utm_source=partner-newsletter` vanished. Worse: `LinkDetail.svelte:81` collapses the UTM section when a link's columns are all NULL — true of **every pre-migration link** — so a **title-only save** silently rewrote `destination_url`, with the preview that would reveal it hidden inside the collapsed section. That is precisely the population this issue's migration note protects.

The landed fix takes a third argument: `composeUtmUrl(base, params, previous)` deletes key `K` iff `previous[K]` was non-blank **and** `params[K]` is now blank. Create passes `emptyUtmParams()` (never deletes); edit passes a `startEdit()` snapshot (deletes exactly what the user cleared). All five harness cases now pass simultaneously, and the guard is mutation-pinned in **both** directions — reverting to unconditional delete fails 3 tests, disabling deletion entirely fails 9.

The snapshot's independence was verified under the **real Svelte 5 proxy**, not by reading: a `.svelte.ts` runes probe confirmed `editUtmParamsAtStart` is a distinct proxy target that does not mutate as the user types, and that aliasing it instead fails 3 of 5 probes.

## Gotchas

- **`composeUtmUrl` is a three-argument *reconciler*, not an appender.** Blank-field semantics depend entirely on `previous`. Passing `params` as `previous` silently disables clearing; passing an all-filled `previous` silently restores the destructive behavior. Neither fails a type check.
- **Fixing shared composition logic to repair one call site broke the other.** The edit-path fix regressed create, because both paths run the same function and only one of them has a builder that "owns" the params. When two callers disagree about what a function's input *means*, the meaning has to become an explicit argument.
- **A collapsed UI section hid the damage.** Both regressions rewrote `destination_url` invisibly, because the "Destination preview" lives inside the section that is collapsed exactly when the columns are empty. A preview that is hidden in precisely the state where it matters is not a safeguard.
- **A test that "encodes the bug" may also be the only guard for a different case.** The rewritten `keeps a base UTM param if empty` looked like a record of the defect; it was also the create-path guarantee, and replacing it removed the sole protection.
- **Wrong comments cost more than they look.** The unassign-ownership comment shipped a checkable, false mutation claim twice. Both times it read as verified. The accurate statement is narrower than it looks: removing *either* ownership gate alone leaves the test green, because the other still rejects and the status is 404 either way.
- **Forward-merge did not close the [#0105](0105.md) dedup trap**, despite an earlier commit message saying so. Two batch rows differing only in `placement` still compose to an identical `destination_url` and still collapse onto one row — the change turned "row 2's placement ignored" into "row 2 overwrites row 1's", which for a batch is worse.
