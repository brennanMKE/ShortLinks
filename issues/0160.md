## Description

`window.confirm()` guards revoke and delete in `Account.svelte:111,163`, `ApiTokens.svelte:132` and `Admin.svelte:247`, but deactivating a link (`Dashboard.svelte:298-314`, `LinkDetail.svelte:294-301`) and removing one from a campaign (`CampaignDetail.svelte:408`) happen on one click. Add a styled `ConfirmDialog` and use it consistently.

## Long Description

- `lib/ConfirmDialog.svelte` on `<dialog>`: a title, one sentence saying what happens, a named action button ("Revoke passkey", not "OK") and Cancel. Focus is trapped, Escape cancels and focus returns to the trigger.
- Replace every `window.confirm()`.
- Use it for link deactivate and remove-from-campaign until #0165 replaces those two with Undo toasts.

## Acceptance criteria

- Vitest covers focus return and Escape. No `confirm(` calls remain in `web/src` (checked with grep in a test or lint rule).
- Checked in the running app via `scripts/dev.sh` (:5173) and `scripts/sim.sh` (iOS Simulator), in light and dark, at desktop width and about 400px, with screenshots attached to the issue folder.
- `cd web && npm test && npm run build` passes.

## Root cause

Confirmation was ad hoc: four places used the native browser `confirm()` (Account revoke and sign-out-everywhere, ApiTokens revoke, Admin rule delete), while link deactivate (Links list, link detail) and remove-from-campaign fired on a single click. There was no shared, styled, accessible dialog.

## Fix

- New `web/src/lib/ConfirmDialog.svelte` on `<dialog>` with `showModal()`: title, one-sentence message, named action button (for example "Revoke passkey") and Cancel. Cancel is focused first, Escape and backdrop click cancel, Tab/Shift+Tab are trapped, focus returns to the trigger, and the action button is red when `destructive`.
- Pure logic in `web/src/lib/confirmDialog.ts` (`dialogKeyAction`, `trapTarget`, `restoreFocus`) so Vitest can cover it in the node environment.
- Each view keeps its existing handler name as the click entry point, which now only records the target. The old body became `perform*`, run on confirm. All native `confirm()` calls are gone; deactivate and remove now confirm (until #0165 swaps them for Undo toasts).
- `confirmDialog.test.ts` also greps all `web/src` sources for native confirm calls.

## Review round 1

- Merged `main` (merge commit) and resolved the four conflicts: LinksList (main's `window.confirm` in `handleDeactivate(link)` now opens ConfirmDialog; `<svelte:window onpaste>` kept), ApiTokens (`tokenRow` + AccountRowMenu kept, dialog added), Admin (NotFound/redirect wrapper kept), LinkDetail (Deactivate in the ⋯ menu; `<svelte:document>` kept). The no-`confirm(` grep test passes on the merged tree.
- Focus return: the trigger is captured in `$effect.pre`, before the menu item unmounts, from the `returnFocus` prop, else the focused element, else the last clicked control (Safari does not focus buttons on click; WebKit emulation caught this). LinkDetail passes its ⋯ button, and AccountRowMenu refocuses its ⋯ button before `onselect`.
- `onconfirm` may return a Promise. While pending both buttons are disabled and the confirm button shows busy text. A rejection keeps the dialog open with the error inside it, and success closes it. Every call site (LinksList, LinkDetail, CampaignDetail, Account passkey and sign-out-everywhere, ApiTokens, Admin) now throws a user-facing Error on non-401 failure instead of swallowing it.
- Backdrop: cancel only on a click whose pointer-down and click are both outside the dialog rect, so border clicks and drags that start inside do not cancel.
- Screenshots retaken on the merged UI (Chromium 1280 and 390, light and dark; WebKit iPhone 14 emulation, light and dark).

Re-verified: `npm run check` 0 errors, `npm test` 21 files / 561 tests pass, `npm run build` OK, `go build` and `go vet` OK.
