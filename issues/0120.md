# 0120 — No URL for the current view: reloading any screen drops the user back on the dashboard

| | |
|---|---|
| **Status** | open |
| **Module** | web |
| **Platform** | All |
| **First seen** | 2026-09-03 |

## Description

The SPA's current view lives only in a Svelte store, never in the URL, so the address bar reads `/` on every screen. Reloading a link detail page, a campaign, Account or Admin does not reload that screen — `App.svelte`'s `onMount` calls `GET /api/me` and unconditionally sets the view to `dashboard`. The browser's Back button leaves the app entirely instead of returning to the previous screen, and no screen can be bookmarked, linked to, or shared.

`web/src/lib/stores.ts`'s `currentView` is the only routing state, and `App.svelte:78-102` is the entire router: an `{#if}` chain over that store. Nothing reads or writes `location.hash`, and the only `history` calls in the codebase are the three `replaceState` calls that strip magic-link tokens from `/register/verify` and `/recover/verify` (`App.svelte:41`, `:52`, `RegisterVerify.svelte:119`, `RecoverVerify.svelte:119`).

## Steps to reproduce

1. Sign in and open any link's detail view, or a campaign detail view.
2. Note the address bar still shows `/`.
3. Reload the page.

## Expected behavior

The URL reflects the current screen (e.g. `#/links/solder0903`, `#/campaigns/spring-sale`), reloading returns to that same screen with the same record loaded, and Back/Forward move between screens within the app.

## Actual behavior

The address bar never changes. Reloading always lands on the dashboard. Back exits the app.

## Scope / deliverables

- Encode the current view in the URL hash, and restore it on boot. Hash routing (`#/…`) rather than `history.pushState` paths: the Go mux already serves `index.html` for every unmatched non-API path (`internal/handlers/static.go`), so path routing would work server-side, but the hash keeps the SPA's routing entirely client-side and cannot collide with the `/u/{key}` redirect namespace or a future server route.
- Cover every view in `App.svelte`'s chain: `dashboard`, `link-detail`, `campaigns`, `campaign-detail`, `account`, `admin`.
- Detail views need their record identity in the URL — the link key and the campaign slug — and must fetch by that identity on a cold load rather than depending on a store the previous screen populated.
- Handle `hashchange` so Back/Forward navigate within the app.
- Leave `/register/verify` and `/recover/verify` as real paths. They are landing targets for emailed links, they are matched on `pathname` before `/api/me` is called (`App.svelte:30-56`), and the existing token-stripping `replaceState` must keep working.
- An unknown or malformed hash falls back to the dashboard, not a blank screen.
- A hash for an authenticated view while unauthenticated still lands on login; ideally the intended view is restored after sign-in, but the redirect-back is optional and can be dropped if it complicates the login flow — say which was chosen.

## Acceptance criteria

- [ ] Every view sets a distinct hash, visible in the address bar.
- [ ] Reloading on each view returns to that view; link and campaign detail reload their own record.
- [ ] Back and Forward move between visited screens instead of leaving the app.
- [ ] A pasted link/campaign URL opens that record directly for a signed-in owner.
- [ ] `/register/verify?token=…` and `/recover/verify?token=…` behave exactly as they do today, token still stripped from the URL.
- [ ] An unknown hash lands on the dashboard.
- [ ] `cd web && npx tsc --noEmit` clean; `npm test` green; `npm run build` green.
- [ ] Verified by driving the running app in a browser (`scripts/dev.sh`), not by unit tests alone.

## Out of scope

- Adopting a routing library. The view set is small and fixed; a hand-rolled hash parser is the smaller change.
- Server-side path routing for SPA screens.
- Deep-linking into a specific tab or filter *within* a view.

## Notes

- No library needed: `svelte-spa-router` or similar would work, but the `{#if}` chain plus a parsed hash is a smaller diff and keeps `App.svelte` readable.
- `Dashboard.svelte`'s `onMount` opens the SSE stream and returns its unsubscribe as the cleanup; any router that swaps views must keep that mount/unmount pairing intact so the stream is not leaked or duplicated across navigations.
- `web/dist/index.html` is a committed placeholder; a verification `npm run build` overwrites it and it must be restored before committing (per `Issues.md`).
