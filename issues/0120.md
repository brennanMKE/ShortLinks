## Description

The SPA's current view lives only in a Svelte store, never in the URL, so the address bar reads `/` on every screen. Reloading a link detail page, a campaign, Account or Admin does not reload that screen — `App.svelte`'s `onMount` calls `GET /api/me` and unconditionally sets the view to `dashboard`. The browser's Back button leaves the app entirely instead of returning to the previous screen, and no screen can be bookmarked, linked to, or shared.

`web/src/lib/stores.ts`'s `currentView` is the only routing state, and `App.svelte:78-102` is the entire router: an `{#if}` chain over that store. Nothing reads or writes `location.hash`, and the only `history` calls in the codebase are the three `replaceState` calls that strip magic-link tokens from `/register/verify` and `/recover/verify` (`App.svelte:41`, `:52`, `RegisterVerify.svelte:119`, `RecoverVerify.svelte:119`).

**Spec:** implement per [`hash-routing.md`](0120/hash-routing.md) (attached). Where the spec and this issue disagreed, the spec wins, and the sections below have been updated to match it. The spec is generic, so the route table and notes below adjust it to the screens that actually exist.

## Steps to reproduce

1. Sign in and open any link's detail view, or a campaign detail view.
2. Note the address bar still shows `/`.
3. Reload the page.

## Expected behavior

The URL reflects the current screen (e.g. `#/links/solder0903`, `#/campaigns/spring-sale`), reloading returns to that same screen with the same record loaded, and Back/Forward move between screens within the app.

## Actual behavior

The address bar never changes. Reloading always lands on the dashboard. Back exits the app.

## Scope / deliverables

- Encode the current view in the URL hash, and restore it on boot. Hash routing (`#/…`) rather than `history.pushState` paths: the Go mux already serves `index.html` for every unmatched non-API path (`internal/handlers/static.go`), so path routing would work server-side, but the hash keeps the SPA's routing entirely client-side and cannot collide with the `/u/{key}` redirect namespace or a future server route.
- Cover every view in `App.svelte`'s chain: `dashboard`, `link-detail`, `campaigns`, `campaign-detail`, `account`, `admin`.
- Detail views need their record identity in the URL — the link key and the campaign slug — and must fetch by that identity on a cold load rather than depending on a store the previous screen populated.
- Handle `hashchange` so Back/Forward navigate within the app.
- Leave `/register/verify` and `/recover/verify` as real paths. They are landing targets for emailed links, they are matched on `pathname` before `/api/me` is called (`App.svelte:30-56`), and the existing token-stripping `replaceState` must keep working.
- An unknown or malformed hash renders a new `NotFound` screen. It must not be blank, crash, or loop.
- A hash for an authenticated view while unauthenticated `replace`s to the login route, **preserving the intended destination**, and the user is sent back there after signing in. This is required.
- Spec deliverables:
  1. `web/src/lib/router.svelte.ts`: Svelte 5 runes (`$state`), not `svelte/store`. `parse(hash)` returns `{ path, params, query, component }`, and a `getRoute()` accessor exposes it. `navigate(path)` sets `location.hash` and adds a history entry. `replace(path)` calls `location.replace('#' + path)` and adds none; use it for redirects and normalization.
  2. `web/src/lib/Link.svelte`: a real `<a href={'#' + to}>` with an `active` class (exact match for `/`, prefix match otherwise). All in-app navigation goes through it; never a `<button onclick>`.
  3. `web/src/lib/Router.svelte`: renders the component for the current route.
  4. One route table wired into `App.svelte`. Match in declaration order, `:param` matches one segment, strip trailing slashes except on `/`, `*` goes last. Query parameters after the hash are read with `URLSearchParams`, never `window.location.search`.
  5. Remove every other record of which screen is showing: the `currentView` store, the `{#if}` chain, and the `currentView.set(...)` calls in every view and `BatchCreateLinks.svelte`. Also remove `selectedLinkKey` and `selectedCampaignSlug`, which become route params. The hash is the only source of truth.
- On first load, normalize an empty hash with `replace('/')` before the first render, so the wrong screen never flashes.

## Root cause

The SPA had no router. Which screen was showing lived only in the `currentView` writable store, and the record a detail screen showed lived in `selectedLinkKey` / `selectedCampaignSlug`, set by the screen that navigated there. Nothing wrote the screen to the URL, and `App.svelte`'s boot always set `currentView` to `dashboard` after `GET /api/me`. So a reload threw away both the screen and its record, and Back had no in-app history entries to return to.

## Fix

The URL hash is now the only source of truth for the current screen.

- **`routing.ts`** holds the pure logic, with no DOM or Svelte:
  - parse a hash into path and query
  - match against the route table: declaration order, `:param` segments, trailing-slash stripping, `*` last
  - the `Link` active rule
  - the login redirect helpers: `loginPathWithRedirect`, and `redirectTargetFrom`, which accepts only in-app `/` paths and rejects `//` and `/\`
  - A segment whose percent-encoding is malformed counts as no match, so it lands on NotFound instead of throwing.
- **`hashRouter.svelte.ts`** is a Svelte 5 runes router. It exposes `getRoute()`, `navigate()`, which pushes a history entry, and `replace()`, which uses `location.replace` and adds none. It is updated on `hashchange`.
- **`Router.svelte`** renders the matched view. A `{#key}` on the path remounts detail views, so they fetch by route param.
- **`Link.svelte`** renders a real `<a href="#…">`.
- **`App.svelte`:**
  - declares the route table
  - normalizes an empty hash before first render
  - leaves `/register/verify` and `/recover/verify` as pathname landings, token stripping included
  - routes through `redirectIfNeeded()`, which runs before the app mounts and again from an effect for sessions that expire mid-visit:
    - signed out on a protected path → `#/login?redirect=…`
    - signed in on `#/login` → the redirect target
- **Views:** every `currentView.set(...)` and store-based selection is gone. Navigation goes through `Link` or `navigate`, and 401 handlers call `replace` to the login path with a redirect.
- **Dashboard rows:** they now contain a `Link`. The row click handler ignores clicks that come from inside an anchor.
- **Unchanged:** no Go changes, and `/u/{key}` is untouched.

It went through two review rounds:

## Gotchas

- **Case-only filename clashes break on macOS.** `lib/router.svelte.ts` and `lib/Router.svelte` import as `./router.svelte` and `./Router.svelte`, which collide on the default case-insensitive APFS. `tsc` and `svelte-check` resolved the wrong file, and on case-sensitive Linux it would have resolved differently. Renaming to `hashRouter.svelte.ts` removed the collision. Don't give a module and a component names that differ only in case.
- **Scoped CSS doesn't reach elements rendered by a child component.** A class passed into `Link` and styled in the parent's `<style>` silently does nothing, and a scoped rule for it reports "Unused CSS selector". Put shared classes in `app.css`. For one-off styles, use `:global()` on a class name unique to that element. `:global(.mono)` restyled every `.mono` in the app.
- **A `<tr onclick>` around an `<a>` catches the anchor's clicks.** Cmd-click opened the new tab and also navigated the current one. The row handler has to ignore events whose target is inside an `<a>`.
- **`decodeURIComponent` throws on malformed `%` sequences.** It threw inside the route computation, which left the app stuck on "Loading…". Catch the error per segment.
- **`URLSearchParams.get` already decodes.** Decoding again corrupts keys that contain `%2F`.
- **Dev auto-login (`internal/middleware/devauth.go`) can't be turned off.** A real signed-out session is unreachable under `scripts/dev.sh`. To test signed-out flows, mock `/api/me` as a 401 and fake `navigator.credentials` in Playwright.
- **`web/dist/index.html` on `main` is a real build, not the placeholder `Issues.md` describes.** It dates from before this issue. This branch never committed `web/dist/*`.
- **`scripts/sim.sh` can capture the page before it loads.** The first capture was blank white. If you get a blank capture, retake it before suspecting the app.
