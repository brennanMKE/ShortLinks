## Description

`GET /api/campaigns/{slug}/export.csv` — the campaign's per-link rollup as CSV, plus a download control in the campaign detail view.

The app deliberately does not do conversions, unique visitors, or geography. Export is the pressure valve: it lets the numbers leave for a spreadsheet where those questions can be answered against other data, without growing the app to cover them.

## Scope / deliverables

- Endpoint returning one row per link in the campaign: short key, short URL, title, destination, source, medium, content, placement, clicks in window, share of campaign total, created date.
- Honors the same `from` / `to` window parameters as the stats endpoint ([#0102](0102.md)), and the same defaults — including the campaign's own `starts_at`/`ends_at` when set.
- Bot-excluded by default, consistent with every other number in the campaign view ([#0101](0101.md)).
- Download control in the campaign detail view.
- `Content-Disposition` filename that identifies the campaign and window, so a folder of exports is not eight files called `export.csv`.

## Acceptance criteria

- [ ] Column headers are present and stable — this file gets opened in a spreadsheet and possibly parsed by something downstream.
- [ ] **Fields containing commas, quotes, or newlines are correctly escaped.** Titles, destinations with query strings, and free-text `placement` values will all contain them. Use `encoding/csv` rather than string concatenation.
- [ ] **A leading `=`, `+`, `-`, or `@` in any field is neutralized** so the CSV cannot execute as a formula when opened in Excel or Sheets. `placement` is free text and this app is single-admin, but the destination URL and title are not always self-authored — and the cost of getting this right is one helper function.
- [ ] Numbers export as numbers, not strings with thousands separators.
- [ ] Dates use a single documented format that spreadsheets parse unambiguously.
- [ ] The row totals reconcile with what the campaign detail view shows for the same window — an export that disagrees with the screen is worse than no export.
- [ ] An empty campaign exports headers and no rows, not an empty file or a 404.
- [ ] **Ownership**: user A cannot export user B's campaign.
- [ ] UTF-8 is handled correctly for non-ASCII titles and placements.
- [ ] `go build ./...`, `go vet ./...`, `gofmt -l` clean; `go test ./...` passes with new tests observed **by name**.

## Out of scope

- Exporting raw click rows. This is a per-link rollup; a raw export has real privacy weight since `clicks` stores IP addresses, and it deserves its own decision.
- Other formats — XLSX, JSON, PDF.
- Scheduled or emailed exports.
- Cross-campaign exports.

## Notes

- Reuse the stats queries from [#0102](0102.md) rather than writing a second aggregation path. Two implementations of "clicks in window" will drift, and the acceptance criterion above requires they agree.
- Streaming the response is not necessary at this scale, but the endpoint should not build the whole file in memory as a single concatenated string either — `encoding/csv` writing to the `ResponseWriter` is both simpler and correct.

## Root cause

Not a defect — the pressure valve that lets the numbers leave for a spreadsheet, so the app does not have to grow conversions, unique visitors, or geography.

## Fix

`GET /api/campaigns/{slug}/export.csv`, calling `clicks.StatsStore.CampaignRollup` — **the same call `/stats` makes, inside the same `REPEATABLE READ` transaction** — so there is no second aggregation path. `CampaignClicksByLink` is never touched. Written with `encoding/csv` to a buffer; the download control sits in the links-table **toolbar**, not the table, so it costs none of [#0106](0106.md)'s headroom.

**Decisions, all stated and tested:**

- **`share_of_listed_links_pct`**, matching [#0103](0103.md)'s on-screen column name exactly. An earlier name said "share of campaign total", which the denominator does not compute — #0103 prints a caveat below the table for precisely this reason, and a CSV cannot carry it.
- **The filename carries the INCLUSIVE window end**, matching the rendered caption. `window_to` is exclusive everywhere else.
- **An empty resolved window (`[X, X)`) is representable, not an error** — every assigned link still gets a row at `0`/`0`, matching the screen. Distinct from an empty campaign, which emits headers and no rows.
- **Formula injection neutralized** on text fields only; numeric columns are routed around the helper via `strconv.FormatInt`, so numbers stay numbers.
- **The UTF-8 BOM is kept** for Excel, with the real cost documented rather than hand-waved.
- **The in-memory buffer is a deliberate deviation** from the issue's own streaming note, documented as such — it buys a clean 500 over a truncated download.

## Verification

`go build`, `go vet` clean; `gofmt -l` shows only the two pre-existing files; `go test ./... -race` passes but for the pre-existing `internal/config` failure. `npm run check` 193 files / 0 errors; `npm test` **373 passing**. `shortlinks_test` left empty.

Verified live against real Postgres with a month of seeded activity: the exported numbers reconcile with the screen, the BOM is present in the downloaded bytes, an em-dash title round-trips, and `?from=2026-07-20&to=2026-07-25` (exclusive) produces `..._2026-07-20_to_2026-07-24.csv` — the inclusive end.

**Eight mutations, all killed**: header rename, `Round`→`Floor` (66 vs 67), BOM deletion, filename reverted to the raw exclusive bound, neutralization dropped on `destination_url` and again on `utm_source`, sort reverted to a key-ascending tiebreak, `.UTC()` dropped, and the sort deleted outright.

`subtractOneUTCDate`'s zero-day guard was swept rather than argued: every day from 1900-01-01 to 2200-01-01 against `to = from + n` for `n ∈ {-2,-1,0,1,2,31,365}`, **0 mismatches**.

## Gotchas

- **Five of this issue's tests read correctly and pinned nothing.** The header-stability test compared the output against the same variable the writer wrote from — renaming a column failed 0 tests. Rounding, the BOM, `.UTC()`, and the sort's existence were each unpinned because every fixture happened to divide exactly, or already be UTC, or already be sorted.
- **The last one survived two review rounds.** Deleting `sort.SliceStable` outright passed the entire `internal/handlers` package, because every fixture arrived pre-sorted and the DB-backed reconciliation test matches rows **by key rather than by position**. It is real work in production — `ListLinksForCampaign` returns `created_at DESC, id DESC`, so rows routinely arrive out of clicks order. Fixed by reordering one fixture; the assertions never changed.
- **A comment can launder a gap.** The tie test's comment ran two motivations together ("deleting the call entirely failed 0 other tests, **and** a key-ascending tiebreaker…") so it read as though it closed both. Its fixture is all-ties and cannot detect the deletion.
- **A column header can be wrong in a way review reads past.** `share_of_campaign_total_pct` was accurate-sounding, matched the arithmetic's *shape*, and was wrong: a link exported `100` when it was 67% of the campaign total.
- **A justification can be false while the decision is right.** The BOM comment claimed `encoding/csv`'s reader skips it. Measured: `header[0]` is `"﻿key"`, and `== "key"` is false — the file's own test helper strips it by hand. The BOM stays; the reasoning had to change.
- **The filename was the only place in the app exposing the raw exclusive bound**, and the only record of the window in the artifact — nothing inside the file names it.

## Downstream constraints

1. **`share_of_listed_links_pct` denominates against listed links, not the campaign total.** Any consumer computing campaign-level share must use `CampaignStats.ClickCount`.
2. **The export and the screen resolve the same default window** because neither passes explicit params. If a window picker is ever added to the view, it must be passed to the export too or the two will disagree.
3. **The window survives only in the filename.** Rename the file or paste it into a sheet and the window is gone. Worth revisiting if anything downstream parses these.
4. **A leading `-` in a text field exports as `'-`.** AC-mandated, but machine consumers must strip the apostrophe.
5. `ListLinksForCampaign` runs outside `CampaignRollup`'s transaction, so rows and counts come from different snapshots — the same property the screen already has.

## Follow-ups

- Under `scripts/dev.sh` (in-memory store, no stats provider) the filename degrades to `..._export__to_.csv`. **Structurally unreachable against Postgres**, where `stats.go` sets both bounds unconditionally. If fixed, drop the whole `_%s_to_%s` suffix when the window is empty, mirroring `windowLabel`'s `'recent activity'` fallback — do not special-case the empty string mid-format.
- `neutralizeFormulaField` covers the four AC characters; leading TAB and CR are also in common CSV-injection guidance.
- `campaignExportFilename`'s doc comment describes only the `windowFrom == windowTo` branch, not the `end == ""` fallback.
