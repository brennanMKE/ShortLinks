## Description

`GET /api/campaigns/{slug}/export.csv` — the campaign's per-link rollup as CSV, plus a download control in the campaign detail view.

The app deliberately does not do conversions, unique visitors, or geography. Export is the pressure valve: it lets the numbers leave for a spreadsheet where those questions can be answered against other data, without growing the app to cover them.

## Scope / deliverables

- Endpoint returning one row per link in the campaign: short key, short URL, title, destination, source, medium, content, placement, clicks in window, share of campaign total, created date.
- Honors the same `from` / `to` window parameters as the stats endpoint ([#0102](0102.md)), and the same defaults — including the campaign's own `starts_at`/`ends_at` when set.
- Bot-excluded by default, consistent with every other number in the campaign view ([#0101](0101.md)).
- Download control in the campaign detail view.
- `Content-Disposition` filename that identifies the campaign and window, so a folder of exports is not eight files called `export.csv`.

## Acceptance criteria

- [ ] Column headers are present and stable — this file gets opened in a spreadsheet and possibly parsed by something downstream.
- [ ] **Fields containing commas, quotes, or newlines are correctly escaped.** Titles, destinations with query strings, and free-text `placement` values will all contain them. Use `encoding/csv` rather than string concatenation.
- [ ] **A leading `=`, `+`, `-`, or `@` in any field is neutralized** so the CSV cannot execute as a formula when opened in Excel or Sheets. `placement` is free text and this app is single-admin, but the destination URL and title are not always self-authored — and the cost of getting this right is one helper function.
- [ ] Numbers export as numbers, not strings with thousands separators.
- [ ] Dates use a single documented format that spreadsheets parse unambiguously.
- [ ] The row totals reconcile with what the campaign detail view shows for the same window — an export that disagrees with the screen is worse than no export.
- [ ] An empty campaign exports headers and no rows, not an empty file or a 404.
- [ ] **Ownership**: user A cannot export user B's campaign.
- [ ] UTF-8 is handled correctly for non-ASCII titles and placements.
- [ ] `go build ./...`, `go vet ./...`, `gofmt -l` clean; `go test ./...` passes with new tests observed **by name**.

## Out of scope

- Exporting raw click rows. This is a per-link rollup; a raw export has real privacy weight since `clicks` stores IP addresses, and it deserves its own decision.
- Other formats — XLSX, JSON, PDF.
- Scheduled or emailed exports.
- Cross-campaign exports.

## Notes

- Reuse the stats queries from [#0102](0102.md) rather than writing a second aggregation path. Two implementations of "clicks in window" will drift, and the acceptance criterion above requires they agree.
- Streaming the response is not necessary at this scale, but the endpoint should not build the whole file in memory as a single concatenated string either — `encoding/csv` writing to the `ResponseWriter` is both simpler and correct.
