# 0126 — Umbrella: ShortLinks becomes its own Portiko identity provider and drops its custom passkey code

| | |
|---|---|
| **Status** | open |
| **Module** | auth / handlers / web / db / infra |
| **Platform** | All |
| **Phase** | 15 — Portiko cutover and cleanup |
| **First seen** | 2026-11-12 |

## Description

Replace ShortLinks' custom passkey code (`internal/auth` sign-up, login and recovery, the credentials API, and the Svelte sign-up/recovery views) with [Portiko](https://github.com/Kolonnade/Portiko). Each instance **becomes its own identity provider**: the Portiko provider runs inside the ShortLinks binary on the instance's own host, and ShortLinks signs in through Portiko's `rp` library. This is the umbrella issue. It doesn't ship code itself, and it closes when its sub-issues do.

## Long Description

**Why.** Portiko was ported from ShortLinks' passkey code (see `internal/passkey/webauthn.go:4` and `internal/accounts/service.go:4` in Portiko) and has since moved past it. It is built on `zitadel/oidc`, stores the WebAuthn user handle, supports several signed-in accounts and back-channel logout, and runs OpenID conformance as a release gate. Keeping two copies of the same passkey code means fixing every bug twice.

**Decided (Brennan, 2026-11-12): the website itself becomes the IdP.** Each instance (sstools, ocsf, dustalmanac) runs the provider in-process. There is no shared accounts service and no separate service to deploy. The consequences:

- **The passkey domain doesn't change.** Portiko is configured with the instance's existing `WEBAUTHN_RP_ID` (e.g. `go.sstools.co`), so existing passkeys still work. They can be **imported** instead of re-enrolled (#0131), provided the user handle has been captured (#0127).
- **Each instance's accounts stay separate.** There is no single sign-in across instances, which matches how they're run today.
- **Same deploy flow.** It's still one binary. The provider gets its own Postgres schema in the existing database, and Apache and DNS are unchanged.
- **Permissions stay in ShortLinks.** Portiko answers *who is this person* and never *what may they do*. `users.is_admin`, `users.active`, the admin pages, the audit log and API tokens all stay in ShortLinks.

**What Portiko lacks today.** These are tracked here; the work happens in `Kolonnade/Portiko`:

- It can't be mounted under a path prefix. Its `/`, `/health` and `/u/{n}/` routes collide with ShortLinks' routes (#0128).
- Registration is a static `REGISTRATION` environment setting, with no hook for ShortLinks' runtime `registrations_enabled` toggle or its first-user-becomes-admin rule (#0129).
- There's no way to list, rename or revoke passkeys, which ShortLinks has today at `/account/credentials` (#0137).

## Acceptance criteria (umbrella)

- Every instance signs in through its embedded Portiko provider. An existing user signs in with the **same passkey** they used before, without re-enrolling, if they signed in at least once after #0127 shipped.
- Users whose handle wasn't captured have a documented path back in through Portiko's recovery (an emailed code, then a new passkey). No account is lost.
- Admin, deactivation, the audit log, API tokens and the #0125 signed-out home page behave as before.
- `internal/auth` no longer contains passkey ceremony code, and the old auth tables are dropped (#0136).
- `go test ./...` and `cd web && npm test && npm run build` pass.

## Effect on other open issues

The E2E issues that test today's sign-in screens will be testing code that this work replaces: [#0081](0081.md) (authentication), [#0086](0086.md) (passkey management), [#0087](0087.md) (registration gate) and [#0088](0088.md) (user management). [#0045](0045.md) (SES delivery of magic links) changes too: Portiko sends one-time codes, not magic links. Re-scope these before working them, or schedule this work ahead of phases 5–10.

## Out of scope

- A shared provider across instances, or single sign-on with CommunityPlatform sites.
- Native apps (Portiko supports them, but ShortLinks has none).
- Several signed-in accounts in the ShortLinks UI. The `rp` library signs in one account per browser session, which is today's model.
