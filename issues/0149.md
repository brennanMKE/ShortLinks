## Description

Embed an MCP server in the binary at `/mcp`, using the official Go SDK (`github.com/modelcontextprotocol/go-sdk`) over Streamable HTTP. Authenticate with the same bearer tokens as the REST API, and expose link and campaign tools that dispatch in-process to the existing REST handlers.

## Long Description

**Package:** `internal/mcpserver`. Route: `mux.Handle("/mcp", requireAPI(mcpHandler))` for POST, GET and DELETE as the transport requires. Cookie sessions are rejected (403 `api_token_required`): MCP is for tokens.

**Read-only tokens.** `requireAPI` blocks non-safe methods for read-only tokens (`internal/middleware/apitoken.go:94`), and MCP uses POST for everything. Exempt `/mcp` from that method check and enforce read-only per tool instead: a read-only session's `tools/list` omits write tools, and calling one anyway returns a tool error. The in-process dispatch goes back through the same middleware with the caller's identity, so a write by a read-only token is still refused by the REST layer as a second guard.

**In-process dispatch.** One helper, `call(ctx, method, path, query, body) (status, json)`, builds an `*http.Request` with the caller's auth context and serves it through the API mux. Tools never reimplement validation, the URL filter, audit writes or cache eviction. Map REST errors to MCP tool errors with the REST error code and message, so the agent can correct itself.

Tool results return the REST JSON as structured content plus a short text summary ("Created go.example.com/u/k3Fz9a → https://…"). Every short URL is returned in full, using the instance's `BASE_URL`.

**Audit.** Tool calls appear in the audit log through the REST handlers, with the token's name, as API calls do today. Add `via: "mcp"` to the audit metadata so the source is visible.

**Parity test.** A test lists the `/api` routes and fails unless each one maps to an MCP tool or is on an explicit, commented exclusion list (QR SVG, the QR zip, CSV export, SSE events, OpenAPI).

## Acceptance criteria

- `/mcp` passes an MCP client round trip in Go tests using the SDK's client over an `httptest.Server`: initialize, `tools/list`, and a call of every tool against the test DB.
- A read-only token sees only read tools, and a forced write call fails at both layers (tested).
- Cookie sessions and missing or revoked tokens are rejected (tested).
- The parity test passes.
- `go test ./...` passes, and `go build ./cmd/shortlinks` still produces one binary.
