## Description

Embed an MCP server in the binary at `/mcp`, using the official Go SDK (`github.com/modelcontextprotocol/go-sdk`) over Streamable HTTP. Authenticate with the same bearer tokens as the REST API, and expose link and campaign tools that dispatch in-process to the existing REST handlers.

## Long Description

**Package:** `internal/mcpserver`. Route: `mux.Handle("/mcp", requireAPI(mcpHandler))` for POST, GET and DELETE as the transport requires. Cookie sessions are rejected (403 `api_token_required`): MCP is for tokens.

**Read-only tokens.** `requireAPI` blocks non-safe methods for read-only tokens (`internal/middleware/apitoken.go:94`), and MCP uses POST for everything. Exempt `/mcp` from that method check and enforce read-only per tool instead: a read-only session's `tools/list` omits write tools, and calling one anyway returns a tool error. The in-process dispatch goes back through the same middleware with the caller's identity, so a write by a read-only token is still refused by the REST layer as a second guard.

**In-process dispatch.** One helper, `call(ctx, method, path, query, body) (status, json)`, builds an `*http.Request` with the caller's auth context and serves it through the API mux. Tools never reimplement validation, the URL filter, audit writes or cache eviction. Map REST errors to MCP tool errors with the REST error code and message, so the agent can correct itself.

## Root cause

ShortLinks had a REST API but no MCP server. To use it, an AI agent needed custom HTTP glue, and nothing exposed the API as tools.

## Fix

Added `internal/mcpserver`, built on the official Go SDK `github.com/modelcontextprotocol/go-sdk` v1.8.0 (pinned).

**Transport and auth**
- `/mcp` serves streamable HTTP in stateless mode, with JSON responses.
- It is registered as `POST`, `GET` and `DELETE /mcp`. GET and DELETE return 405. A bare `/mcp` pattern would conflict with the SPA catch-all.
- Requests pass through `requireAPI`. Cookie sessions get 403 `api_token_required`. Missing, bogus or revoked tokens get 401.
- A server is built for each request from the caller's identity, so no session can outlive a revoked token.

**Read-only tokens**
- `isMCPTransport` exempts exactly `POST /mcp` from the method-based read-only check.
- Write tools are filtered out of a read-only token's `tools/list`.
- A forced write call returns a tool error. If the tool guard is bypassed, the REST layer still refuses with 403 `api_token_read_only`.

**Dispatch to the REST handlers**
- `Caller.call` builds an `*http.Request` carrying the caller's own `Authorization` header and serves it through the whole mux, so `requireAPI` re-authenticates.
- Only `/api` paths are targeted. Keys and slugs are path-escaped as a single segment. `.`, `..` and anything containing `/` are refused, and any inner 3xx becomes `invalid_request`.
- Inner calls skip only the per-token rate limiter, using an unexported `middleware.WithInternalDispatch` context flag.
- REST errors map to tool errors that carry the status, code and message.

**Tools**
- 17 tools: `whoami`, `list_links`, `get_link`, `get_link_qr` (PNG image content), `create_link`, `update_link`, `deactivate_link`, `reactivate_link`, `list_campaigns`, `get_campaign`, `list_campaign_links`, `create_campaign`, `update_campaign`, `delete_campaign`, `batch_create_campaign_links`, `assign_links_to_campaign`, `remove_link_from_campaign`.
- Each has typed, described inputs and the issue's annotations.
- `Idempotency-Key` is passed through for creates.
- Every link object gets a full `short_url`.
- Results carry a summary, the JSON as text (most clients only show the model `content`), and structured content.

**Audit**
- `audit.WithVia(ctx, "mcp")` marks entries made through MCP. They stay attributed to the token's id and name.

**Hardening** (review fixes, `a970fc1`)
- JSON-RPC batch arrays are rejected with 400. Without this, one POST could run many tool calls for a single rate-limit charge.
- Bodies are capped at 256 KiB (413 above that), and the SDK limit matches.
- Panics in tool bodies or dispatched handlers become `internal_error` tool errors. The SDK runs tools in bare goroutines, so an unrecovered panic would kill the process.
- `http.NewCrossOriginProtection()` wraps `/mcp`.
- `DisableLocalhostProtection` stays set: Apache proxies from loopback, and the endpoint is bearer-only. The reason is in a code comment.

**Routing refactor**
- `mountAndServe` became `buildMux` with a recording router.
- `newPostgresHandler` is split out so tests can serve the real mux.
- The route set is identical except for the three `/mcp` patterns. The reviewer compared them.
- `/mcp` is also mounted in dev mode.

**Parity test**
- It fails unless each `/api` route maps to a tool or is in `mcpserver.Excluded` with a reason.
- Excluded: QR SVG, QR zip, CSV export, SSE events, `/api/reports*` (deferred to #0150), `GET /api/campaigns/{slug}/stats`, `DELETE /api/links/{key}` (same as `deactivate_link`), `/api/public/home`, and `/api/openapi.yaml` (pre-listed for #0148).

## Verification

Run against `shortlinks_test_0139`.

- `go build ./...` and `go vet ./...` are clean, and `go build ./cmd/shortlinks` still produces one binary.
- `go test ./... -count=1` passes in every package except the known `internal/config` `TestLoad_DefaultsApplied` (#0116).
- `go test ./internal/mcpserver/ ./cmd/shortlinks/ -race` passes. The SDK client runs over `httptest` against the real production mux (`TestMCPRealMux`) and covers:
  - initialize, `tools/list`, and a call to all 17 tools, including the QR PNG as image content;
  - read-only filtering, with both layers refusing a write;
  - cookie, missing, bogus and revoked tokens rejected;
  - an idempotency replay, and a 422 tool error on key reuse;
  - audit rows with `via: "mcp"`;
  - the parity test (confirmed to fail when an exclusion is removed);
  - batch 400, oversize 413, both panic cases, and dot keys.
- Manual smoke: the built binary in dev mode answered `initialize`, `tools/list` (17 tools) and `create_link` over curl.
- `cd web && npm test`: 442 passed.

The Opus reviewer requested changes (batch rate-limit bypass, unrecovered panics), then re-reviewed `a970fc1` and approved. It also probed path injection and BOM or whitespace batch smuggling; both were refused.

## Gotchas

- **Adding report tools (#0150).** Write a `Registrar` that calls `mcpserver.AddTool(b, Spec{…}, fn)`, append it to `registrars` in `tools.go`, and remove the `/api/reports*` entries from `Excluded`.
- **Dev mode.** Dev auto-login makes a header-less request look like a cookie session, so it gets 403 rather than 401.
- **No recover around `tools/list` filtering or the SDK's own code.** Only an SDK bug could crash there.
- **Not yet tried with a real client.** No real Claude Code client has connected yet; that is #0151.
- **Deploy.** Apache uses `ProxyPreserveHost On`, so the cross-origin check sees the right Host. Check during #0151 that the vhosts proxy `/mcp` without buffering.
