# 0182 — Links have no external id, so a client can't find its link again without storing the key or matching titles

| | |
|---|---|
| **Status** | in-progress |
| **Module** | links / handlers / db |
| **Platform** | All |
| **Phase** | 21 — Invitation links (CoupleDozen) |
| **First seen** | 2026-11-18 |

## Description

CommunityPlatform stores nothing on its side. To deactivate an invitation's link when the invitation is withdrawn, it would have to search by title. Add an optional client-supplied `external_id`, unique per user, and a way to look a link up by it.

## Long Description

Requested by the CommunityPlatform session on 2026-11-18, for CoupleDozen invitation links on the new go.coupledozen.com instance. Their plan is in CommunityPlatform `docs/Plans/2026-11-ShortInviteLinks.md`, with issues GroupsWeb #0274/#0275 and CommunityBackend #0108. Each invitation link carries a secret token that grants entry to a family group, so these links need more protection than marketing links.

**Wanted:**
- **`external_id`:** optional, up to 128 printable ASCII characters. It's set on create or batch create rows, and can be changed with PATCH (null clears it).
- **Uniqueness:** unique per user, enforced with a partial unique index where it's not null. A conflict on create returns 409 `external_id_taken`, with the existing link's key.
- **Lookup:**
  - `GET /api/links?external_id=<id>` returns the matching link or an empty list;
  - plus a shortcut, `GET /api/links/by-external-id/{id}`, which returns 404 when there's no match.
  
  Both go in the MCP tools and OpenAPI later.
- **Dedup interaction:** today, creating a link to a destination you already shortened returns the existing link with `duplicate: true`. When `external_id` is given and the destination is a duplicate with a **different** `external_id`, create a new link instead of merging. Two invitations must never share a link. Document this.
- **Idempotency** (#0147) is unchanged. The two features are independent.

## Root cause

Links had no client-owned identifier, so a client that stores nothing (CommunityPlatform) could only find its link again by title. Deduplication also keyed only on `(user_id, destination_url)`, which would have merged two invitations to the same page into one link.

## Fix

- Migration `000025_links_external_id` (renumbered from 000024 at the coordinator's request, since #0131 takes 000024): nullable `links.external_id TEXT` with a `links_external_id_format` CHECK (1 to 128 printable ASCII), and the partial unique index `idx_links_user_external_id (user_id, external_id) WHERE external_id IS NOT NULL`. Additive; the column has no default so no rows are rewritten. The index is a plain `CREATE UNIQUE INDEX`, not `CONCURRENTLY`, because golang-migrate runs the file as one transaction and the column add must share the file (migration numbers 000026/27 belong to #0180/#0183). The index is empty when built, so the lock lasts one scan of `links`. Down migration drops index and column.
- `internal/links`: `Link.ExternalID`, `NewLink.ExternalID`, `LinkUpdate.ExternalID`, `ListOptions.ExternalID`, `GetLinkByExternalID`, `ValidExternalID`, and `*ExternalIDTakenError` (carries the holder's key; matches `ErrExternalIDTaken`). The dedup lookup adds `external_id IS NOT DISTINCT FROM`, so different ids never merge and a plain create never returns an id-bearing link. Denied rows never claim an id.
- Handlers: `external_id` on create, batch rows and PATCH (null or "" clears); 409 `{"error":"external_id_taken","external_id","key"}`; `?external_id=` list filter; `GET /api/links/by-external-id/{id}`.
- Routing: the new literal route conflicts with `GET /api/links/{key}/qr.svg|qr.png` in Go's mux, so those two now go through one `GET /api/links/{key}/{file}` route (`LinksHandler.File`). `router.HandleAs` still records the two real routes for the drift and MCP parity tests. The key `by-external-id` is reserved.
- `internal/reports/public.go`: the public top-links query requires `l.external_id IS NULL` (the `TODO(#0182)`); clicks still count in totals.
- OpenAPI spec, MCP (`external_id` on `create_link`, `update_link`, `list_links`, batch rows; new `get_link_by_external_id`), dev store, and docs (`docs/links.md`, `docs/database.md`, `docs/mcp.md`).
- No UI change, so no screenshots or simulator run apply.

## Review round 1

Merged `main` (no conflicts; migration 000025 kept after #0131's 000024). Changes:

- PATCH refuses a non-empty `external_id` on a link denied by the URL filter (`400`); clearing is allowed. Enforced in `links.Store.UpdateLink` and the dev store (`ErrLinkDenied`), mapped in the handler.
- Decision for re-creating by the same destination and `external_id`: an inactive link is **not** reactivated. The existing link is returned unchanged with `duplicate: true` and `active: false` (201, nothing written, no SSE). Without an `external_id` the old reactivation stays. Documented in `docs/links.md` and the OpenAPI create description. Replays under one `Idempotency-Key` are unaffected.
- Migration comment rewritten (it overstated the lock behavior) and `SET lock_timeout = '5s'` / `RESET` added.
- `File` dispatcher 404 uses `writeError` (JSON).
- Batch `duplicateKey` includes `external_id`.
- A failed holder lookup gives a 409 without a `key` field.
- The `.`/`..` path limitation is now in the OpenAPI path parameter too.
- Tests: `links_external_id_review_test.go` (inactive not revived, denied PATCH, batch rows differing only in id) and `internal/devstore/external_id_test.go`.

Verification: fresh DB `shortlinks_0182r`, `go test -count=1 -p 1 ./...` all ok, `go vet ./...` clean.
