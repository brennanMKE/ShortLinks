# 0085 — E2E: UTM builder & analytics charts

| | |
|---|---|
| **Status** | open |
| **Module** | web / links / clicks |
| **Platform** | All |
| **First seen** | 2026-07-02 |

## Description

Automate the UTM-parameter builder on the create form and the analytics chart
rendering (`ClicksChart`, `UTMBarChart`). Depends on [#0080](0080.md); part of
[#0079](0079.md).

## Scope / scenarios to automate

- **UTM builder panel.** Expand the "Campaign / UTM parameters" panel on the
  Dashboard create form, fill source/medium/campaign/term/content, and assert the
  resulting stored/previewed URL contains the expected `utm_*` query params.
- **UTM persistence.** A link created with UTM params shows them on LinkDetail and
  applies them on redirect (cross-check with #0084).
- **Clicks chart.** After generating clicks on a link (via redirects), the
  `ClicksChart` on LinkDetail (and/or Dashboard) renders with data points
  reflecting the click activity. Assert the chart is present and non-empty.
- **UTM breakdown chart.** `UTMBarChart` renders a breakdown by UTM dimension for
  links/clicks that carry UTM data. Assert bars/segments appear for the seeded
  activity.
- **Empty analytics state.** A link with zero clicks shows the chart's empty
  state rather than erroring.

## Preconditions

- Fresh-seed dev server; ability to create UTM-tagged links and drive redirects to
  produce click data. Page objects: `DashboardPage` (UTM panel), `LinkDetailPage`
  (charts).

## Acceptance criteria

- [ ] UTM panel produces the correct `utm_*` params (asserted on the URL).
- [ ] ClicksChart renders with data after clicks are generated.
- [ ] UTMBarChart renders a breakdown for UTM-tagged activity.
- [ ] Zero-click empty state asserted.

## Out of scope

- UTM passthrough at redirect time — #0084 (assert here only that the builder
  writes them).
- Chart pixel/visual regression — assert presence/structure and data, not exact
  pixels.

## Notes

- The charts are custom SVG/DOM (`charts.ts`, `ClicksChart.svelte`,
  `UTMBarChart.svelte`) with existing unit tests (`charts.test.ts`, `utm.test.ts`).
  E2e should assert the *rendered* chart reflects real end-to-end data, not
  re-test the pure chart math.
