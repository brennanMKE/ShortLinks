# 0117 — The short-link display base is hard-coded to `go.sstools.co` instead of coming from `BASE_URL`

| | |
|---|---|
| **Status** | open |
| **Module** | web / handlers / config |
| **Platform** | All |
| **First seen** | 2026-08-25 |

## Description

Every short URL the product shows, copies, exports, or encodes into a QR code is built from a **hard-coded** `https://go.sstools.co`, not from the deployment's `BASE_URL`. There are two copies of the constant, one per language, and a comment on each telling the reader to keep them in sync by hand:

- `web/src/lib/links.ts:19` — `export const SHORT_URL_BASE = 'https://go.sstools.co';`
- `internal/qr/qr.go:59` — `const ShortURLBase = "https://go.sstools.co"`

`BASE_URL` already exists, is already required by `internal/config` (`config.go:117`), and is already documented in `DEPLOYMENT.md:153` as "Public base URL". It is simply not used for the one thing its name describes. Today it only feeds auth email links (`internal/auth/mailer.go`).

The consequence is that this codebase cannot be deployed under any other domain without editing Go and TypeScript source. `DEPLOYMENT.md:11` tells an operator to "substitute your domain wherever `go.sstools.co` appears and set `BASE_URL`" — the second half of that sentence does nothing for short links, and the first half is a source edit, not configuration.

## Why this matters

- **It is a source edit masquerading as configuration.** An operator who sets `BASE_URL` correctly still gets `go.sstools.co` on every copy button, CSV export, and QR code.
- **Two hand-synced constants across a language boundary will drift.** `qr.go`'s own comment says so: "Keep this in sync with links.ts's SHORT_URL_BASE by hand — there is no shared source of truth across the Go/TS boundary." A QR code that disagrees with the short URL printed next to it is a silent, on-paper failure.
- **Dev cannot exercise the real path.** `links.ts`'s comment argues the production base is deliberate because "a copied localhost link is useless to share". That is backwards: in dev `BASE_URL` *is* localhost, and a localhost link is exactly what works on the machine running the dev server. Today a dev-mode copy button hands you a URL that resolves to production.

## Scope / deliverables

- Serve the configured `BASE_URL` to the SPA rather than compiling a domain into it. `GET /api/me` is the natural carrier — the SPA already calls it on boot, and short URLs are only ever displayed to an authenticated user.
- Make `qr.ShortURL` take the base as an argument, sourced from `config.Config.BaseURL`, so the QR payload and the displayed URL are derived from one value.
- Normalize a trailing slash on `BASE_URL` so `https://x.co/` and `https://x.co` produce the same short URL.
- Delete both hard-coded constants and the "keep in sync by hand" comments they carry.
- Update `DEPLOYMENT.md` so the domain-substitution instruction reflects what is actually configurable.

## Acceptance criteria

- [ ] No occurrence of `go.sstools.co` remains in `web/src/**` or `internal/**` outside of documentation and test fixtures.
- [ ] With `BASE_URL=https://example.test`, the dashboard's copy button, `LinkDetail`'s share URL, the campaign CSV export's `ShortURL` column, and the QR payload all produce `https://example.test/u/{key}`.
- [ ] `BASE_URL=https://example.test/` (trailing slash) produces the same result — no `//u/`.
- [ ] `go build ./... && go test ./...` green; `cd web && npm run build` and `npm test` green.
- [ ] `gofmt -l` clean for any file touched.

## Out of scope

- `cmd/shortlinks/seed.go`'s `seedLinkPrefix` — that is fixture data for seeded demo rows, and its doc comment states the fixed value is deliberate. Worth revisiting, not here.
- `WEBAUTHN_RP_ID` / `WEBAUTHN_RP_ORIGIN`, which are separately configured and already read from the environment.
- Multi-domain support (the PRD's "Custom domains" future item at `PRD.md:826`). This issue is one configured base, not N.

## Notes

- `internal/config` already requires `BASE_URL` unconditionally, so no new validation or fallback is needed — the value is guaranteed non-empty at startup.
- The SPA reads the base once at boot; `shortUrl()` must therefore resolve it at call time rather than capturing a module-load-time constant.
