## Description

Brennan wants AI agents to use an API key to do everything he can do in the web UI: create links and campaigns, manage them, and ask questions about link activity. The REST API already covers link and campaign CRUD with `slk_` bearer tokens ([docs/using-api-tokens.md](../docs/using-api-tokens.md)), but there are no reports, link search, reactivation, retry safety or machine-readable spec, and there is no MCP server. This umbrella tracks the plan. It ships no code itself.

## Long Description

**Decided (Brennan, 2026-11-18):** a full REST API plus an MCP server, both authenticated with the existing API tokens. A set of **reports computed in Go** gives agents fast, ready-made answers instead of making them page through links and add up clicks.

### Architecture

```
agent ──Bearer slk_…──▶ /mcp  (Streamable HTTP, internal/mcpserver)
                         │  tools dispatch in-process to ▼
agent / script ─Bearer─▶ /api/...  REST handlers ──▶ links, campaigns, clicks stores
                         /api/reports/{name}  ──▶ internal/reports (SQL aggregations)
SPA (cookie session) ──▶ same /api routes
```

- **One code path.** MCP tools call the same REST handlers in-process (a loopback dispatcher that builds an `*http.Request` carrying the caller's auth context and calls the mux). Validation, the URL filter, cache eviction, audit entries and read-only enforcement then behave the same for MCP calls as for HTTP. Report tools call `internal/reports` directly.
- **Reports are a Go package** (`internal/reports`) with one shared parameter model (window, time zone, comparison period, campaign and UTM filters). The REST API serves them at `GET /api/reports/{name}`, the MCP server exposes one typed tool per report, and the redesigned SPA (#0152) reads its Overview and campaign analytics from the same reports.
- **Content grouping moves to Go.** The design put it in a TypeScript module. Agents need it too, so it lives in `internal/reports` (#0140) and the SPA consumes it.

### MCP tools (all at `/mcp`)

| Group | Tools | Read-only token |
|---|---|---|
| Identity | `whoami` | ✓ |
| Links | `list_links`, `get_link`, `get_link_qr` (PNG image content) | ✓ |
| Links (write) | `create_link`, `update_link`, `deactivate_link`, `reactivate_link` | hidden |
| Campaigns | `list_campaigns`, `get_campaign`, `list_campaign_links` | ✓ |
| Campaigns (write) | `create_campaign`, `update_campaign`, `delete_campaign`, `batch_create_campaign_links`, `assign_links_to_campaign`, `remove_link_from_campaign` | hidden |
| Reports | `list_reports`, `get_overview`, `get_top_content`, `get_top_links`, `get_breakdown`, `get_timeseries`, `get_movers`, `get_idle_links`, `compare_campaigns`, `get_campaign_performance`, `get_link_performance` | ✓ |
| Prompts | `weekly_summary`, `campaign_report`, `whats_working` | ✓ |

Each tool carries MCP annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`). `delete_campaign` and `deactivate_link` are marked destructive.

### Out of scope (browser-only by design)

Admin pages (users, settings, URL filters, audit log), passkeys, sign out everywhere, and API token management stay browser-only, as [docs/api-tokens.md](../docs/api-tokens.md) already decides. A token is never an admin. Finer-grained token scopes are a possible follow-up, not part of this plan.

## Acceptance criteria

- Every non-browser-only action in the web UI can be done with an API token over REST and over MCP.
- A test enumerates the `/api` routes registered in `cmd/shortlinks/main.go` and fails if one is missing from the OpenAPI spec (#0148) or has no MCP tool and isn't on an explicit exclusion list (#0149).
- Claude Code can connect with `claude mcp add --transport http shortlinks https://<host>/mcp --header "Authorization: Bearer slk_…"` and answer "which content got the most clicks this month?" with one report tool call (#0151).
- `go test ./...` and `cd web && npm run build` pass.
