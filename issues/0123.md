## Description

#0122 adds a clicks-by-placement table to CampaignDetail and `by_placement` to the campaign stats JSON, but there's no CSV of it. `GET /api/campaigns/{slug}/export.csv` (#0107, `internal/handlers/campaigns_export.go`) exports one row per link only. Getting per-shop totals into a spreadsheet still means pivoting that per-link file by hand.

## Long Description

The #0122 plan deferred this on purpose. `campaigns_export.go` mirrors the per-link table, and it shouldn't grow a second table without someone deciding to. The product question for Brennan: should this be a separate endpoint (e.g. `/api/campaigns/{slug}/export-placements.csv`) or a second block in the existing file?

**Wanted:**
- **Columns:** placement, link count, click count, using the same grouping, `(none)` row, sort order, window and bot exclusion as `by_placement`. The rows must sum to the same totals as the on-screen table.
- **Download:** a button on the CampaignDetail placement panel, next to the existing export.
- **Auth:** works with an API token (`Authorization: Bearer slk_…`), so WoodDust or Home Assistant can fetch it.

**Constraints (from #0122 and #0121):** aggregate counts only, no per-click detail. Placement must never appear in a URL or UTM parameter, which includes the download filename.
