# 0150 — The MCP server has no report tools or prompts, so agents can't answer questions about link activity

## Description

Expose every report from `internal/reports` as a typed MCP tool, plus `list_reports`, and add three MCP prompts for the questions Brennan asks most.

## Long Description

**Tools:** `list_reports`, `get_overview`, `get_top_content`, `get_top_links`, `get_breakdown`, `get_timeseries`, `get_movers`, `get_idle_links`, `compare_campaigns`, `get_campaign_performance`, `get_link_performance`. Each takes the shared parameters from #0139 as typed, described fields (an enum for `range`, an array of strings for each UTM filter, a `tz` string defaulting to the instance's `DEFAULT_TIMEZONE`) plus its report-specific ones. Each calls `internal/reports` directly; reports are read-only, so in-process HTTP dispatch isn't needed.

Results return `highlights` as the text content and the full envelope as structured content, so a model can answer from the text and read the data when it needs detail. Keep each tool description to one or two sentences that say **when** to use it ("Use for 'what content is getting the most clicks'…").

**Prompts:**

| Prompt | Arguments | What it asks the model to do |
|---|---|---|
| `weekly_summary` | `tz?` | Call `get_overview` and `get_movers` for the last 7 days and write a short summary: totals versus the previous week, the top three pieces of content, what's rising and what's gone quiet. |
| `campaign_report` | `slug` | Call `get_campaign_performance` and summarise which content won on which channel, with idle links. |
| `whats_working` | `range?` | Call `get_top_content` and `get_breakdown` by source and recommend where to post next. |

**Performance budget:** every report tool responds in under 300 ms for a user with 1,000 links and 100,000 clicks in the window, measured with a seeded test DB benchmark (`go test -bench`). If one doesn't, add the index it needs (for example `clicks (link_id, clicked_at)`) in a migration.

## Acceptance criteria

- Every registered report has a tool. A test fails if a report is added to the registry without a tool.
- MCP client round-trip tests call each tool and each prompt.
- The benchmark exists, and its result is recorded in the resolution notes.
- `go test ./...` passes.
