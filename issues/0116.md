# 0116 — `TestLoad_DefaultsApplied` fails because its fixture predates a required variable

| | |
|---|---|
| **Status** | open |
| **Module** | config |
| **Platform** | All |
| **First seen** | 2026-08-09 |

## Description

`internal/config`'s `TestLoad_DefaultsApplied` fails on a clean checkout:

```
config_test.go:74: loadFromFile returned error: config: missing required variable BASE_URL
```

`setRequired` (`internal/config/config_test.go:14-21`) writes the set of variables that were required when it was written, and `BASE_URL` was made required afterwards — by commit `791e7d3`, the same commit that caused the [#0110](0110.md)/[#0111](0111.md) migration drift, though the two problems are otherwise unrelated.

## Why this matters

**It is a persistent red test, and this repo runs `go test ./...` as its verification gate.** Every issue resolved in this series has had to carry the phrase "except the pre-existing `internal/config` failure" through implementation, review, and resolution notes. That is a standing exception the eye learns to skip past — and a second failure appearing next to it would be easy to wave through as the known one.

It is also trivially fixable, which is the argument for just doing it rather than continuing to annotate around it.

## Scope / deliverables

- Add `BASE_URL` to `setRequired`, or otherwise make the fixture derive the required set from the same source `Load` uses so it cannot drift again.
- **Prefer the non-drifting form if it is cheap.** A hand-maintained list of required variables in a test is the thing that broke; restating it correctly leaves the same trap for the next required variable.
- Check whether any sibling test in `internal/config` has the same shape and would fail on the next addition.

## Acceptance criteria

- [ ] `go test ./internal/config/ -count=1` passes.
- [ ] `go test ./... -race` is **fully green** with `TEST_DATABASE_URL` set — no standing exception left to annotate.
- [ ] Adding a new required variable to `Load` does not silently break this test, or breaks it with a message that names the missing variable.
- [ ] `gofmt -l` clean for any file touched.

## Out of scope

- Changing which variables `Load` requires. `BASE_URL` being required is correct; the test is what is stale.
- The two pre-existing `gofmt` offenders (`internal/handlers/redirect_e2e_test.go`, `internal/handlers/static_test.go`) — unrelated, and worth their own cleanup.
