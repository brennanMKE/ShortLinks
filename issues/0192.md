# 0192 — An unknown /api/ path returns the SPA's HTML shell with 200 instead of a JSON 404

| | |
|---|---|
| **Status** | in-progress |
| **Module** | handlers |
| **Platform** | All |
| **Phase** | 22 — Web performance and stale tabs |
| **First seen** | 2026-11-19 |

## Description

The SPA catch-all (`GET /`) also answers paths under `/api/`. When a route isn't mounted, for example `/api/reports` in dev mode, the client gets `200 text/html` (the app shell) instead of an error. #0186 found this because LinkDetail parsed the HTML as a report and threw. Clients and agents expect JSON errors from `/api`.

## Acceptance criteria

- Any unmatched `/api/*` request returns `404` with the standard JSON error body and `Cache-Control: no-store`, in both Postgres and dev mode. A Go test covers an unknown path and a known path with the wrong method (405 if the mux gives it).
- The SPA catch-all still serves hash-routed pages and `/assets/*` as before (#0184 B5 unchanged).

## Relation

- Found in review of [#0186](0186.md).

## Root cause

`SPAHandler` is mounted on the `GET /` catch-all, the least-specific mux pattern, so any `/api/*` path with no mounted route (for example `/api/reports` in dev mode) fell through to it. It has no `/api` awareness, so it served the HTML shell with 200.

## Fix

`SPAHandler.ServeHTTP` now answers `api` and `api/*` with `writeError(w, 404, "not found")` (the standard `{"error":...}` JSON) and `Cache-Control: no-store`. Every real `/api` route is a more specific pattern and still wins, so this applies to both Postgres and dev mode with no change to `buildMux`. A known path with the wrong method gets the mux's own 405. The shell and `/assets/*` behavior is untouched (#0184 B5).

## Verification

- `go build ./... && go vet ./...` clean; `go test ./internal/handlers/ ./cmd/...` pass, including new `TestSPAUnknownAPIPathIsJSON404` (unknown paths, `/api`, `/api/`, 405 on wrong method, known path, shell, `/apiary` still shell).
- Dev-mode binary on :8222 (`STORAGE=json`, built SPA): `/api/nope` gives 404, `application/json`, `no-store`, `{"error":"not found"}`; `/` gives 200 HTML `no-cache`; `/assets/index-*.js` gives 200 `immutable`; `/assets/missing.js` gives 404 `no-cache`; `POST /api/nope` gives 405. Server stopped afterwards.
