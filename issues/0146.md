## Description

Campaign list items carry all-time counts only (`campaignCountColumns` in `internal/campaigns/store.go`), and the SPA's Trend column is a placeholder dash. Add `clicks_30d`, a 30-point daily `sparkline` and a derived `status` to each item of `GET /api/campaigns`.

## Long Description

- `clicks_30d` and `sparkline` (30 integers, oldest first, today last) use the shared report window logic from #0139 with `range=30d`, bots excluded. `tz` is an optional query parameter.
- Build them from one grouped query over `clicks` by `campaign_id, day` for all of the caller's campaigns, not one query per campaign.
- `status` is `live`, `scheduled`, `ended` or `archived`, from the dates and the archived flag, using the same function as `campaign-comparison` (#0142).
- Add `sort=activity|created|name` (default `created`, today's order).

## Root cause

`GET /api/campaigns` returned only all-time `total_clicks` and had no status field. A dead campaign could therefore outrank a live one, and the SPA had no data for its Trend column.

## Fix

- **New store query.** `campaigns.Store.CampaignDailyClicks` runs one grouped query over `clicks`, by `(campaign_id, day)`:
  - joined to `links` and `campaigns`, both scoped to the caller;
  - bots excluded;
  - bucketed with `date_trunc('day', clicked_at AT TIME ZONE tz)`, matching `reports.DayExpr`;
  - over a half-open window.
- **Window and new fields.** The handler resolves the window with `reports.ParseParams` and `ResolveWindows` at `range=30d`, which includes today. It zero-fills a 30-point `sparkline` and sums it into `clicks_30d`, so the two always agree. It takes `status` from `reports.CampaignStatus`, with today in `tz`.
- **Time zone.** `tz` is optional. It defaults to `DEFAULT_TIMEZONE` through `WithDefaultTimezone`, which is wired in both `main.go` paths. The window is always 30 days; `range`, `from` and `to` are ignored.
- **Sorting.** The new `sort` parameter takes:
  - `created`: the existing default.
  - `activity`: `clicks_30d` descending.
  - `name`: case-insensitive.

  Ties fall back to newest first via a stable sort. The list isn't paginated, so sorting in Go is correct. A bad value for `sort` or `tz` returns a 400 (`invalid_sort` or `invalid_tz`).
- **Dev mode** returns zeros.
- **Review fixes (`91d5afd`):** scope by link owner to match the reports exactly, a cross-user test, a comment fix, and a docs note.
