## Description

Add two reports: `breakdown` (clicks by one dimension, with share) and `timeseries` (daily or weekly clicks, optionally split by a dimension). These answer "where do my clicks come from?" and "how did Bluesky trend this month?" across all of a user's links, under the shared filters.

## Long Description

**`breakdown`**, extra params `dimension` (required): `source`, `medium`, `utm_campaign`, `content`, `term`, `referer`, `placement`, `campaign`, `link`, or `content_group` (uses #0140's key). `limit` defaults to 20, and the rest are summed into an `other` row.

```json
{"dimension": "source", "total": 1284, "rows": [{"value": "mastodon", "clicks": 498, "share": 0.388, "previous_clicks": 410}], "other": {"clicks": 12, "values": 4}}
```

Referrers are reported as hostnames (parse `clicks.referer`; empty means `(direct)`). Reuse and generalise `dimensionBreakdown` (`internal/clicks/stats.go:1014`) to take a predicate builder instead of one column/id pair, rather than writing a second copy.

**`timeseries`**, extra params `granularity=day|week` (default `day`; weeks start Monday in `tz`), `split_by` (any `breakdown` dimension) and `series_limit` (default 5, other series summed as `other`).

```json
{"granularity": "day", "series": [{"name": "mastodon", "points": [{"date": "2026-10-20", "clicks": 12}]}], "previous": [{"date": "2026-09-20", "clicks": 9}]}
```

Without `split_by` there is one series named `all`. Days with no clicks are zero-filled.

## Root cause

Breakdowns and time series existed only for one link or one campaign (`UTMStatsForLink`, `CampaignStats`, `dimensionBreakdown`). Nothing worked across all of a user's links under the shared report filters, so there was no answer to "where do my clicks come from?" or "how did Bluesky trend this month?".

## Fix

Added `internal/reports/breakdown.go` and `timeseries.go`, both built on `ScopedQuery`.

**`breakdown`** (`dimension` is required; it is one of `source`, `medium`, `utm_campaign`, `content`, `term`, `referer`, `placement`, `campaign`, `link`, `content_group`):
- Returns rows with `share`, `previous_clicks` and `previous_total`, plus an `other` rollup, or null when every value fits within `limit`.
- Referrers are reported as hostnames parsed in SQL. Empty ones become `(direct)`.
- Empty UTM and placement values use `~none`. Clicks with no campaign use `none`, labelled "No campaign".
- `content_group` is grouped in Go with `ContentKey`/`ContentTitle` and carries `truncated` like `top-content`.

**`timeseries`** (`granularity=day|week`, `split_by`, `series_limit`):
- Days are zero-filled.
- Weeks start on Monday in `tz` and use civil-date arithmetic, so DST changes don't shift them.
- Split series beyond `series_limit` are summed into an `other` series.
- `previous` has the same number of buckets as the current series and is aligned by position. Each previous bucket covers the same day offsets and is dated by its first day.

**Referrer retention.** Referrers are cleared after `clicks.DetailRetention` (90 days). When the previous window starts before that cutoff, referrer comparisons return null previous values and skip "Biggest gain". The highlights explain this. They also warn when the current window reaches past the cutoff.

**Acceptance criterion waived (orchestrator, 2026-11-18): `dimensionBreakdown` was not generalised.** That function (`internal/clicks/stats.go:1014`) is a flat single-id query with a fixed LIMIT and no time zone, joins, previous window or referrer parsing. A predicate builder would make it more complex without removing any duplication, so the reports use their own `ScopedQuery`-based SQL. `internal/clicks` is untouched, and its tests pass unchanged. Import cycles were not the reason: `clicks` never imports `reports`.

The review fixes were made in `67f67cd` on `issue/0141`: referrer retention, aligned weekly `previous`, a shared highlight noun (`dimNoun`), and more tests.

## Gotchas

- **`previousSeries` relies on equal window lengths.** It assumes the previous window has the same length as the current one, which `ResolveWindows` guarantees. A report that overrides windows (the #0143 hook) must keep them equal, or it will index out of range.
- **No-click windows skip the retention caveat.** The highlight functions return "No clicks…" early, so a window with no clicks omits it.
- **The referrer regex is a constant inlined into the SQL.** That is safe only because it is not user input; keep it that way.
- **Campaign and link breakdowns need a scoping predicate.** #0143's per-campaign and per-link breakdowns should pass one through `ScopeOpts.Where` and reuse `dimensionSQL`, `refererHost` and `contentGroups`.
