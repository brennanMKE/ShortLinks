# 0106 — QR codes per link for print placements

| | |
|---|---|
| **Status** | open |
| **Module** | web / handlers |
| **Platform** | All |
| **First seen** | 2026-08-07 |

## Description

For fliers, each poster location gets its own short link so scans are attributable to a location. That only works if there is a QR code to print. Generate one per link in the campaign view, downloadable at print resolution.

## Scope / deliverables

- A QR code per link, generated from its short URL.
- Download as **SVG** (vector, correct for print) and **PNG at print resolution**.
- Available from the campaign detail links table ([#0103](0103.md)) and, if it fits naturally, the existing link detail view.
- Bulk download for a campaign — one archive containing every link's code, named by short key and placement so a stack of printed sheets can be matched to locations without guessing.
- **Pick a library — server-side Go or client-side — and record the choice and its reasoning in `docs/campaigns.md`** ([#0108](0108.md)). Either is acceptable; the decision should be deliberate and written down rather than incidental.

## Acceptance criteria

- [ ] A generated code scans correctly on a real phone camera — **verified by actually scanning one**, not by trusting the encoder.
- [ ] SVG output is vector (no embedded raster) and scales to poster size without artifacts.
- [ ] PNG output is at a resolution suitable for print, and the chosen DPI/pixel size is documented rather than arbitrary.
- [ ] Error correction level is chosen deliberately and documented — a flier gets scuffed outdoors, so the default may not be right.
- [ ] The encoded URL is the short URL, not the destination. Encoding the destination would bypass click recording entirely and silently break attribution — the exact thing this feature exists to enable.
- [ ] Quiet zone (the mandatory white margin) is preserved in both formats; codes fail to scan without it and it is the most common way this goes wrong.
- [ ] Bulk download filenames are unambiguous and filesystem-safe, including when a placement contains spaces, slashes, or punctuation.
- [ ] A link with no placement still exports with a sensible filename.
- [ ] `cd web && npm run check` 0 errors; tests pass with new tests observed by name.
- [ ] **Seen running** via `./scripts/dev.sh`, including a real scan of a downloaded code.

## Out of scope

- Branded or logo-embedded QR codes.
- Print layout — sheets, crop marks, multi-up arrangements. Producing the codes is in scope; laying them out for a printer is not.
- Scan-specific analytics distinct from clicks. A scan **is** a click; there is no separate scan event, and the plan's attribution model depends on that staying true.
- Dynamic QR codes that can be re-pointed after printing. The short link already provides that indirection — the code encodes the short URL, and the short URL's destination is editable.

## Notes

- The suggested convention for print links (documented, not enforced) is `utm_medium=print`, `utm_source=flyer`, with `utm_content` or `placement` naming the location.
- Print scans have no referer and no bot noise ([#0101](0101.md)), so they are cleaner signal per click than social — but they undercount in raw comparison because impression volume differs by orders of magnitude. Worth remembering when this data lands next to social in a chart.
