## Description

For fliers, each poster location gets its own short link so scans are attributable to a location. That only works if there is a QR code to print. Generate one per link in the campaign view, downloadable at print resolution.

## Scope / deliverables

- A QR code per link, generated from its short URL.
- Download as **SVG** (vector, correct for print) and **PNG at print resolution**.
- Available from the campaign detail links table ([#0103](0103.md)) and, if it fits naturally, the existing link detail view.
- Bulk download for a campaign — one archive containing every link's code, named by short key and placement so a stack of printed sheets can be matched to locations without guessing.
- **Pick a library — server-side Go or client-side — and record the choice and its reasoning in `docs/campaigns.md`** ([#0108](0108.md)). Either is acceptable; the decision should be deliberate and written down rather than incidental.

## Acceptance criteria

- [ ] A generated code scans correctly on a real phone camera — **verified by actually scanning one**, not by trusting the encoder.
- [ ] SVG output is vector (no embedded raster) and scales to poster size without artifacts.
- [ ] PNG output is at a resolution suitable for print, and the chosen DPI/pixel size is documented rather than arbitrary.
- [ ] Error correction level is chosen deliberately and documented — a flier gets scuffed outdoors, so the default may not be right.
- [ ] The encoded URL is the short URL, not the destination. Encoding the destination would bypass click recording entirely and silently break attribution — the exact thing this feature exists to enable.
- [ ] Quiet zone (the mandatory white margin) is preserved in both formats; codes fail to scan without it and it is the most common way this goes wrong.
- [ ] Bulk download filenames are unambiguous and filesystem-safe, including when a placement contains spaces, slashes, or punctuation.
- [ ] A link with no placement still exports with a sensible filename.
- [ ] `cd web && npm run check` 0 errors; tests pass with new tests observed by name.
- [ ] **Seen running** via `./scripts/dev.sh`, including a real scan of a downloaded code.

## Out of scope

- Branded or logo-embedded QR codes.
- Print layout — sheets, crop marks, multi-up arrangements. Producing the codes is in scope; laying them out for a printer is not.
- Scan-specific analytics distinct from clicks. A scan **is** a click; there is no separate scan event, and the plan's attribution model depends on that staying true.
- Dynamic QR codes that can be re-pointed after printing. The short link already provides that indirection — the code encodes the short URL, and the short URL's destination is editable.

## Notes

- The suggested convention for print links (documented, not enforced) is `utm_medium=print`, `utm_source=flyer`, with `utm_content` or `placement` naming the location.
- Print scans have no referer and no bot noise ([#0101](0101.md)), so they are cleaner signal per click than social — but they undercount in raw comparison because impression volume differs by orders of magnitude. Worth remembering when this data lands next to social in a chart.

## Root cause

Not a defect — the printable artifact the per-location attribution model depends on.

## Fix

**Server-side Go**, recorded in `docs/campaigns.md` as the deliberate choice: `github.com/skip2/go-qrcode` encodes; `github.com/makiuchi-d/gozxing` decodes **in tests only**, confirmed absent from the production binary via `go list -deps ./cmd/shortlinks`.

**Error correction level H** (~30%) because a flier gets scuffed outdoors. **20px per module** → ~820px ≈ 2.73in at 300 DPI. No `pHYs` chunk, deliberately.

Four delivery points: per-row **SVG and PNG** links in the campaign links table, a "QR code" row on link detail, and `GET /api/campaigns/{slug}/qr.zip` naming entries by short key and placement.

## Verification

`npm run check` 193 files / 0 errors; `npm test` **370 passing**; `go build`, `go vet`, `go test ./... -race` clean apart from the pre-existing `internal/config` failure. `shortlinks_test` left empty.

Quiet zone measured at exactly 4 modules on all four sides in both formats — from parsed SVG geometry and hand-unfiltered PNG IDAT scanlines, not from the library's promise. SVG confirmed pure vector (287 `<rect>`, no `<image>`, no `data:`); PNG chunks exactly `IHDR, IDAT, IEND`.

The "scans on a real phone" criterion was met as closely as this environment allows: the reviewer built a **Swift binary against Apple's Vision framework** (`VNDetectBarcodesRequest`, the detector behind the iOS camera) and scanned all 68 entries of a real bulk zip plus browser-downloaded files. Zero mismatches; every code resolved to its own short URL, none to a destination.

## Gotchas

- **The layout invariant cost more than the feature.** QR generation passed review on its first pass. The eleventh table column took **four fix rounds**, and each round was honestly measured and still wrong.
- **Round one measured against thin test data.** A campaign with titles `T1…` and placements `P1…` reports `926 == 926`; the same code with realistic content reports `940 / 926` with the Remove button clipped. **Row count is not the variable — column width is.** `Share of listed links` alone swings 68.81px → 125.48px between datasets. Build the adversarial dataset *first*.
- **`scrollWidth == clientWidth` is a threshold, not a fit.** With `table { width: 100% }` and `table-layout: auto` the used width is `max(926, min-content)`, so a table can report `926 == 926` while sitting **0.36px** from failure — which is what round three shipped. Measure `min-content` directly via `.links-table { width: min-content }`.
- **A 7-character custom alias reopened the regression.** Generated keys are 6 chars, so every test passed; `validKey` accepts 1–12. Under round three's geometry a 12-char alias measured **−41.98px**.
- **A `max-width` on the `<td>` alone is inert.** `.placement-cell` capped its `<td>` at 90px while its uncapped `<th>` set the column to 101.56px. The cap did nothing for the whole life of #0103.
- **The budget was allocated backwards once.** Round four spent 20px on `.title-cell`/`.dest-cell` (buying one character, changing nothing readable) while squeezing `.key-cell` to 60px — which truncates the **default** 6-char generated key, needing 43px of content box against 36px available. The entire desktop column read `Uf9…` `p0z…` `QUL…`.
- **A truncated column *header* is a worse defect than truncated data**, because it removes the label telling you what the column is. `Destination` ellipsized to `DE…` with no `title`, and read as a broken page rather than a narrow column. Renaming to `URL` (60px == 60px) fixed it at zero width cost — the same move as `Short key` → `Key`.
- **Three consecutive rounds shipped comments that misstated their own measurements.** The worst inverted a sign: `min-content 929.72px — only 3.72px of margin` described a stage that was 3.72px **past** a 926px container, turning a failing step into a passing-looking one. The numbers kept being right while the readings were wrong.
- **A test comment claimed a crop it never performed**, and `docs/campaigns.md` cited that test as one of two quiet-zone pins — the doc vouching for coverage that did not exist. Replaced with a real crop plus a blackened-ring test; the pair was checked for *discrimination*, confirming a merely-cropped clean image still decodes.
- **`decodeSVG` reconstructed the grid from geometry alone**, so white modules on a white background would have passed every SVG test.
- **`.btn`/`.btn-subtle` on an anchor outside `Button.svelte` match nothing** — Svelte scopes them — so the toolbar link rendered UA-default `rgb(0,0,238)` underlined, 6px off its neighbour's baseline, while a comment claimed it was styled like the Button.

## Downstream constraints

1. **`min-content` headroom is 15.58px.** Any new column or widened cap must re-measure it, not `scrollWidth`. The margin is worth roughly two extra digits of `Clicks` (7 digits leaves +5.16px).
2. **Every text column is now capped on BOTH `<th>` and `<td>`.** Capping only the `<td>` is inert.
3. **`.dest-cell` is a deliberate 60px stub** pending [#0113](0113.md), not a sharer of the width give-back. Its `<td>` `title` is currently the only way to read a full destination on desktop.
4. **Verify layout against a 12-character custom alias**, not the 6-char generated default.
5. `Source`/`Medium` remain **uncapped** — [#0112](0112.md).
6. The zero-scroll invariant is verified at 1024/1280/1440/1920, **not** at every width ≥900px — [#0114](0114.md).

## Follow-ups

- [#0112](0112.md), [#0113](0113.md), [#0114](0114.md) — all three surfaced by this issue's layout verification; none are #0106 regressions.
- Placement cells still cannot distinguish `Westlake Center Platform Kiosk Panel` from `Westlake Center Mezzanine Wayfinding Board` — the tail carries the meaning, and no affordable cap fixes it. Wants middle-truncation; recorded against [#0113](0113.md).
- `Cache-Control: immutable` on QR images vs. a `Content-Disposition` filename embedding the editable placement: after a placement edit, a re-download can serve the stale filename from cache for up to a year. Documented at `internal/handlers/links.go`, not fixed.
- Custom aliases differing only in case would collide on extraction on a case-insensitive filesystem. Probability from generated keys ~7e-10.
