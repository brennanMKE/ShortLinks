# 0128 — Portiko can't be mounted under a path prefix, so it can't share a host with ShortLinks

| | |
|---|---|
| **Status** | open |
| **Module** | portiko (upstream) |
| **Platform** | All |
| **Phase** | 12 — Portiko groundwork |
| **First seen** | 2026-11-12 |

## Description

Portiko's router (`provider/router.go` in `Kolonnade/Portiko`) registers its routes at the root of the host: `GET /{$}`, `GET /health`, `GET /u/{n}/{$}`, `/login`, `/signin`, `/profile`, `/oauth/`, `/accounts/` and `/.well-known/…`. ShortLinks already uses `/`, `/health` and `/u/{key}` on the same host. Portiko needs to support running under a prefix such as `/id`, so a site can be its own provider. **The work happens in the Portiko repo.** This issue tracks it for ShortLinks.

## Long Description

**Wanted in Portiko:**
- A provider can be served under a path. For example, `ISSUER=https://go.example.com/id` serves every provider route under `/id/…` and puts that path in discovery, the JWKS URL, the templates' links and form actions, and redirects. Either `provider.Handler()` works behind `http.StripPrefix` with the issuer path taken into account, or the router takes the prefix directly. `zitadel/oidc` supports issuers with a path; check that Portiko's own pages and API (`/accounts/v1/*`, the passkey JavaScript in the templates) do too.
- Cookies are limited to the prefix path where that's possible, and have names that won't clash with the host site's (ShortLinks uses `shortlinks_session`).
- The well-known discovery documents (`kitprotocol.WellKnownPath`, `LegacyWellKnownPath`) resolve correctly for an issuer with a path.
- The `rp` library works against an issuer on the same origin as the site. The redirect URI and the issuer share a host, and `RedirectURL` is under the site's own paths.
- An embedding test: one `http.ServeMux` serves both a host app and the provider under `/id`, and a full sign-in with `virtualwebauthn` succeeds.

**Why a prefix and not a subdomain:** Brennan decided (2026-11-12) that the ShortLinks website itself is the IdP. A prefix on the same host keeps the passkey domain unchanged and needs no new DNS, Apache virtual host or certificate.

## Notes

- ShortLinks' `/u/{key}` and Portiko's `/u/{n}/{$}` don't overlap as Go patterns (the trailing slash differs), but `/` and `/health` do conflict, and two `/u/` namespaces on one host would confuse people. A prefix avoids all of it.
