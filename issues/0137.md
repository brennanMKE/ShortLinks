# 0137 — Portiko has no way to list, rename or revoke passkeys, which ShortLinks users can do today

| | |
|---|---|
| **Status** | open |

| **Platform** | All |

## Description

ShortLinks' Account page lists a user's passkeys and lets them rename or revoke one (`GET /account/credentials`, `PATCH`/`DELETE /account/credentials/{id}` in `internal/handlers/credentials.go`). Revoking the last passkey is refused with 409 `cannot_revoke_last_credential`. Portiko's account pages (`provider/templates/home.html`, `profile.html`) only edit the display name and avatar, and its router has no passkey-management endpoints. Moving to Portiko would remove a feature users have now, unless Portiko gains one first. **The work happens in the Portiko repo.**

## Long Description

**Wanted in Portiko:** on the signed-in account pages, a list of the account's passkeys showing the name, a hint about which provider holds it (ShortLinks derives this from the AAGUID in `deviceHint`), when it was created and when it was last used. Rename and revoke actions go through `/accounts/v1/…`. The rules:
- Revoking the account's last passkey is refused.
- Revoking writes to Portiko's `auth_audit` table.
- Renaming uses the same passkey-name signal Portiko already sends on profile changes, so the name shown in the browser's or OS's password manager updates. **Superseded (2026-11-12):** WebAuthn has no per-credential name signal, and `signalCurrentUserDetails` names the account, not a passkey. Rename changes only Portiko's label and sends no signal; revoke calls `signalAllAcceptedCredentials`. See Portiko's `docs/passkeys.md`.

Once this lands, ShortLinks' Account page links to it (#0133) and the ShortLinks endpoints are deleted (#0136).
