## Description

Add `campaign-performance` (one campaign: summary, content × channel matrix, placements, daily series) and `link-performance` (one link: series, breakdowns, referrers, sibling links for the same content, last click). These are the single-call answers to "how is the Guides 2026-11 campaign doing?" and "how is this link doing?".

## Long Description

**`campaign-performance`**, extra params `slug` (required) and `columns=source|medium|placement` (default `source`). The default window is the campaign's own dates, reusing `campaignWindow`; an explicit `range`/`from`/`to` overrides it.

```json
{"campaign": {"slug": "guides-2026-11", "name": "Guides 2026-11", "status": "live", "starts_on": "2026-11-01", "ends_on": "2026-11-30"},
 "totals": {"clicks": 902, "previous_clicks": null, "per_active_day": 50.1, "links": 42, "links_clicked": 24},
 "matrix": {"columns": ["mastodon", "bluesky"], "rows": [{"content_key": "…", "title": "…", "cells": {"mastodon": {"clicks": 118, "key": "HaQRwV"}, "bluesky": {"clicks": 61, "key": "riCY47"}}, "total": 179}], "column_totals": {"mastodon": 498, "bluesky": 261}},
 "timeseries": [{"date": "2026-11-14", "clicks": 64}],
 "placements": [{"placement": "Mission St board", "clicks": 14}],
 "removed_links_clicks": 7}
```

A cell holds `key` when exactly one link covers that pairing, and `keys` when several do. A missing pairing is absent, not zero. With more than six columns, keep the top five and add `other`.

**`link-performance`**, extra param `key` (required):

```json
{"link": {"key": "HaQRwV", "title": "…", "label": "Mastodon guide post 84", "destination_url": "…", "campaign_slug": "guides-2026-11", "active": true},
 "totals": {"clicks": 90, "previous_clicks": 74, "all_time": 141, "last_clicked_at": "2026-11-18T18:42:00Z"},
 "timeseries": [], "by_source": [], "by_medium": [], "by_content": [], "by_referer": [],
 "siblings": [{"key": "riCY47", "label": "Bluesky guide post 83", "clicks": 52}]}
```

`siblings` are the caller's other links with the same content key, in any campaign.

## Root cause

Campaign and link stats were only available from the older endpoints (`GET /api/campaigns/{slug}/stats` and `GET /api/links/{key}`). Those endpoints use UTC days and leave out today. Neither answered "which content won on which channel?", and neither showed a link's siblings, so agents and the planned UI had no single report for either question.

## Fix

Added two reports to `internal/reports`.

**`campaign-performance`** requires `slug` and accepts `columns=source|medium|placement`.
- Unknown or unowned slugs return 404 `campaign_not_found`, via a new `NotFoundError` that the handler maps with `errors.As`.
- The window defaults to the campaign's own dates through the `Windows` hook. `ends_on` counts as an inclusive last day in `tz`, clamped to today, and today so far is included. Without an explicit `compare=previous` there is no previous window.
- An explicit `range`, `from` or `to` overrides the default. A campaign with only one date falls back to the standard window.
- Clicks are scoped by forcing the campaign filter to the slug. The envelope reports the forced slug through the new `Report.CampaignParam`.
- The matrix is built from content groups, with one column per source, medium or placement:
  - Columns are ranked by clicks. Above six, the top five are kept plus an `other` column, and each link is counted once.
  - A cell carries `key` when one link fills it, or `keys` when several do. Pairings with no clicks are absent.
  - The response also carries `column_totals`, `total_rows` and `limit`.
- Also returned: `timeseries`, `placements` (with `is_none`) and `removed_links_clicks`.

**`link-performance`** requires `key`. Unknown or unowned keys return 404 `link_not_found`.
- Returns totals, an all-time count and `last_clicked_at`. These ignore the window and filters but respect bots.
- Returns a timeseries, and breakdowns by source, medium, content and referrer. Referrer retention is handled the same way as in `breakdown`.
- Returns `siblings`: the caller's other links with the same content key, in any campaign. The label comes from `LinkLabel`, falling back to the key.

`timeseries.go` gained `dayRowsWhere` and `previousSeriesWhere`, and the existing functions now wrap them with unchanged SQL.

- `filters.campaign` now reports the forced slug.
- No duplicate placement highlight.

## Gotchas

- **Totals differ from the existing campaign stats endpoint.** `GET /api/campaigns/{slug}/stats` (`campaignWindow`) leaves out the campaign's last day and today, so its totals can be lower than this report's. #0164 shows both on one page, so fix `campaignWindow` first. A note has been added to #0119.
- **Matrix column names are normalized** (placement values are lower-cased and trimmed), while `placements` shows the most common spelling.
- **Raw ids in SQL text.** The link filters build `l.id = <id>` as SQL text from an int64 the database returned, because `ScopeOpts.Where` takes no placeholders. This is safe, but don't pass user input that way.
