## Description

Write an OpenAPI 3.1 spec for every `/api` route, embed it in the binary, and serve it at `GET /api/openapi.yaml` (no auth: it holds no secrets). A test keeps it in step with the router.

## Long Description

- Source of truth: `internal/openapi/openapi.yaml` (moved from the planned `docs/openapi.yaml` because `//go:embed` can't reach `docs/`), embedded with `//go:embed`. It covers request and response schemas, error codes, bearer auth, read-only behaviour, the report parameters from #0139 and every report.
- **Drift test:** parse the spec and the routes registered in `cmd/shortlinks/main.go` (expose the route table so the test can read it, or register routes through a helper that records them). Fail when an `/api` route is missing from the spec or the spec lists a route that doesn't exist.
- Link the spec from [docs/using-api-tokens.md](../docs/using-api-tokens.md).

## Acceptance criteria

- `GET /api/openapi.yaml` returns the spec with `Content-Type: application/yaml`.
- The spec validates as OpenAPI 3.1 in a Go test, or with a pinned validator in a test-only tool dependency.
- The drift test passes, and fails when a route is added without a spec entry (demonstrated in the PR description, not committed).
- Work this after #0139–#0147, or update it as each lands.
- `go test ./...` passes.

## Root cause

The REST API was documented only in prose (`docs/links.md`, `docs/campaigns.md`, `docs/analytics.md`, `docs/using-api-tokens.md`). There was no machine-readable description for agents or client generators, and nothing stopped the docs drifting from the router.

## Fix

**The spec.** A hand-written OpenAPI 3.1 spec at `internal/openapi/openapi.yaml`. The `internal/openapi` package embeds it and exposes `Spec()` and `Handler()`.
- It covers all 25 `/api` operations: request and response schemas, bearer (`slk_`) and cookie auth, 403 `api_token_read_only`, 429 with `Retry-After`, and 500 on every authenticated operation.
- `Idempotency-Key` on the three creates, with `Idempotent-Replayed` and the 400, 409, 413 and 422 codes.
- `PATCH` `active` with 422 `destination_denied` and 409 `conflict`.
- The links list modes and parameters. The campaign activity fields, with status enums.
- Reports are one `/api/reports/{name}` path with `name` as an enum. It documents the common params, each report's own and required params, the envelope with `data` as an `anyOf` of the ten report schemas, and the 400 and 404 codes.
- Request bodies set `additionalProperties: false`, matching `decodeJSON`'s `DisallowUnknownFields`.
- `servers` uses a `{base_url}` variable defaulting to `https://example.com`.
- Admin, `/account` and `/mcp` are out of scope, and `info.description` says so.

**Serving.** `GET /api/openapi.yaml` is registered in `buildMux`, with no auth and `Content-Type: application/yaml`. It sends a sha256 `ETag` and answers a matching `If-None-Match` with 304.

**Tests.**
- `TestOpenAPIDrift` compares `METHOD /path` between the spec and `buildMux`'s real route table, in both directions.
- `TestOpenAPIValid` validates against the OpenAPI 3.1 meta-schema. `BuildV3Model` catches broken `$ref`s.
- `TestOpenAPISchemaTypes` walks every schema and rejects invalid `type` values, which the validator alone misses.
- `TestOpenAPIOperationConventions`, `TestOpenAPIEndpoint` and `TestOpenAPIETag`.
- The validators (`pb33f/libopenapi`, `libopenapi-validator`) and `gopkg.in/yaml.v3` are test-only.

**Other changes.** `go get` moved `golang.org/x/crypto`, `x/net`, `x/sys`, `x/text` and `x/sync` to newer same-major versions.

The review fixes went into `cf3be4f` and `7e1c7fc` on `issue/0148`:
- `tz` alone doesn't switch modes;
- 404 on create and 500 everywhere;
- `additionalProperties: false`;
- wording and enums;
- the `servers` variable;
- the schema walk;
- the ETag;
- the `export.csv` `from`/`to` parameters and their 400.

## Verification

- `go build ./...` and `go vet ./...` are clean.
- `go test ./... -count=1` passes in every package except the known `internal/config` `TestLoad_DefaultsApplied` (#0116).
- The OpenAPI, `DiffRoutes` and `TestMCPToolParity` tests pass (25 routes, 25 operations).

- `go list -deps ./cmd/shortlinks` differs from main only by `internal/openapi`.
- The Opus reviewer requested changes twice: first for the `tz` trigger and the missing 404, then for the `export.csv` parameters. It approved everything else. The last fix touched only the spec, and I checked it against the reviewer's request and re-ran the tests.

## Files changed

- `internal/openapi/openapi.yaml`, `openapi.go` (new): the spec, the embed, and the handler with an ETag.
- `cmd/shortlinks/main.go`: registers `GET /api/openapi.yaml`.
- `cmd/shortlinks/openapi_test.go` (new): the drift, validity, schema-walk, conventions, endpoint and ETag tests.
- `docs/README.md`, `docs/using-api-tokens.md`: link to the spec.
- `go.mod`, `go.sum`: the test-only validators, yaml.v3, and the `x/*` bumps.

## Gotchas

- **The spec must change with every `/api` change.** The drift test enforces this.
- **The spec is hand-maintained and isn't checked against the handlers.** Only paths and methods are guaranteed. Response bodies and status codes rely on review.
- **The `x/*` bumps reach the production binary.** They are routine, compatible updates. govulncheck wasn't available to list the security fixes they bring.
