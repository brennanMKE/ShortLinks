## Description

Write an OpenAPI 3.1 spec for every `/api` route, embed it in the binary, and serve it at `GET /api/openapi.yaml` (no auth: it holds no secrets). A test keeps it in step with the router.

## Long Description

- Source of truth: `docs/openapi.yaml`, embedded with `//go:embed`. It covers request and response schemas, error codes, bearer auth, read-only behaviour, the report parameters from #0139 and every report.
- **Drift test:** parse the spec and the routes registered in `cmd/shortlinks/main.go` (expose the route table so the test can read it, or register routes through a helper that records them). Fail when an `/api` route is missing from the spec or the spec lists a route that doesn't exist.
- Link the spec from [docs/using-api-tokens.md](../docs/using-api-tokens.md).

## Acceptance criteria

- `GET /api/openapi.yaml` returns the spec with `Content-Type: application/yaml`.
- The spec validates as OpenAPI 3.1 in a Go test, or with a pinned validator in a test-only tool dependency.
- The drift test passes, and fails when a route is added without a spec entry (demonstrated in the PR description, not committed).
- Work this after #0139–#0147, or update it as each lands.
- `go test ./...` passes.
