## Description

`POST /api/links` and the other link responses return `key` but not the full short URL. Clients have to know the instance's base URL and append `/u/<key>` themselves. CommunityPlatform also believed the base was hard-coded to go.sstools.co. That's not true: the server uses `BASE_URL` and the SPA derives it from its own origin (`web/src/lib/links.ts`). Still, the API should return the URL it means.

## Long Description

Requested by the CommunityPlatform session on 2026-11-18, for CoupleDozen invitation links on the new go.coupledozen.com instance. Their plan is in CommunityPlatform `docs/Plans/2026-11-ShortInviteLinks.md`, with issues GroupsWeb #0274/#0275 and CommunityBackend #0108. Each invitation link carries a secret token that grants entry to a family group, so these links need more protection than marketing links.

**Wanted:** add `short_url`, built from `BASE_URL` with `qr.ShortURL`, to every link object the REST API returns:
- create, including a duplicate response;
- get;
- list, in both plain and extended modes;
- PATCH;
- batch create rows;
- campaign link lists.

The MCP tools (#0149) add it themselves today; switch them to the REST field once it exists. The plain list response pinned by #0144's golden test gains this one field. Update the golden copy deliberately and note it.

## Root cause

`linkView` (the one JSON shape shared by every link endpoint) had `key` but no URL, and only the MCP layer decorated results by rewriting the JSON after the fact (`addShortURLs`). REST clients had to know the base and append `/u/<key>`.

## Fix

- `internal/handlers/links.go`: `linkView` gains `short_url`, filled by `toLinkView(l, baseURL)` with `qr.ShortURL(BASE_URL, key)` (the same builder the QR codes, CSV export and reports use; the SPA builds the same string from `/api/me` `base_url`). Every endpoint goes through `toLinkView`, so this covers create (and the duplicate response), get, PATCH, plain/extended and grouped (#0189) list, campaign get, campaign link list, assign, and batch create rows.
- MCP: removed the `addShortURLs` rewriting (and its test); tool outputs now carry the REST field unchanged. `docs/mcp.md` updated.
- OpenAPI: `Link.short_url` (required); the drift test passes.
- Golden test: `TestLinksList_DefaultResponseGolden` and the item-key list were updated deliberately; the only change is `short_url` on each item (`https://example.test/u/<key>`).
- Docs: `docs/links.md` "Short URL composition" replaced; it still described a hardcoded `go.sstools.co` base from before #0117.
- Web: `Link` type gains optional `short_url`. The SPA keeps its own `shortUrl()` (already correct, and usable before data loads), so no behavioural web change.
