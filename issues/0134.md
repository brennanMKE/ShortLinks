# 0134 — Dev mode has no stand-in for Portiko sign-in

## Description

Dev mode (`STORAGE=json`, `internal/devstore`) stubs out registration, login and recovery (`DevRegistrar`, `devLoginService`) and signs every request in through `DevAutoLogin`. That doesn't carry over once sign-in goes through Portiko. `scripts/dev.sh` and the planned E2E harness (#0080) need dev mode to keep working without Postgres or a real passkey.

## Long Description

**Options for the plan to choose between:**
1. Keep `DevAutoLogin` as the dev-mode sign-in and skip Portiko entirely in dev mode. This is the simplest, but the Portiko path never gets exercised locally.
2. Run the embedded provider in dev mode with Portiko's `DEV_INSECURE` setting, the stdout mailer and a local Postgres. This is realistic, but dev mode then needs a database.
3. Both: `DevAutoLogin` by default, and a `scripts/dev.sh --portiko` mode for testing the real flow.

Whatever is chosen, document it in `docs/dev.md`. The `devstore` stubs for the old ceremonies are deleted in #0136.
