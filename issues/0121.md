# 0121 — Hash click IPs and expire click records

| | |
|---|---|
| **Status** | open |
| **Module** | clicks, migrations |
| **Platform** | All |
| **First seen** | 2026-11-08 |
| **Phase** | 2 — Backend correctness |

## Description

Each click stores the visitor's raw IP as `INET` along with the user agent and referer (`docs/analytics.md`, "What is captured"). Dust Almanac promises its visitors that IPs are kept only as daily-salted hashes. Its poster QR codes redirect through go.dustalmanac.com, so this record breaks that promise. Brennan decided (2026-11-08) to fix it **before the posters launch**, so it is worked ahead of the phase order.

## Scope

- **Store a keyed daily hash in place of the raw IP:** HMAC-SHA256 with a salt that rotates daily, derived from a secret in `config.env`, the same approach as WoodDust's `contrib.IPHasher`. That's enough to count repeat clicks within a day.
- **Existing rows:** a migration to hash or null `ip`, and to drop or retype the column (migrations are append-only).
- **Retention:** a sweep that removes click detail after 90 days, keeping daily aggregates if the stats need them.
- **Docs:** update `docs/analytics.md`, and check that nothing (bot detection, stats, CSV) depends on the raw IP.

## Plan

### Root cause

`internal/handlers/redirect.go` `buildClickInfo` copies `clientIP(r)` into `ClickInfo.IPAddress`; `internal/clicks/recorder.go` `Record` passes it through `nullableIP` straight into `clicks.ip_address INET`. Nothing ever reads that column back: `internal/clicks/stats.go` has no `ip_address` reference, `internal/links/store.go` and `internal/campaigns/store.go` only `COUNT(*)` clicks, `botdetect.go` is UA-only, the CSV export reuses `CampaignRollup`, and no API endpoint or SPA type exposes per-click rows (`web/src/lib/types.ts:310 ip_address` is the **audit log** entry, not clicks). So the raw IP is stored, never consumed, and kept forever. `api_tokens.last_used_ip` and `audit_log.ip_address` are the signed-in **operator's** IP, not visitors'; out of scope here, noted at the end.

### Decisions

1. **Key source: derive from `SESSION_SECRET`, no new variable.** `SESSION_SECRET` is already required, validated non-empty, documented as 32 bytes of entropy, and present on go.sstools.co and go.opencircuitsf.com. A per-purpose subkey `HMAC-SHA256(key=SESSION_SECRET, "shortlinks click-ip key v1")` is cryptographically independent of the cookie-signing use (WoodDust's `contrib.DeriveKey` does the same from its form key). A required `CLICK_IP_SECRET` would make both live hosts fail at startup on upgrade for no security gain; an optional override is a trivial follow-up if ever wanted. Consequence to document: rotating `SESSION_SECRET` also changes the IP key — harmless, since the daily salt already makes hashes incomparable across days.
2. **Column: drop `ip_address INET`, add `ip_hash BYTEA` (32 bytes, nullable).** Matches `api_tokens.token_hash BYTEA`. Legacy rows get `NULL`: SQL cannot reproduce the Go-side daily key, and an unsalted `sha256(host(ip_address))` of an IPv4 is reversible by brute force (2^32 space), so nulling is the only honest one-way transform. Down migration re-adds `ip_address INET` empty (lossy by design; the raw IPs are gone and that is the point).
3. **Hash uses the click's own UTC day, not wall-clock `now()`.** `Record` hashes with `HashAt(ip, clickedAt)` so the salt day always agrees with the row's `clicked_at` (the goroutine can straddle midnight).
4. **Retention = strip, not delete; fixed 90 days; hourly.** `links.click_count`, `campaigns.total_clicks` are all-time `COUNT(*)` over `clicks`, and every chart accepts arbitrary `?from=/?to=`; deleting rows would need a daily-aggregate table plus rewrites of ~10 queries. Instead the sweep sets `ip_hash = NULL, user_agent = NULL` on rows older than 90 days and keeps the row as an anonymous event, so every existing count, chart, and breakdown stays correct with zero query changes. `referer` is **kept**: it is a stats dimension (`by_referer`, `dimensionBreakdown` in `stats.go`) and identifies the referring page, not the visitor. `user_agent` is safe to strip: `is_bot` is classified at record time and already persisted. Not configurable — the 90 days is the published promise; a constant is one less knob to misconfigure.
5. **`Recorder` does the hashing**, not the handler. Raw IP stops at the `clicks` package boundary; `ClickInfo`/`Click.IPAddress` keep carrying the raw string so `clientIP`, the adapter, and handler tests are untouched. `NewRecorder` gains a hasher parameter; a `nil` hasher stores `NULL` (fail closed on privacy, never raw).

### Steps (in order)

1. **Migration `000015_clicks_ip_hash`.**
   - `up.sql`: header comment (#0121, why NULL not transformed, see decision 2), then `ALTER TABLE clicks DROP COLUMN ip_address, ADD COLUMN ip_hash BYTEA;`
   - `down.sql`: `ALTER TABLE clicks DROP COLUMN ip_hash, ADD COLUMN ip_address INET;` with a comment that it restores the shape only.
   - Apply to the test DB: `migrate -path migrations -database "$TEST_DATABASE_URL" up`.
2. **`internal/clicks/iphash.go`** (new).
   - `type IPHasher struct{ key []byte }`; `func NewIPHasher(secret string) (*IPHasher, error)` — error on empty secret; key = `HMAC-SHA256(secret, "shortlinks click-ip key v1")`.
   - `func (h *IPHasher) HashAt(ip string, at time.Time) []byte`: `netip.ParseAddr(strings.TrimSpace(ip))`; on error return `nil`; `addr = addr.Unmap().WithZone("")`; `day := at.UTC().Format("2006-01-02")`; `salt := HMAC-SHA256(h.key, "shortlinks click-ip salt v1\x00"+day)`; return `HMAC-SHA256(salt, addr.String())` (full 32 bytes). `Hash(ip)` = `HashAt(ip, time.Now())` for convenience. Mirrors WoodDust `contrib.IPHasher.Hash`, differing only in binary output and the explicit `at`.
   - Only `crypto/hmac`, `crypto/sha256`, `net/netip`; no new modules.
3. **`internal/clicks/recorder.go`.**
   - `NewRecorder(pool *pgxpool.Pool, hasher *IPHasher, log *slog.Logger)`.
   - In `Record`: replace `ip_address` with `ip_hash` in the INSERT column list; replace `nullableIP(c.IPAddress)` with `r.hashIP(c.IPAddress, clickedAt)` returning `any` (`nil` when hasher is nil or hash is nil). Delete `nullableIP`; `net` import goes away. Update the `Click.IPAddress` doc comment ("hashed before storage; never persisted raw") and the "Non-UTM metadata" paragraph.
   - Update every call site to the 3-arg form (mechanical): `cmd/shortlinks/main.go:152`, `internal/handlers/redirect_e2e_test.go:29,163`, `internal/clicks/recorder_test.go` (16 sites), `internal/clicks/stats_test.go` (5 sites). Tests may pass `nil` except where they assert the hash.
4. **`internal/clicks/retention.go`** (new).
   - `const DetailRetention = 90 * 24 * time.Hour`, `const sweepInterval = time.Hour`, `const sweepTimeout = 30 * time.Second`.
   - `type Sweeper struct{ pool; log; retention time.Duration }`, `NewSweeper(pool, log)`.
   - `func (s *Sweeper) Sweep(ctx, now time.Time) (int64, error)`: `UPDATE clicks SET ip_hash = NULL, user_agent = NULL WHERE clicked_at < $1 AND (ip_hash IS NOT NULL OR user_agent IS NOT NULL)` with `$1 = now.Add(-s.retention)`; return `RowsAffected`. The OR guard keeps repeat runs from rewriting already-stripped rows; `idx_clicks_clicked_at` serves the range.
   - `func (s *Sweeper) Run(ctx)`: sweep once immediately, then on a `time.Ticker(sweepInterval)` until `ctx.Done()`; each pass under `context.WithTimeout(ctx, sweepTimeout)`; log `Info` with rows affected when > 0, `Error` on failure, never panic.
5. **`cmd/shortlinks/main.go`** (`servePostgres`, after line 152): `hasher, err := clicks.NewIPHasher(cfg.SessionSecret)` (return err); pass to `NewRecorder`; `go clicks.NewSweeper(pool, slog.Default()).Run(context.Background())` (the server has no graceful-shutdown ctx today; process exit ends the goroutine). Dev mode (`STORAGE=json`) records no clicks (`devstore` `RecordClick` is a no-op), so nothing is wired there.
6. **`internal/config`**: no new fields. Add one sentence to the `SessionSecret` field comment: it also derives the click-IP hashing key. No validation change (`scripts/dev.sh` uses a short dev value; `NewIPHasher` only rejects empty).
7. **Tests** — see below.
8. **Docs** — see below.

### Edge cases

- **IPv4-mapped IPv6** (`::ffff:203.0.113.7`) hashes identically to `203.0.113.7` (`Unmap`). **Zone** (`fe80::1%eth0`) is stripped. IPv6 is hashed at full address, not /64 — the daily salt already bounds linkability; note as a possible later tightening.
- **X-Forwarded-For**: `clientIP` keeps using the first entry (Apache appends the true client; a forged leading entry only pollutes that visitor's own hash). No change; also used by `middleware/ratelimit.go` so leave both alone.
- **UTC day boundary**: salt comes from `clickedAt.UTC()`; 23:59:59Z and 00:00:00Z next day produce different hashes for the same IP by design.
- **Empty / unparseable IP** → `NULL` (same as today). **Empty secret** → `NewIPHasher` error → `serve` fails fast; config already rejects a missing `SESSION_SECRET`.
- **Deploy order**: the old binary on the new schema (or new binary on old) makes every click INSERT fail silently (logged, redirect still works) until both match — same class as the `000013`/`000014` notes. Run `migrate up` then `./scripts/deploy.sh`.
- **First startup after upgrade**: the sweep immediately nulls `user_agent` on every row older than 90 days on both existing hosts. Intended; call it out in DEPLOYMENT.md.
