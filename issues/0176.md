## Description

Let an admin upload a hero image in Admin → Settings, store it on the server, and serve it to the public home page (#0174). Brennan will generate the image with Codex, so the issue fixes the size and format the upload expects.

## Long Description

**Storage: Postgres, not the filesystem.** The app ships as a single binary on three hosts, and backups already cover the database ([docs/backups.md](../docs/backups.md)). Add a table `site_assets (name text primary key, content_type text, bytes bytea, width int, height int, sha256 text, alt text, updated_at timestamptz)` with a migration and its down migration. The only row for now is `name='hero'`.

**Upload** (admin only, cookie session; tokens get 403 as for every admin route):
- `PUT /admin/home/hero` takes `multipart/form-data` with fields `image` and `alt`. `DELETE /admin/home/hero` removes the image. Both write audit entries (`home.hero.updated`, `home.hero.removed`) with size, dimensions and hash, never the bytes.
- **Accepted formats:** PNG, JPEG or WebP, sniffed from the bytes rather than trusting the extension or the declared content type. The upload must decode, which also yields the width and height.
- **Limits:**
  - at most 2 MB;
  - between 1200×400 and 4000×2000 pixels;
  - aspect ratio between 2:1 and 4:1;
  - `alt` text required, at most 200 characters.
  
  Any failure returns a 400 whose message says exactly what to change ("Image is 900×600; use at least 1200 px wide and a 2:1 to 4:1 shape").
- **Re-encode and strip metadata.** Decode, then re-encode as JPEG (quality 85) or keep PNG when the image has transparency, so EXIF and GPS data never reach visitors. WebP decoding needs `golang.org/x/image/webp`; WebP inputs are re-encoded to JPEG.

**Serving.** `GET /public/hero` returns the stored bytes with the stored content type, `ETag` set to the sha256, `Cache-Control: public, max-age=86400` and `X-Content-Type-Options: nosniff`. It returns 404 when there is no image. `GET /api/public/home` returns `hero: {"url": "/public/hero?v=<sha256 prefix>", "alt", "width", "height"}`, so a new upload busts caches. Route `/public/hero` before the SPA's catch-all.

**For Codex (put this in the admin UI hint and the docs):**
- Wide banner, **2400×800** (3:1), JPEG or PNG, under 2 MB.
- Keep the subject in the middle third. The page crops the sides on phones to a 4:3 centre.
- No text in the image, so it stays readable at any width and the title can change without regenerating it.
- It must work on both the light and dark page backgrounds.

## Root cause

The server had nowhere to keep an uploaded image and `GET /api/public/home` returned `hero: null` unconditionally (#0174 left the contract in place).

## Fix

- Migration `000023_create_site_assets` (up/down) adds `site_assets`. (000022 is reserved for #0179 and 000023 was reassigned here, so there is a numbering gap.)
- `internal/siteassets`: Postgres `Store` and an in-memory `MemStore` for dev mode.
- `internal/handlers/hero.go`: `PUT/DELETE /admin/home/hero` (behind `requireAdmin`, so API tokens get 403) and public `GET /public/hero`, wired in `buildMux` in both modes via `HomeHandler.WithHero`; `GET /api/public/home` now fills `hero`.
- Upload security: the multipart body is streamed (no temp files) under a hard cap of 2 MB plus 64 KB of framing; format is sniffed from magic bytes only (PNG, JPEG, WebP; SVG, GIF and the rest refused); dimensions are read from the header and checked before any pixels are decoded (1200x400 to 4000x2000, 2:1 to 4:1); the image is then decoded and re-encoded (JPEG q85, or PNG when transparent), so no metadata survives, and the re-encoded size is capped at 2 MB too. `alt` is required, at most 200 characters, one line.
- Serving: ETag is the sha256, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, 304 on `If-None-Match`. A request with the current `?v=` gets `public, max-age=31536000, immutable`; anything else gets `public, max-age=86400`, so a stale `?v=` can never pin old content. `middleware.Compress` already skips `/public/hero`.
- Audit `home.hero.updated` / `home.hero.removed` carry size, dimensions, hash and content type, never bytes. Delete with nothing set returns 404.
- Docs: configuration.md (rules and Codex brief), database.md, auth.md. The admin UI is #0177.
- Known limit: EXIF orientation is dropped with the rest of the metadata and not applied.
